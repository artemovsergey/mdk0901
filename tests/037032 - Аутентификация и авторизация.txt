##01::3

Процесс шифрования пароля в базе данных
##02::3

Процесс проверки прав доступа аутентифицированного пользователя
Процесс проверки подлинности пользователя
Процесс отправки письма с подтверждением
Процесс хранения сессий на сервере

##04::3
Что происходит при cookie-based аутентификации?
Сервер создаёт сессию и отправляет браузеру Cookie с её идентификатором
Сервер выдаёт пользователю JWT-токен
Сервер не сохраняет никаких данных о пользователе
Браузер сам создаёт учётную запись пользователя
##05::3
Какой недостаток имеет cookie-based аутентификация?
Сервер хранит состояние сессий и плохо масштабируется
Пользователь должен вводить пароль при каждом запросе
Cookies невозможно передать браузеру
Она работает только в мобильных приложениях
##06::3
Из каких частей состоит JWT?
Header, Payload, Signature
Логин, пароль, роль
URL, порт, протокол
Cookie, сессия, ключ
##07::3
Что содержится в части Header JWT?
Алгоритм шифрования и тип токена
Список ролей пользователя
Дата рождения пользователя
Пароль пользователя в открытом виде
##08::3
Что такое claims в JWT?
Утверждения с полезными данными о пользователе
Заголовки HTTP-запроса
Список подключённых клиентов
Настройки веб-сервера
##09::3
Что означает claim exp в JWT?
Срок действия токена
Имя пользователя
Роль пользователя
Алгоритм подписи
##10::3
Что гарантирует подпись Signature в JWT?
Токен не был изменён после создания
Токен невозможно прочитать
Токен хранится в базе данных
Токен действует бессрочно

Content-Type со значением JSON
Cookie со значением Session

##12::3
В чём преимущество JWT перед cookie-based подходом?
Серверу не нужно хранить сессии, что упрощает масштабирование
Токен невозможно подделать без пароля
Токен не имеет срока действия
Токен передаётся только по защищённому каналу
##13::3
Что делает атрибут Authorize?
Ограничивает доступ только аутентифицированным пользователям
Разрешает доступ всем пользователям без ограничений
Создаёт нового пользователя в системе
Отключает проверку подлинности
##14::3
Что делает атрибут AllowAnonymous?
Разрешает доступ без аутентификации
Запрещает доступ всем пользователям
Требует роль администратора
Шифрует передаваемые данные
##15::3
В чём отличие политик от ролей?
Политики гибче и позволяют описывать сложные правила доступа
Политики работают только с ролями администратора
Роли позволяют описывать любые сложные условия
Отличий между ними нет
