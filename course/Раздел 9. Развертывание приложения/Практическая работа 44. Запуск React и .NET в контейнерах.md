# Практическая работа 44. Запуск React и .NET в контейнерах

### **Тема:** Контейнеризация fullstack-приложения: .NET Web API и React (Vite) в Docker и Docker Compose

### **Цель:**
Освоить упаковку fullstack-приложения в Docker-образы и запуск всего стека одной командой. Научиться писать многоэтапные (multi-stage) Dockerfile для .NET Web API и React-приложения, настраивать `docker-compose.yml` (сервисы, порты, переменные окружения, зависимости, healthcheck, сети), правильно передавать переменные Vite на этапе сборки и раздавать собранную статику через nginx с поддержкой SPA-маршрутизации.

### **Теоретическая часть:**

**Зачем нужен Docker.** Приложение работает на компьютере разработчика, но «падает» на сервере — из-за разных версий Node.js, .NET, установленных библиотек и настроек окружения. Docker упаковывает приложение вместе со всеми зависимостями в **контейнер** — изолированную переносимую единицу, которая одинаково работает на любой машине, где установлен Docker. Вместо инструкции «установите Node 22, .NET 8, nginx и настройте так-то» вы передаёте готовый образ.

**Образ, контейнер и слои.**
- **Образ (image)** — неизменяемый шаблон: код, среда выполнения, библиотеки, переменные окружения.
- **Контейнер (container)** — запущенный экземпляр образа. Образ можно запустить много раз, получив несколько контейнеров.
- **Слои (layers)** — образ собирается по шагам, и каждый шаг `Dockerfile` (`COPY`, `RUN` и т. д.) создаёт слой. Слои кэшируются: если файл не менялся, Docker переиспользует готовый слой и сборка идёт быстрее. Поэтому сначала копируют файлы зависимостей (`package.json`, `*.csproj`) и ставят зависимости, и только потом — исходный код.

**Dockerfile.** Это текстовый «рецепт» сборки образа. Основные инструкции:

| Инструкция | Назначение |
|------------|------------|
| `FROM` | базовый образ (например, `node:22-alpine`, `mcr.microsoft.com/dotnet/sdk:8.0`) |
| `WORKDIR` | рабочая директория внутри контейнера |
| `COPY` | копирует файлы с хоста в образ |
| `RUN` | выполняет команду во время сборки (`npm ci`, `dotnet publish`) |
| `ARG` | аргумент сборки, доступен только во время `docker build` |
| `ENV` | переменная окружения, сохраняется в готовом образе |
| `EXPOSE` | документирует, на каком порту слушает контейнер |
| `ENTRYPOINT` / `CMD` | команда запуска контейнера |

**Multi-stage build (многоэтапная сборка).** Сборка требует тяжёлых инструментов (SDK .NET, Node.js + `node_modules`), а для запуска они не нужны. Поэтому Dockerfile делят на этапы: на первом идёт сборка, на второй копируется только результат. Итоговый образ получается лёгким и безопасным: в нём нет ни SDK, ни исходников.

```dockerfile
# этап сборки
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
# ... publish ...

# этап запуска — только среда выполнения
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine
COPY --from=build /app/publish .
```

**`.dockerignore`.** По умолчанию в контекст сборки попадают все файлы проекта. Файл `.dockerignore` исключает лишнее (`node_modules`, `dist`, `bin`, `obj`, `.git`) — это ускоряет сборку и уменьшает образ.

**Docker Compose.** Для fullstack-приложения нужны два контейнера (API и frontend) и сеть между ними. Docker Compose описывает всё это в одном файле `docker-compose.yml`:

- **`services`** — контейнеры приложения (`api`, `frontend`);
- **`ports`** — проброс портов «хост:контейнер», например `"8080:8080"`;
- **`environment`** — переменные окружения сервиса;
- **`depends_on`** — порядок запуска (frontend ждёт api); с `condition: service_healthy` — ожидание готовности по healthcheck;
- **`healthcheck`** — периодическая проверка, что контейнер жив (`test`, `interval`, `retries`);
- **`networks`** — общая сеть, в которой сервисы видят друг друга по имени сервиса (`http://api:8080`);
- **`volumes`** — постоянное хранение данных (нужно для баз данных; в этой работе статике хранение не требуется).

**Важный нюанс Vite: переменные `VITE_*` запекаются при сборке.** Vite подставляет значения `import.meta.env.VITE_*` **в момент `npm run build`**, прямо в JS-бандл. В браузере это уже константы, а не переменные окружения. Значит, `VITE_API_URL` нельзя задать «снаружи» через `environment` в compose — она передаётся при сборке образа:

```dockerfile
ARG VITE_API_URL=http://localhost:8080/api
ENV VITE_API_URL=$VITE_API_URL
RUN npm run build
```

```yaml
build:
  args:
    VITE_API_URL: http://localhost:8080/api
```

Если изменить адрес API, нужно **пересобрать** образ frontend (`docker compose up --build`).

**CORS на стороне API.** В режиме разработки frontend (Vite, `http://localhost:5173`) и API (`http://localhost:5000`) — разные источники (origin), и браузер блокирует запросы без разрешающих заголовков CORS. В продакшене при раздаче статики через nginx фронтенд и API тоже могут находиться на разных портах (`http://localhost` и `http://localhost:8080`). Поэтому в `Program.cs` настраивают политику CORS с перечнем разрешённых источников. Альтернатива для продакшена — проксировать запросы `/api` через nginx, тогда все запросы будут одного источника и CORS не понадобится.

### **Ход работы:**

1. Подготовить окружение: установить Docker Desktop, проверить команды `docker --version` и `docker compose version`, включить Linux-контейнеры.
2. Создать структуру проекта: папки `backend/` (ASP.NET Core Web API) и `frontend/` (React + Vite), добавить `.gitignore`.
3. Реализовать backend: контроллер с данными и endpoint `/health`, настроить CORS в `Program.cs`.
4. Реализовать frontend: компонент, который загружает данные из API; адрес API вынести в переменную `VITE_API_URL`.
5. Написать `backend/Dockerfile` (multi-stage: `sdk` → `aspnet:8.0-alpine`) и `backend/.dockerignore`.
6. Написать `frontend/Dockerfile` (multi-stage: `node:22-alpine` со сборкой → `nginx:alpine` со статикой), `frontend/nginx.conf` с SPA-fallback и `frontend/.dockerignore`.
7. Собрать `docker-compose.yml`: сервисы `api` и `frontend`, проброс портов `8080` и `80`, build-arg `VITE_API_URL`, зависимость frontend от api по healthcheck, общая сеть.
8. Запустить `docker compose up --build -d`, проверить `docker compose ps`, открыть `http://localhost` (frontend) и `http://localhost:8080/api/products` (API), сделать скриншоты, оформить README.md и запушить репозиторий в Gogs.

**2. backend/Controllers/ProductsController.cs — простое API со списком товаров:**

```csharp
using Microsoft.AspNetCore.Mvc;

namespace WebAPI.Controllers;

[ApiController]
[Route("api/[controller]")]
public class ProductsController : ControllerBase
{
    // Учебные данные в памяти — без базы данных.
    private static readonly List<Product> Products =
    [
        new Product { Id = 1, Name = "Ноутбук", Price = 74990m },
        new Product { Id = 2, Name = "Мышь", Price = 1990m },
        new Product { Id = 3, Name = "Клавиатура", Price = 4590m },
    ];

    [HttpGet]
    public ActionResult<List<Product>> GetProducts() => Ok(Products);

    [HttpGet("{id:int}")]
    public ActionResult<Product> GetProduct(int id)
    {
        var product = Products.FirstOrDefault(p => p.Id == id);
        return product is null ? NotFound() : Ok(product);
    }
}

public class Product
{
    public int Id { get; set; }
    public string Name { get; set; } = string.Empty;
    public decimal Price { get; set; }
}
```

**3. backend/Program.cs — CORS и endpoint для healthcheck:**

```csharp
var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

// Разрешаем запросы с фронтенда: dev (Vite), preview и контейнер (nginx).
builder.Services.AddCors(options =>
{
    options.AddPolicy(
        "Frontend",
        policy =>
        {
            policy
                .WithOrigins(
                    "http://localhost", // frontend в контейнере, порт 80
                    "http://localhost:5173", // npm run dev (Vite)
                    "http://localhost:4173" // npm run preview
                )
                .AllowAnyHeader()
                .AllowAnyMethod();
        }
    );
});

var app = builder.Build();

app.UseCors("Frontend");
app.MapControllers();

// Простейшая проверка работоспособности для docker healthcheck.
app.MapGet("/health", () => Results.Ok(new { status = "ok" }));

app.Run();
```

**4. backend/Dockerfile — multi-stage сборка .NET API:**

```dockerfile
# Этап 1: сборка и публикация приложения.
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
WORKDIR /src
# Сначала копируем только csproj — слой restore кэшируется отдельно.
COPY ["WebAPI.csproj", "./"]
RUN dotnet restore "WebAPI.csproj"
COPY . .
RUN dotnet publish "WebAPI.csproj" -c Release -o /app/publish /p:UseAppHost=false

# Этап 2: лёгкий рантайм без SDK.
FROM mcr.microsoft.com/dotnet/aspnet:8.0-alpine AS final
WORKDIR /app
COPY --from=build /app/publish .
# Слушаем порт 8080 внутри контейнера.
ENV ASPNETCORE_URLS=http://+:8080
ENV ASPNETCORE_ENVIRONMENT=Production
EXPOSE 8080
ENTRYPOINT ["dotnet", "WebAPI.dll"]
```

**5. frontend/Dockerfile — multi-stage сборка React и раздача через nginx:**

```dockerfile
# Этап 1: сборка статики React (Vite).
FROM node:22-alpine AS build
WORKDIR /app
# package-lock.json обязателен для воспроизводимой установки через npm ci.
COPY package.json package-lock.json ./
RUN npm ci
COPY . .
# Vite «запекает» VITE_* переменные в бандл на этапе сборки.
ARG VITE_API_URL=http://localhost:8080/api
ENV VITE_API_URL=$VITE_API_URL
RUN npm run build

# Этап 2: раздача готовой статики из папки dist.
FROM nginx:alpine AS final
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

**6. frontend/nginx.conf — SPA-fallback для клиентской маршрутизации:**

```nginx
server {
    listen 80;
    server_name _;

    root /usr/share/nginx/html;
    index index.html;

    # Любой неизвестный путь отдаёт index.html — иначе перезагрузка
    # страницы на маршруте /products вернёт 404 (маршруты обрабатывает React).
    location / {
        try_files $uri $uri/ /index.html;
    }

    # Хэшированные файлы сборки можно кэшировать надолго.
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }
}
```

**8. frontend/src/components/ProductsList.tsx — компонент, который дергает API:**

```tsx
import { useEffect, useState } from 'react';

interface Product {
  id: number;
  name: string;
  price: number;
}

// Значение подставляется Vite на этапе сборки (см. ARG VITE_API_URL).
const API_URL: string = import.meta.env.VITE_API_URL ?? 'http://localhost:8080/api';

export function ProductsList() {
  const [products, setProducts] = useState<Product[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let cancelled = false;

    async function loadProducts() {
      try {
        const response = await fetch(`${API_URL}/products`);
        if (!response.ok) {
          throw new Error(`Ошибка ${response.status}`);
        }
        const data = (await response.json()) as Product[];
        if (!cancelled) {
          setProducts(data);
        }
      } catch (err) {
        if (!cancelled) {
          setError(err instanceof Error ? err.message : 'Не удалось загрузить данные');
        }
      } finally {
        if (!cancelled) {
          setIsLoading(false);
        }
      }
    }

    void loadProducts();

    return () => {
      cancelled = true;
    };
  }, []);

  if (isLoading) {
    return (
      <p role="status" className="state">
        Загрузка товаров…
      </p>
    );
  }

  if (error) {
    return (
      <p role="alert" className="state state-error">
        Ошибка: {error}
      </p>
    );
  }

  return (
    <ul className="products">
      {products.map((product) => (
        <li key={product.id} className="product-card">
          <h3>{product.name}</h3>
          <p>Цена: {product.price.toLocaleString('ru-RU')} ₽</p>
        </li>
      ))}
    </ul>
  );
}
```

**9. docker-compose.yml — оркестрация обоих сервисов:**

```yaml
services:
  # Backend: ASP.NET Core Web API на порту 8080.
  api:
    build:
      context: ./backend
      dockerfile: Dockerfile
    image: react-dotnet-demo-api
    container_name: demo-api
    ports:
      - "8080:8080"
    environment:
      ASPNETCORE_ENVIRONMENT: Production
      ASPNETCORE_URLS: http://+:8080
    healthcheck:
      test: ["CMD-SHELL", "wget -qO- http://localhost:8080/health || exit 1"]
      interval: 10s
      timeout: 5s
      retries: 5
      start_period: 20s
    networks:
      - app-network

  # Frontend: React + nginx на порту 80.
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
      args:
        # Адрес API «запекается» в бандл при сборке образа.
        VITE_API_URL: http://localhost:8080/api
    image: react-dotnet-demo-frontend
    container_name: demo-frontend
    ports:
      - "80:80"
    depends_on:
      api:
        # Frontend стартует после того, как API пройдёт healthcheck.
        condition: service_healthy
    networks:
      - app-network

networks:
  app-network:
    driver: bridge
```
