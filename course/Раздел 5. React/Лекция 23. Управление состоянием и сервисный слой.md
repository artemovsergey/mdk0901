#### **1. Локальное и глобальное состояние**

**Состояние** — это данные, от которых зависит отрисованный интерфейс. Когда состояние меняется, React перерисовывает затронутые компоненты.

Состояние бывает двух видов:

*   **Локальное** — нужно только одному компоненту или небольшой группе рядом. Например, значение поля ввода, открыт ли выпадающий список, активная вкладка.
*   **Глобальное** — нужно разным, далеко расположенным частям приложения. Например, данные текущего пользователя, корзина покупок, выбранная тема оформления.

**Когда достаточно `useState`.** Если данные использует один компонент — никакой общей инфраструктуры не нужно:

```tsx
function SearchInput() {
  const [query, setQuery] = useState('')

  return (
    <input
      value={query}
      onChange={(e) => setQuery(e.target.value)}
      placeholder="Поиск"
    />
  )
}
```

**«Поднятие состояния» (lifting state up).** Если данные нужны двум соседним компонентам, состояние переносят в их общего родителя и передают вниз через props. Это самый простой способ «поделиться» состоянием, и он предпочтителен, пока дерево неглубокое.

```tsx
function Parent() {
  const [filter, setFilter] = useState('all')

  return (
    <>
      <FilterSelect value={filter} onChange={setFilter} />
      <ProductList filter={filter} />
    </>
  )
}
```

**Когда нужен глобальный стор.** Проблемы начинаются, когда:

*   состояние нужно компонентам в разных ветках дерева (профиль в шапке и настройки в модальном окне);
*   данные приходится «протаскивать» через много промежуточных компонентов, которым они не нужны (props drilling);
*   одну и ту же логику изменения состояния используют несколько мест.

Тогда применяют Context, Zustand или специализированный инструмент для серверных данных.

#### **2. Context и `useReducer`**

**Зачем нужен reducer.** Когда состояние сложное (несколько связанных полей) и меняется по-разному, вместо множества `useState` удобно описать все изменения одной функцией-редьюсером. Reducer — чистая функция `(state, action) => newState`, которая по типу действия возвращает новое состояние.

```tsx
import { useReducer } from 'react'

// 1. Тип состояния
interface CounterState {
  count: number
  step: number
}

// 2. Типы действий — объединение (union) с диcкриминантом type
type CounterAction =
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'setStep'; payload: number }
  | { type: 'reset' }

// 3. Reducer: всегда возвращает новое состояние, ничего не мутирует
function counterReducer(state: CounterState, action: CounterAction): CounterState {
  switch (action.type) {
    case 'increment':
      return { ...state, count: state.count + state.step }
    case 'decrement':
      return { ...state, count: state.count - state.step }
    case 'setStep':
      return { ...state, step: action.payload }
    case 'reset':
      return { count: 0, step: 1 }
    default:
      return state
  }
}
```

Использование:

```tsx
function Counter() {
  const [state, dispatch] = useReducer(counterReducer, { count: 0, step: 1 })

  return (
    <div>
      <p>Значение: {state.count} (шаг {state.step})</p>
      <button onClick={() => dispatch({ type: 'increment' })}>+</button>
      <button onClick={() => dispatch({ type: 'decrement' })}>−</button>
      <button onClick={() => dispatch({ type: 'setStep', payload: 5 })}>Шаг 5</button>
      <button onClick={() => dispatch({ type: 'reset' })}>Сброс</button>
    </div>
  )
}
```

Ключевые правила reducer:

*   функция **чистая**: без запросов, `console.log` и случайных чисел;
*   состояние **не мутируется** — всегда создаётся новый объект через spread;
*   TypeScript сам подскажет допустимые `type` и `payload`, если объявить union действий.

**Комбинация Context + useReducer.** Context передаёт состояние и `dispatch` вниз без props drilling, reducer описывает изменения. Вместе они образуют простой глобальный стор на встроенных средствах React.

```tsx
// src/cart/CartContext.tsx
import { createContext, useContext, useReducer } from 'react'
import type { Dispatch, ReactNode } from 'react'

export interface CartItem {
  id: number
  title: string
  price: number
  quantity: number
}

interface CartState {
  items: CartItem[]
}

export type CartAction =
  | { type: 'add'; item: Omit<CartItem, 'quantity'> }
  | { type: 'remove'; id: number }
  | { type: 'clear' }

function cartReducer(state: CartState, action: CartAction): CartState {
  switch (action.type) {
    case 'add': {
      const existing = state.items.find((item) => item.id === action.item.id)
      if (existing) {
        return {
          items: state.items.map((item) =>
            item.id === action.item.id
              ? { ...item, quantity: item.quantity + 1 }
              : item,
          ),
        }
      }
      return { items: [...state.items, { ...action.item, quantity: 1 }] }
    }
    case 'remove':
      return { items: state.items.filter((item) => item.id !== action.id) }
    case 'clear':
      return { items: [] }
    default:
      return state
  }
}

interface CartContextValue {
  state: CartState
  dispatch: Dispatch<CartAction>
}

const CartContext = createContext<CartContextValue | null>(null)

export function CartProvider({ children }: { children: ReactNode }) {
  const [state, dispatch] = useReducer(cartReducer, { items: [] })

  return (
    <CartContext.Provider value={{ state, dispatch }}>
      {children}
    </CartContext.Provider>
  )
}

export function useCart() {
  const context = useContext(CartContext)
  if (!context) {
    throw new Error('useCart должен использоваться внутри CartProvider')
  }
  return context
}
```

Компонент обращается к состоянию и меняет его через `dispatch`:

```tsx
function CartBadge() {
  const { state } = useCart()
  const total = state.items.reduce((sum, item) => sum + item.quantity, 0)

  return <span className="badge">{total}</span>
}
```

**Ограничения подхода.**

*   Context не оптимизирует ререндеры: при изменении значения провайдера перерисовываются **все** потребители контекста, даже если им нужна лишь часть данных.
*   Чем больше свойств в контексте, тем чаще лишние обновления. Приходится дробить контексты (состояние отдельно, `dispatch` отдельно).
*   Логика изменения состояния живёт в reducer — это хорошо, но типизация union-действий быстро разрастается.

Для небольших приложений и редко меняющихся данных (тема, язык, данные пользователя) Context + useReducer — отличный выбор. Для часто меняющегося состояния удобнее Zustand.

#### **3. Zustand — компактный глобальный стор**

**Zustand** — небольшая библиотека для глобального состояния. Главные идеи: стор — это хук, состояние и действия лежат вместе, а компонент подписывается только на нужные ему кусочки.

**Установка:**

```bash
npm install zustand
```

**Создание стора.** Функция `create` принимает колбэк, который получает `set` (изменить состояние) и `get` (прочитать актуальное состояние) и возвращает объект с состоянием и actions. Двойные скобки `create<T>()(...)` — это каррирование, нужное TypeScript для вывода типов.

```tsx
// src/store/counterStore.ts
import { create } from 'zustand'

interface CounterState {
  count: number
  step: number
  increment: () => void
  decrement: () => void
  setStep: (step: number) => void
  reset: () => void
}

export const useCounterStore = create<CounterState>()((set) => ({
  // Начальное состояние
  count: 0,
  step: 1,

  // Действия просто меняют состояние через set
  increment: () => set((state) => ({ count: state.count + state.step })),
  decrement: () => set((state) => ({ count: state.count - state.step })),
  setStep: (step) => set({ step }),
  reset: () => set({ count: 0, step: 1 }),
}))
```

Использование в компоненте:

```tsx
function Counter() {
  const count = useCounterStore((state) => state.count)
  const step = useCounterStore((state) => state.step)
  const increment = useCounterStore((state) => state.increment)

  return (
    <div>
      <p>Значение: {count} (шаг {step})</p>
      <button onClick={increment}>+</button>
    </div>
  )
}
```

> Действия (`increment`, `setStep`) не меняются между рендерами, поэтому подписка на них не вызывает лишних обновлений. Их можно безопасно выбирать по одному.

**Селекторы и оптимизация ререндеров.** Селектор — функция, которая из всего стора выбирает нужный фрагмент. Компонент перерисовывается только когда изменилось именно выбранное значение. Несколько значений удобно выбрать одним вызовом с `useShallow`, который сравнивает результат поверхностно:

```tsx
import { useShallow } from 'zustand/react/shallow'

function CartSummary() {
  const { items, clear } = useCartStore(
    useShallow((state) => ({ items: state.items, clear: state.clear })),
  )

  return (
    <div>
      <p>Товаров: {items.length}</p>
      <button onClick={clear}>Очистить</button>
    </div>
  )
}
```

Без `useShallow` селектор, возвращающий новый объект `{ items, clear }`, при каждом рендере создавал бы новую ссылку и вызывал бесконечный цикл. Поэтому объекты и массивы из селектора либо сравнивают поверхностно, либо выбирают по одному полю, либо вычисляют производные значения через `useMemo`.

**Производные значения.** Если значение можно вычислить из состояния (сумма, количество), его не хранят отдельно, а вычисляют:

```tsx
const total = useCartStore((state) =>
  state.items.reduce((sum, item) => sum + item.price * item.quantity, 0),
)
```

**`persist` — сохранение в localStorage.** Middleware `persist` автоматически сериализует стор в хранилище и восстанавливает его при загрузке. Это удобно для корзины, темы, черновиков форм.

```tsx
// src/store/cartStore.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

export interface CartItem {
  id: number
  title: string
  price: number
  quantity: number
}

interface CartState {
  items: CartItem[]
  addItem: (item: Omit<CartItem, 'quantity'>) => void
  removeItem: (id: number) => void
  clear: () => void
}

export const useCartStore = create<CartState>()(
  persist(
    (set) => ({
      items: [],
      addItem: (item) =>
        set((state) => {
          const existing = state.items.find((i) => i.id === item.id)
          if (existing) {
            return {
              items: state.items.map((i) =>
                i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i,
              ),
            }
          }
          return { items: [...state.items, { ...item, quantity: 1 }] }
        }),
      removeItem: (id) =>
        set((state) => ({ items: state.items.filter((i) => i.id !== id) })),
      clear: () => set({ items: [] }),
    }),
    {
      name: 'cart-storage', // ключ в localStorage
      // Можно сохранять только часть состояния
      partialize: (state) => ({ items: state.items }),
    },
  ),
)
```

По умолчанию `persist` сохраняет весь стор, включая функции нельзя — они не сериализуются, но Zustand корректно восстанавливает только данные. Поле `partialize` позволяет явно указать, какие данные сохранять.

**Преимущества Zustand:**

*   минимум шаблонного кода — нет провайдера, нет `dispatch`;
*   состояние и действия в одном объекте;
*   точечные подписки через селекторы — меньше лишних ререндеров;
*   легко тестируется: стор можно использовать вне компонентов;
*   middleware из коробки: `persist`, `devtools`, `immer`.

#### **4. Сервисный слой**

**Зачем отделять работу с сервером от компонентов.** Если компонент сам знает адреса эндпоинтов, заголовки и форматы ответов, то:

*   логику невозможно переиспользовать в другом компоненте;
*   при смене адреса API правки нужны в десятках мест;
*   компонент сложно тестировать — приходится подменять сеть;
*   разметка и логика данных смешиваются (нарушение Single Responsibility).

**Сервисный слой** — модули, которые инкапсулируют работу с сервером и отдают компонентам уже готовые типизированные данные. Компонент не знает, откуда пришли данные.

**Структура.** Обычно создают папку `src/api/` (или `src/services/`):

```
src/
├── api/
│   ├── http.ts            # настроенный экземпляр axios
│   ├── productsApi.ts     # функции работы с товарами
│   └── authApi.ts         # функции аутентификации
└── types/
    └── api.ts             # общие типы ответов API
```

**Экземпляр axios с `baseURL`.** Единая точка настройки клиента: базовый адрес, таймаут, заголовки, перехватчики.

```ts
// src/api/http.ts
import axios from 'axios'

// Базовый адрес берём из переменной окружения Vite
export const API_URL = import.meta.env.VITE_API_URL ?? 'http://localhost:5000/api'

export const http = axios.create({
  baseURL: API_URL,
  timeout: 10_000,
  headers: {
    'Content-Type': 'application/json',
  },
})

// Перехватчик запроса: подставляем токен авторизации
http.interceptors.request.use((config) => {
  const token = localStorage.getItem('auth_token')
  if (token) {
    config.headers.Authorization = `Bearer ${token}`
  }
  return config
})

// Перехватчик ответа: единая обработка ошибок
http.interceptors.response.use(
  (response) => response,
  (error) => {
    if (error.response?.status === 401) {
      // Можно перенаправить на страницу входа
      console.warn('Требуется авторизация')
    }
    return Promise.reject(error)
  },
)
```

Переменные окружения Vite начинаются с `VITE_` и читаются через `import.meta.env`. Типы для них уже подключены шаблоном через `"types": ["vite/client"]` в `tsconfig.app.json`.

**Модуль предметной области.** Каждый модуль экспортирует функции и типы:

```ts
// src/api/productsApi.ts
import { http } from './http'

export interface Product {
  id: number
  title: string
  description: string
  price: number
  image: string
  category: string
}

export interface ProductFilters {
  category?: string
  search?: string
}

export async function fetchProducts(filters: ProductFilters = {}): Promise<Product[]> {
  const { data } = await http.get<Product[]>('/products', { params: filters })
  return data
}

export async function fetchProductById(id: number): Promise<Product> {
  const { data } = await http.get<Product>(`/products/${id}`)
  return data
}

export async function createProduct(payload: Omit<Product, 'id'>): Promise<Product> {
  const { data } = await http.post<Product>('/products', payload)
  return data
}

export async function removeProduct(id: number): Promise<void> {
  await http.delete(`/products/${id}`)
}
```

**Использование в компоненте.** Компонент вызывает сервис и управляет только UI-состоянием (загрузка, ошибка, данные):

```tsx
// src/pages/ProductsPage.tsx
import { useEffect, useState } from 'react'
import { fetchProducts } from '../api/productsApi'
import type { Product } from '../api/productsApi'
import { useCartStore } from '../store/cartStore'

export function ProductsPage() {
  const [products, setProducts] = useState<Product[]>([])
  const [isLoading, setIsLoading] = useState(true)
  const [error, setError] = useState<string | null>(null)

  const addItem = useCartStore((state) => state.addItem)

  useEffect(() => {
    fetchProducts()
      .then(setProducts)
      .catch(() => setError('Не удалось загрузить товары'))
      .finally(() => setIsLoading(false))
  }, [])

  if (isLoading) return <p>Загрузка…</p>
  if (error) return <p role="alert">{error}</p>

  return (
    <ul className="product-list">
      {products.map((product) => (
        <li key={product.id} className="product-card">
          <h3>{product.title}</h3>
          <p>{product.price.toLocaleString('ru-RU')} ₽</p>
          <button
            onClick={() =>
              addItem({ id: product.id, title: product.title, price: product.price })
            }
          >
            В корзину
          </button>
        </li>
      ))}
    </ul>
  )
}
```

Разделение обязанностей: сервис знает про HTTP, стор — про данные корзины, компонент — про разметку и взаимодействие.

#### **5. Сравнение подходов**

| Инструмент | Какое состояние хранит | Когда выбирать | Особенности |
|------------|------------------------|----------------|-------------|
| `useState` | Локальное, в одном компоненте | Поля форм, флаги, вкладки | Проще всего, но не делится между компонентами |
| Поднятие состояния | Общее для соседних компонентов | Неглубокое дерево | Без библиотек, но растёт количество props |
| Context + `useReducer` | Глобальное, меняется редко | Тема, язык, текущий пользователь | Ререндерит всех потребителей при изменении |
| **Zustand** | Глобальное, меняется часто | Корзина, фильтры, UI-состояние | Селекторы, `persist`, нет провайдера |
| **TanStack Query** | Серверное (данные из API) | Списки, детали, мутации | Кэш, повторные запросы, статусы — раздел 7 |

**Важно различать клиентское и серверное состояние.**

*   **Клиентское** состояние живёт только в браузере: корзина до оформления, открытые панели, черновик формы. Его хранят в `useState`, Context или Zustand.
*   **Серверное** состояние — копия данных с сервера: список товаров, профиль, заказы. Для него используют **TanStack Query**, потому что нужно кэширование, повторная загрузка и синхронизация. Подробно этот инструмент разбирается в разделе 7 «Интеграция фронтенда и бекенда».

Не стоит складывать серверные данные в Zustand — тогда кэш, инвалидация и повторные запросы лягут на вас. Zustand для клиентского, TanStack Query для серверного.

#### **6. Практика: корзина товаров**

Соберём каталог с корзиной: товары загружаются из API, корзина хранится в Zustand и переживает перезагрузку страницы.

**Структура:**

```
src/
```

**Стор корзины с производными значениями:**

```ts
// src/store/cartStore.ts
import { create } from 'zustand'
import { persist } from 'zustand/middleware'

export interface CartItem {
  id: number
  title: string
  price: number
  quantity: number
}

interface CartState {
  items: CartItem[]
  addItem: (item: Omit<CartItem, 'quantity'>) => void
  removeItem: (id: number) => void
  updateQuantity: (id: number, quantity: number) => void
  clear: () => void
}

export const useCartStore = create<CartState>()(
  persist(
    (set) => ({
      items: [],

      addItem: (item) =>
        set((state) => {
          const existing = state.items.find((i) => i.id === item.id)
          if (existing) {
            return {
              items: state.items.map((i) =>
                i.id === item.id ? { ...i, quantity: i.quantity + 1 } : i,
              ),
            }
          }
          return { items: [...state.items, { ...item, quantity: 1 }] }
        }),

      removeItem: (id) =>
        set((state) => ({ items: state.items.filter((i) => i.id !== id) })),

      updateQuantity: (id, quantity) =>
        set((state) => ({
          items: state.items.map((i) =>
            i.id === id ? { ...i, quantity: Math.max(1, quantity) } : i,
          ),
        })),

      clear: () => set({ items: [] }),
    }),
    { name: 'cart-storage', partialize: (state) => ({ items: state.items }) },
  ),
)

// Селектор для суммы заказа
export const selectCartTotal = (state: CartState) =>
  state.items.reduce((sum, item) => sum + item.price * item.quantity, 0)

// Селектор для количества позиций
export const selectCartCount = (state: CartState) =>
  state.items.reduce((sum, item) => sum + item.quantity, 0)
```

**Страница корзины:**

```tsx
// src/pages/CartPage.tsx
import { useCartStore, selectCartTotal } from '../store/cartStore'

export function CartPage() {
  const items = useCartStore((state) => state.items)
  const total = useCartStore(selectCartTotal)
  const removeItem = useCartStore((state) => state.removeItem)
  const updateQuantity = useCartStore((state) => state.updateQuantity)
  const clear = useCartStore((state) => state.clear)

  if (items.length === 0) {
    return <p>Корзина пуста</p>
  }

  return (
    <section className="cart">
      <h1>Корзина</h1>

      <ul>
        {items.map((item) => (
          <li key={item.id} className="cart-row">
            <span>{item.title}</span>
            <input
              type="number"
              min={1}
              value={item.quantity}
              onChange={(e) => updateQuantity(item.id, Number(e.target.value))}
              aria-label={`Количество: ${item.title}`}
            />
            <span>{(item.price * item.quantity).toLocaleString('ru-RU')} ₽</span>
            <button onClick={() => removeItem(item.id)} aria-label={`Удалить ${item.title}`}>
              Удалить
            </button>
          </li>
        ))}
      </ul>

      <p className="cart-total">
        Итого: <strong>{total.toLocaleString('ru-RU')} ₽</strong>
      </p>
      <button onClick={clear}>Очистить корзину</button>
    </section>
  )
}
```

### **Резюме**

*   **Локальное состояние** живёт в компоненте (`useState`), **глобальное** — в общем сторе.
*   **Поднятие состояния** и **Context + useReducer** решают задачу общих данных без библиотек, но Context ререндерит всех потребителей.
*   **Zustand**: `create<State>()(...)` объединяет состояние и actions, селекторы дают точечные подписки, `persist` сохраняет стор в `localStorage`.
*   **Reducer** — чистая функция `(state, action) => newState`; действия типизируются union-типом.
*   **Сервисный слой** (`src/api/`) отделяет работу с сервером от UI: единый axios-клиент с `baseURL`, типизированные функции на каждый эндпоинт.
*   **Клиентское** состояние храните в Zustand / Context, **серверное** — в TanStack Query (раздел 7).

**Лучшие практики:**

*   начинайте с `useState` и поднимайте состояние только при реальной необходимости;
*   вычисляемые значения не храните, а вычисляйте;
*   в Zustand выбирайте из стора минимум данных; для объектов используйте `useShallow`;
*   задавайте `partialize`, если не весь стор нужно сохранять;
*   все обращения к сети держите в сервисных модулях, а не в компонентах;
*   не смешивайте серверное и клиентское состояние в одном сторе.
