### **Детальное рассмотрение каждого пункта плана:**

#### **1. Компоненты: глубже взгляд**

**Функциональный компонент — это обычная функция.**
В современном React компонент — это функция, которая возвращает JSX-разметку. Никаких классов, конструкторов и специальных механизмов регистрации: компонент объявляется один раз, экспортируется из файла и импортируется туда, где нужен.

```tsx
// src/components/Button.tsx
export function Button() {
  return <button type="button">Нажми меня</button>;
}
```

Использовать его можно двумя способами — как обычную функцию или как JSX-тег:

```tsx
import { Button } from './components/Button';

// Как тег (предпочтительно — читается как разметка)
const first = <Button />;

// Как вызов функции (тоже работает, но на практике используют редко)
const second = Button();
```

Разберём код:
*   имя функции — `Button`, то есть компонент называется так же, как файл;
*   функция не принимает аргументов (пока);
*   возвращает JSX — разметку, которую React превратит в DOM-элементы;
*   экспорт — именованный (`export function`), импорт — в фигурных скобках.

Важно: функциональный компонент **не выполняет никакой работы с DOM напрямую**. Он только описывает, как разметка выглядит при данных входных параметрах. Реальное обновление DOM берёт на себя React.

**Имя компонента с большой буквы.**
React различает компоненты и обычные HTML-теги именно по регистру первой буквы:

*   имя с **заглавной** буквы (`<ProductCard />`) — React ищет функцию `ProductCard` в области видимости и вызывает её;
*   имя со **строчной** буквы (`<productCard />`) — React считает это ссылкой на HTML-тег `productcard` и просто отрисует неизвестный элемент. В консоли появится предупреждение, а на экране — пустой тег.

Это правило распространяется и на имена переменных с компонентами:

```tsx
// Правильно: переменная названа с большой буквы
const Header = () => <header>Шапка сайта</header>;

// Неправильно: React воспримет это как HTML-тег <headerComponent>
const headerComponent = () => <header>Шапка сайта</header>;
```

Соглашение проекта: файл компонента и сам компонент называются одинаково и с большой буквы — `ProductCard.tsx` → `ProductCard`.

**Чистые функции и почему это важно.**
Компонент должен быть **чистой функцией** (pure function):

1.  при одинаковых props он всегда возвращает одинаковый JSX;
2.  во время рендера он не изменяет внешние переменные, не пишет в DOM, не отправляет запросы и не запускает таймеры.

Почему это критично:

*   React может вызвать компонент несколько раз подряд — в частности, в `StrictMode` он вызывается дважды в dev-режиме, чтобы помочь найти лишние побочные эффекты;
*   React может «отбросить» результат рендера, если данные изменились, и вызвать компонент заново;
*   весь побочный код (запросы, подписки, таймеры) выносится в хуки (`useEffect`) — о них в лекции 18.

```tsx
// Чистый компонент: результат зависит только от props
export function Greeting({ name }: { name: string }) {
  return <p>Привет, {name}!</p>;
}

// Грязный компонент: изменяет внешнюю переменную при рендере — так нельзя
let counter = 0;
export function BadCounter() {
  counter++; // побочный эффект во время рендера
  return <p>Рендеров: {counter}</p>;
}
```

**Импорт и экспорт: `default` и named.**
В TypeScript/ES-модулях есть два вида экспорта, и оба встречаются в React-проекте.

**Именованный экспорт (named):**

```tsx
// src/components/ProductCard.tsx
export function ProductCard() {
  return <article className="product-card">...</article>;
}
```

```tsx
// src/App.tsx
import { ProductCard } from './components/ProductCard';
```

**Экспорт по умолчанию (default):**

```tsx
// src/components/ProductCard.tsx
export default function ProductCard() {
  return <article className="product-card">...</article>;
}
```

```tsx
// src/App.tsx
import ProductCard from './components/ProductCard';
```

В чём разница:

| | Named export | Default export |
|---|---|---|
| Синтаксис экспорта | `export function Button() {}` | `export default function Button() {}` |
| Синтаксис импорта | `import { Button } from './Button'` | `import Button from './Button'` |
| Имя при импорте | строго совпадает с экспортом | можно задать любое |
| Сколько сущностей | сколько угодно в одном файле | только одна |
| Автодополнение IDE | точное, переименование работает | может подставить неверное имя |

**Почему в проекте принят именованный экспорт для компонентов:**

*   имя компонента не может «разъехаться» при импорте — IDE и рефакторинг работают предсказуемо;
*   из одного файла можно экспортировать несколько связанных вещей (компонент, его типы props, вспомогательные функции);
*   поиск по имени компонента сразу показывает и объявление, и все места использования;
*   ESLint и oxlint не жалуются на импорт из файла с default-экспортом.

**Исключение — входные точки.** Корневой компонент `App.tsx` и точка входа `main.tsx` из шаблона Vite используют default-экспорт:

```tsx
// src/App.tsx
export default App;
```

```tsx
// src/main.tsx
import App from './App.tsx';
```

В одном файле можно комбинировать оба вида экспорта, но злоупотреблять этим не стоит: если в файле есть default-экспорт, то именованные сущности в нём лучше не дублировать.

#### **2. JSX: не просто HTML**

**Что такое JSX.**
JSX — расширение синтаксиса JavaScript, которое позволяет писать разметку прямо в коде. Это **не HTML**: перед выполнением JSX компилируется в вызовы функций создания элементов React. Поэтому в JSX действуют правила JavaScript, а не HTML.

**Выражения в фигурных скобках `{ }`.**
Любое JavaScript-выражение можно вставить в разметку через фигурные скобки. Внутри `{ }` можно:

*   подставить переменную или поле объекта;
*   выполнить арифметику или вызвать функцию;
*   использовать тернарный оператор;
*   отрисовать результат `map`.

```tsx
// src/components/UserProfile.tsx
const user = {
  name: 'Иван',
  age: 30,
};

export function UserProfile() {
  const title = 'Профиль пользователя';

  function getWelcomeMessage(): string {
    return `Добро пожаловать, ${user.name}!`;
  }

  return (
    <section>
      <h1>{title}</h1>
      <p>Имя: {user.name}</p>
      <p>Возраст: {user.age + 1}</p>
      <p>{getWelcomeMessage()}</p>
      <p>Следующий год: {2024 + 1}</p>
      <p>Статус: {user.age >= 18 ? 'Взрослый' : 'Несовершеннолетний'}</p>
    </section>
  );
}
```

Результат в браузере:

```html
<section>
  <h1>Профиль пользователя</h1>
  <p>Имя: Иван</p>
  <p>Возраст: 31</p>
  <p>Добро пожаловать, Иван!</p>
  <p>Следующий год: 2025</p>
  <p>Статус: Взрослый</p>
</section>
```

Обратите внимание на разницу между двумя фигурными скобками:

```tsx
// Строковый литерал — кавычки
<p className="card">Текст</p>

// Выражение — фигурные скобки
<p className={isActive ? 'card card--active' : 'card'}>Текст</p>
```

Внутри `{ }` нельзя использовать инструкции (`if`, `for`, `const`). Условный рендеринг и списки подробно разбираются в лекции 17.

**Атрибуты в camelCase.**
Поскольку JSX — это JavaScript, имена атрибутов записываются в camelCase, а не так, как в HTML. Основные соответствия:

| HTML | JSX | Комментарий |
|------|-----|-------------|
| `class` | `className` | `class` — зарезервированное слово в JavaScript |
| `for` | `htmlFor` | для связи `<label>` и поля ввода |
| `onclick` | `onClick` | событие передаётся функцией, а не строкой |
| `onchange` | `onChange` | обработчики событий — в camelCase |
| `tabindex` | `tabIndex` | |
| `colspan` / `rowspan` | `colSpan` / `rowSpan` | |
| `readonly` | `readOnly` | |
| `maxlength` | `maxLength` | |
| `autocomplete` | `autoComplete` | |

Пример:

```tsx
export function SearchForm() {
  function handleClick() {
    console.log('Кнопка нажата');
  }

  return (
    <form>
      <label htmlFor="query">Поиск:</label>
      <input
        id="query"
        type="text"
        autoComplete="off"
        maxLength={50}
        placeholder="Введите запрос"
      />
      <button type="button" onClick={handleClick}>
        Найти
      </button>
    </form>
  );
}
```

Важно: на обработчик события в JSX передаётся **функция**, а не строка с кодом:

```tsx
// Правильно: ссылка на функцию
<button onClick={handleClick}>Нажми меня</button>

// Правильно: стрелочная функция, если нужны аргументы
<button onClick={() => deleteItem(product.id)}>Удалить</button>

// Неправильно: вызов функции произойдёт сразу при рендере
<button onClick={handleClick()}>Нажми меня</button>
```

**Атрибут `style` — объект JavaScript.**
В JSX в `style` передаётся не строка CSS, а объект. Имена CSS-свойств записываются в camelCase, а числовые значения трактуются как пиксели:

```tsx
export function Notice({ isWarning }: { isWarning: boolean }) {
  return (
    <p
      style={{
        color: isWarning ? 'red' : 'green',
        fontSize: 16,
        fontWeight: 'bold',
        backgroundColor: '#f5f5f5',
      }}
    >
      Текст с изменяемым размером
    </p>
  );
}
```

Двойные фигурные скобки здесь не случайны: внешние `{ }` — это JSX-выражение, а внутренние `{ }` — литерал объекта.

Для постоянных стилей лучше использовать CSS-классы, а `style` оставлять для действительно динамических значений:

```tsx
<div className="card" style={{ width: `${progress}%` }}>
  Прогресс
</div>
```

**Самозакрывающиеся теги и единый корневой элемент.**
В JSX, в отличие от HTML, любой тег без содержимого **обязан** быть самозакрывающимся:

```tsx
// Правильно
<img src="/logo.svg" alt="Логотип" />
<input type="text" />
<br />
<hr />

// Неправильно — это ошибка компиляции
<img src="/logo.svg" alt="Логотип">
<br>
```

Второе жёсткое правило: компонент может вернуть **только один корневой элемент**. Такой код не скомпилируется:

```tsx
// Ошибка: два соседних элемента на верхнем уровне
export function Header() {
  return (
    <h1>Магазин электроники</h1>
    <nav>...</nav>
  );
}
```

Обернуть элементы можно в общий контейнер:

```tsx
export function Header() {
  return (
    <header>
      <h1>Магазин электроники</h1>
      <nav>...</nav>
    </header>
  );
}
```

Но лишний `div` не всегда нужен и может испортить вёрстку (например, сломать Grid или Flex). Для таких случаев есть **фрагменты**.

**Фрагменты `<>...</>`.**
Фрагмент — это «невидимая» обёртка: React не создаёт для неё DOM-элемент. Короткий синтаксис — пустые угловые скобки:

```tsx
export function Header() {
  return (
    <>
      <h1>Магазин электроники</h1>
      <nav>...</nav>
    </>
  );
}
```

Полный синтаксис `<Fragment>` нужен, если фрагменту требуется атрибут, чаще всего `key` при выводе списка:

```tsx
import { Fragment } from 'react';

export function DescriptionList({ items }: { items: { term: string; value: string }[] }) {
  return (
    <dl>
      {items.map((item) => (
        <Fragment key={item.term}>
          <dt>{item.term}</dt>
          <dd>{item.value}</dd>
        </Fragment>
      ))}
    </dl>
  );
}
```

Итого правило: несколько соседних элементов — оборачиваем во фрагмент `<>...</>`; один элемент — фрагмент не нужен.

**Безопасность в JSX: автоэкранирование.**
React автоматически **экранирует** все значения, вставленные через `{ }`. Это защищает от XSS-атак: если в данных окажется HTML-тег или скрипт, он будет показан как обычный текст, а не выполнен.

```tsx
export function Comment() {
  const maliciousCode = '<script>alert("XSS")</script><h1>Взлом</h1>';

  return <p>{maliciousCode}</p>;
}
```

На странице пользователь увидит текст как есть, а не выполненный скрипт:

```html
<p>&lt;script&gt;alert("XSS")&lt;/script&gt;&lt;h1&gt;Взлом&lt;/h1&gt;</p>
```

Вставить «сырой» HTML можно только осознанно, через специальный prop `dangerouslySetInnerHTML`:

```tsx
// ОПАСНО: применять только к доверенному контенту, прошедшему санитизацию
<div dangerouslySetInnerHTML={{ __html: trustedHtml }} />
```

Такое название React дал намеренно: оно предупреждает разработчика, что ответственность за безопасность переходит к нему. Использовать этот prop без крайней необходимости не следует.

#### **3. props: связь между компонентами**

**props — это входные данные компонента.**
Props (свойства) — единственный способ передать данные от родительского компонента к дочернему. Они передаются как атрибуты JSX и доступны внутри компонента через первый параметр функции.

Главное правило: **props доступны только для чтения**. Внутри компонента их нельзя изменять — это гарантирует предсказуемость и односторонний поток данных сверху вниз.

```tsx
// Родитель передаёт данные
<ProductCard title="Ноутбук" price={79990} />

// Ребёнок принимает их как параметр
export function ProductCard(props: ProductCardProps) {
  return (
    <article>
      <h3>{props.title}</h3>
      <p>{props.price} ₽</p>
    </article>
  );
}
```

Обратите внимание: строка передаётся в кавычках (`title="Ноутбук"`), а число, объект, массив или выражение — в фигурных скобках (`price={79990}`, `product={item}`, `tags={['новинка']}`). Без фигурных скобок значение `79990` или `item` превратилось бы в строку.

**Деструктуризация параметров.**
Писать `props.title`, `props.price`, `props.imageUrl` утомительно. На практике props сразу деструктурируют прямо в параметрах функции:

```tsx
interface ProductCardProps {
  title: string;
  price: number;
}

export function ProductCard({ title, price }: ProductCardProps) {
  return (
    <article>
      <h3>{title}</h3>
      <p>{price} ₽</p>
    </article>
  );
}
```

Тип при этом указывается **после** деструктуризации — через двоеточие. Это позволяет IDE подсказывать имена доступных props и находить опечатки.

**Типизация: `interface Props` и `type Props`.**
Контракт props описывают в TypeScript двумя способами — и оба равнозначны:

```tsx
// Вариант 1: interface
interface ProductCardProps {
  title: string;
  price: number;
  isAvailable: boolean;
}

// Вариант 2: type
type ProductCardProps = {
  title: string;
  price: number;
  isAvailable: boolean;
};
```

Соглашение проекта:
*   тип props называется `{ИмяКомпонента}Props` — `ProductCardProps`, `ButtonProps`, `UserFormProps`;
*   тип описывается рядом с компонентом в том же файле, вверху;
*   в проекте используется `interface` для props — он лучше читается и легко расширяется другим интерфейсом;
*   если тип нужен и в родителе (например, для формирования данных), его экспортируют: `export interface ProductCardProps`.

Тип можно задать и прямо в параметрах, если компонент маленький и тип больше нигде не нужен:

```tsx
export function Badge({ text }: { text: string }) {
  return <span className="badge">{text}</span>;
}
```

Что даёт типизация props:

*   ошибка «родитель забыл передать обязательный prop» видна ещё в редакторе;
*   подсказки IDE: имена, типы, автодополнение значений;
*   безопасный рефакторинг: переименование prop меняет все места использования;
*   самодокументируемость: по `interface Props` сразу видно контракт компонента.

**Необязательные props и значения по умолчанию.**
Prop становится необязательным, если после имени поставить `?`:

```tsx
interface ProductCardProps {
  title: string;
  price: number;
  discount?: number;      // может быть не передан
  imageUrl?: string;      // может быть не передан
}
```

Для необязательных props задают значения по умолчанию — прямо в деструктуризации:

```tsx
export function ProductCard({
  title,
  price,
  discount = 0,
  imageUrl = '/images/placeholder.svg',
}: ProductCardProps) {
  const finalPrice = price - (price * discount) / 100;

  return (
    <article className="product-card">
      <img src={imageUrl} alt={title} />
      <h3>{title}</h3>
      <p>{finalPrice.toFixed(0)} ₽</p>
      {discount > 0 && <span className="badge">Скидка {discount}%</span>}
    </article>
  );
}
```

Особенность: значение по умолчанию срабатывает только тогда, когда prop равен `undefined` (то есть родитель его не передал). Если родитель осознанно передал `discount={0}`, то именно `0` и будет использовано — значение по умолчанию не подменит его.

```tsx
// discount не передан — сработает значение по умолчанию 0
<ProductCard title="Мышь" price={1500} />

// discount передан явно — используется 10
<ProductCard title="Мышь" price={1500} discount={10} />
```

**Особый prop `children: ReactNode`.**
`children` — это вложенное содержимое JSX-тега. React передаёт его компоненту автоматически:

```tsx
<Card>
  <h2>Заголовок</h2>
  <p>Текст внутри карточки</p>
</Card>
```

Чтобы компонент мог отрисовать это содержимое, prop `children` нужно принять и вставить в JSX. Тип для него — `ReactNode`, который импортируется **как тип**:

```tsx
// src/components/Card.tsx
import type { ReactNode } from 'react';

interface CardProps {
  title: string;
  children: ReactNode;
}

export function Card({ title, children }: CardProps) {
  return (
    <section className="card">
      <h3 className="card__title">{title}</h3>
      <div className="card__body">{children}</div>
    </section>
  );
}
```

`ReactNode` — это общий тип для всего, что React умеет рендерить: JSX-элементы, строки, числа, массивы, `null`, `undefined`, фрагменты.

Использование `Card`:

```tsx
<Card title="Доставка">
  <p>Курьером по городу — 300 ₽</p>
  <p>Самовывоз — бесплатно</p>
</Card>
```

`children` — основа **композиции**: родитель решает, какое содержимое положить внутрь, а дочерний компонент отвечает только за оформление.

> Синтаксис `import type { ReactNode } from 'react'` обязателен в шаблоне `react-ts` с параметром `verbatimModuleSyntax`: типы импортируются отдельно и удаляются компилятором, чтобы не попасть в итоговый JavaScript-бандл.

**Как компонент узнаёт об изменении props.**
Отдельного метода жизненного цикла для этого в React нет. Всё проще: когда родитель перерисовывается и передаёт новые значения props, React вызывает дочерний компонент заново с новыми props. Результат рендера зависит только от текущих props.

*   props — неизменяемые (immutable): дочерний компонент не может их поменять;
*   обновление UI инициирует родитель, меняя собственное состояние (state) или передавая новые данные;
*   React сравнивает предыдущий и новый JSX и обновляет в DOM только изменившиеся узлы.

Если при изменении prop нужно выполнить побочное действие (например, запрос к серверу), оно выносится в хук `useEffect` с нужным prop в списке зависимостей — это тема лекции 18. Смысл правила прост: **реагировать на изменение входных данных, не изменяя их**.

**Композиция и дробление UI на компоненты.**
Большой компонент с длинным JSX тяжело читать и сопровождать. Правило: дробим интерфейс на маленькие компоненты, каждый из которых отвечает за одну вещь (single responsibility).

Признаки, что компонент пора разделить:

*   в одном компоненте смешаны layout, логика и повторяющиеся фрагменты;
*   одинаковую разметку приходится копировать несколько раз;
*   JSX-функция не помещается на один экран;
*   разные части интерфейса меняются по разным причинам.

Например, вместо «монолита»:

```tsx
// Плохо: один компонент делает всё
export function ProductPage() {
  return (
    <article>
      <img src="/images/laptop.svg" alt="Ноутбук" />
      <h3>Ноутбук</h3>
      <p>
        <s>89990 ₽</s> <strong>79990 ₽</strong>
      </p>
      <span className="badge">Скидка 11%</span>
    </article>
  );
}
```

выделяем самостоятельные блоки `Price` и `Badge`, а `ProductCard` становится композицией:

```tsx
// src/components/Price.tsx
interface PriceProps {
  value: number;
  oldValue?: number;
}

export function Price({ value, oldValue }: PriceProps) {
  return (
    <p className="price">
      {oldValue !== undefined && <s>{oldValue} ₽</s>} <strong>{value} ₽</strong>
    </p>
  );
}
```

```tsx
// src/components/Badge.tsx
import type { ReactNode } from 'react';

export function Badge({ children }: { children: ReactNode }) {
  return <span className="badge">{children}</span>;
}
```

```tsx
// src/components/ProductCard.tsx
import type { ReactNode } from 'react';
import { Badge } from './Badge';
import { Price } from './Price';

export interface ProductCardProps {
  title: string;
  price: number;
  oldPrice?: number;
  imageUrl?: string;
  discount?: number;
  children?: ReactNode;
}

export function ProductCard({
  title,
  price,
  oldPrice,
  imageUrl = '/images/placeholder.svg',
  discount = 0,
  children,
}: ProductCardProps) {
  return (
    <article className="product-card">
      <img className="product-card__image" src={imageUrl} alt={title} />
      <h3 className="product-card__title">{title}</h3>
      <Price value={price} oldValue={oldPrice} />
      {discount > 0 && <Badge>Скидка {discount}%</Badge>}
      {children}
    </article>
  );
}
```

Теперь каждый блок можно переиспользовать и тестировать отдельно, а `ProductCard` остаётся читаемым.

**Сравнительная таблица способов передачи данных.**

| Что передаём | Как выглядит в JSX | Направление | Пример |
| :--- | :--- | :--- | :--- |
| Значение prop | `<Card title="Привет" />` | Родитель → Ребёнок | строка в кавычках |
| Выражение как prop | `<Card price={product.price * 0.9} />` | Родитель → Ребёнок | значение в фигурных скобках |
| Вложенный JSX | `<Card><p>Текст</p></Card>` | Родитель → Ребёнок | приходит как `children` |
| Обратный вызов (callback) | `<Button onClick={handleSave} />` | Ребёнок → Родитель | ребёнок вызывает переданную функцию |
| Разметка через выражение | `<p>{user.name}</p>` | Данные → Разметка | любое JS-выражение в `{ }` |

Ключевая идея React: данные идут **вниз** через props, а события — **вверх** через функции-обработчики, переданные как props. Это односторонний поток данных, и именно он делает поведение приложения предсказуемым.

**Шаг 4. Компонент `ProductCard`** — типизированные props, необязательные props с значениями по умолчанию, `children`, обратный вызов:

```tsx
// src/components/ProductCard.tsx
import type { ReactNode } from 'react';
import type { Product } from '../types/product';
import { Badge } from './Badge';
import { Price } from './Price';

export interface ProductCardProps {
  product: Product;
  onSelect?: (id: number) => void;
  children?: ReactNode;
}

export function ProductCard({ product, onSelect, children }: ProductCardProps) {
  const hasDiscount = product.discount !== undefined && product.discount > 0;

  function handleSelect() {
    onSelect?.(product.id);
  }

  return (
    <article className="product-card">
      <img
        className="product-card__image"
        src={product.imageUrl ?? '/images/placeholder.svg'}
        alt={product.title}
      />
      <h3 className="product-card__title">{product.title}</h3>
      <Price value={product.price} oldValue={product.oldPrice} />

      {hasDiscount && <Badge variant="danger">Скидка {product.discount}%</Badge>}
      {!product.isAvailable && <Badge>Нет в наличии</Badge>}

      {children}

      <button
        type="button"
        onClick={handleSelect}
        disabled={!product.isAvailable}
      >
        Подробнее
      </button>
    </article>
  );
}
```

Разберём код:
*   `product: Product` — обязательный prop с объектом товара;
*   `onSelect?: (id: number) => void` — необязательный обратный вызов: дочерний компонент сообщает родителю, что карточку выбрали;
*   `children?: ReactNode` — необязательное вложенное содержимое;
*   `onSelect?.(product.id)` — безопасный вызов: если обработчик не передан, ничего не произойдёт;
*   `product.imageUrl ?? '/images/placeholder.svg'` — подстановка значения, если поле не задано.

### **Резюме**

*   **Компонент** — это обычная функция, которая возвращает JSX. Имя компонента всегда начинается с большой буквы, иначе React примет его за HTML-тег.
*   **Чистота** — обязательное свойство компонента: одинаковые props → одинаковый JSX, никаких побочных эффектов во время рендера.
*   **Импорт и экспорт:** компоненты проекта используют именованный экспорт (`export function Button`), входные точки (`App.tsx`, `main.tsx`) — экспорт по умолчанию.
*   **JSX** — не HTML, а синтаксис JavaScript:
    *   JavaScript-выражения — в фигурных скобках `{ }`;
    *   атрибуты — в camelCase: `className`, `htmlFor`, `onClick`, `tabIndex`;
    *   `style` — объект JavaScript, а не строка CSS;
    *   одиночные теги самозакрываются: `<img />`, `<input />`;
    *   корневой элемент только один; несколько соседних элементов оборачиваются во фрагмент `<>...</>`;
    *   вставленные данные автоматически экранируются — это защита от XSS.
*   **props** — входные данные компонента, доступные только для чтения:
    *   передаются как JSX-атрибуты, принимаются деструктуризацией параметров;
    *   типизируются через `interface {ИмяКомпонента}Props` (или `type`);
    *   необязательные props помечаются `?` и получают значения по умолчанию в деструктуризации;
    *   `children: ReactNode` — стандартный способ передать вложенную разметку.
*   **Поток данных** односторонний: данные идут вниз через props, события — вверх через функции-обработчики.
*   **Композиция** — основа React: интерфейс дробится на маленькие компоненты, каждый из которых отвечает за одну задачу.
*   Чтобы использовать компонент, нужно:
    1.  создать файл компонента в `src/components/`;
    2.  описать тип props (`interface {Имя}Props`);
    3.  объявить функцию с заглавной буквы и экспортировать её (`export function ...`);
    4.  импортировать компонент и вставить его в JSX другого компонента, передав props.
