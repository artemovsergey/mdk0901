# Лекция 15. Основы React, структура проекта

**Цель лекции:** Познакомить студентов с библиотекой React, дать понимание, зачем нужны её ключевые концепции (компоненты, JSX, props, состояние), и научить ориентироваться в структуре проекта, созданного с помощью Vite.

**Аудитория:** Студенты, знакомые с основами JavaScript/TypeScript, HTML и CSS.

---

### **План лекции:**

1.  **Введение в React**
    *   Что такое React?
    *   Почему React — библиотека, а не фреймворк?
    *   Ключевые концепции: Компоненты, JSX, Props, State, Хуки.
    *   Почему TypeScript?

2.  **Vite — сборщик и dev-сервер**
    *   Что такое Vite и зачем он нужен?
    *   Создание и запуск проекта (`npm create vite`, `npm run dev`, `npm run build`).

3.  **Детальный разбор структуры проекта**
    *   **Корневая директория:** `package.json`, `vite.config.ts`, `tsconfig.json`, `index.html`.
    *   **Папка `src/` — сердце приложения:**
        *   `main.tsx` — входная точка приложения.
        *   `App.tsx` — корневой компонент.
        *   `components/` — папка для компонентов (создаём сами).
    *   **Другие важные папки:** `public/`, `assets/`, CSS-файлы.

    *   Создаём первый компонент вручную.
    *   Передаём данные через props.
    *   Подключаем компонент к `App.tsx`.

### **Детальное рассмотрение каждого пункта плана:**

#### **1. Введение в React**

**Что такое React?**
React — это библиотека JavaScript для создания пользовательских интерфейсов (в основном одностраничных приложений — SPA). Главная идея — **компонентный подход** и **декларативность**: мы описываем, как интерфейс должен выглядеть при текущем состоянии данных, а React сам решает, какие элементы DOM нужно обновить.

**Почему React называют библиотекой, а не фреймворком?**
React отвечает только за представление (view) — рендеринг интерфейса. Всё остальное подключается отдельными библиотеками:

*   маршрутизация — React Router;
*   работа с сервером — TanStack Query + Axios;
*   формы — react-hook-form;
*   глобальное состояние — Zustand.

Это даёт гибкость: стек собирается под конкретную задачу.

**Ключевые концепции:**

*   **Компоненты (Components):** функции, которые возвращают JSX-разметку. Каждый компонент управляет небольшим участком экрана.
    *   *Пример:* `Header`, `ProductList`, `Button`.

*   **JSX:** расширение синтаксиса JavaScript, позволяющее писать разметку прямо в коде. Это не HTML! Основные отличия:
    *   `className` вместо `class`;
    *   `htmlFor` вместо `for`;
    *   атрибуты в camelCase (`onClick`, `tabIndex`);
    *   любые выражения JavaScript записываются в фигурных скобках: `{price * 2}`.

*   **Props (свойства):** входные данные компонента. Передаются как атрибуты JSX, только для чтения — изменять props внутри компонента нельзя.

*   **State (состояние):** внутренние данные компонента. Когда состояние меняется, React автоматически перерисовывает интерфейс (подробно — в лекции 18).

*   **Хуки (Hooks):** функции (`useState`, `useEffect` и другие), дающие компоненту возможности React — состояние, побочные эффекты, контекст.

**Почему TypeScript?**
TypeScript — это надмножество JavaScript, которое добавляет строгую типизацию. Шаблон Vite `react-ts` настраивает TypeScript сразу. Типы помогают:

*   находить ошибки на этапе разработки;
*   описывать контракт props компонента через `interface`;
*   улучшать поддержку IDE (автодополнение, навигация по коду).

#### **2. Vite — сборщик и dev-сервер**

**Что такое Vite?**
Vite (франц. «быстрый») — официально рекомендованный инструмент сборки фронтенд-проектов. Он предоставляет:

*   мгновенный запуск dev-сервера — не нужно ждать, пока соберётся весь проект;
*   горячую замену модулей (HMR) — изменения сразу видны в браузере без полной перезагрузки;
*   оптимизированную production-сборку в папку `dist/`.

**Установка и основные команды:**
```bash
# Создание нового проекта с шаблоном React + TypeScript
npm create vite@latest my-app -- --template react-ts

# Переход в папку проекта и установка зависимостей
cd my-app
npm install

# Запуск dev-сервера (по умолчанию http://localhost:5173)
npm run dev

# Сборка production-версии в папку dist/
npm run build

# Проверка кода линтером (oxlint)
npm run lint

# Локальный предпросмотр production-сборки (http://localhost:4173)
npm run preview
```

> Начиная с npm 7, в команде `npm create` нужно указывать двойное тире (`--`) перед `--template`, иначе параметр не будет передан генератору проекта.

#### **3. Детальный разбор структуры проекта**

Давайте посмотрим на структуру проекта, созданного командой `npm create vite@latest my-app -- --template react-ts`:

```
my-app/
├── public/                 # Статические файлы (копируются в сборку как есть)
│   ├── favicon.svg
│   └── icons.svg
├── src/                    # Исходный код приложения
│   ├── assets/             # Ресурсы, импортируемые в код (картинки, шрифты)
│   │   ├── hero.png
│   │   ├── react.svg
│   │   └── vite.svg
│   ├── App.css             # Стили корневого компонента
│   ├── App.tsx             # Корневой компонент приложения
│   ├── index.css           # Глобальные стили
│   └── main.tsx            # Входная точка приложения
├── .gitignore
├── .oxlintrc.json          # Настройки линтера oxlint
├── index.html              # Главная HTML-страница
├── package.json            # Зависимости и npm-скрипты
├── README.md
├── tsconfig.json           # Настройки TypeScript (ссылки на app/node)
├── tsconfig.app.json       # Настройки TypeScript для кода приложения
├── tsconfig.node.json      # Настройки TypeScript для конфигов Vite
└── vite.config.ts          # Конфигурация Vite
```

**Корневая директория:**

*   `index.html` — главная (и единственная) HTML-страница приложения. Она намеренно почти пустая: содержит только контейнер `div#root` и подключение точки входа.
    ```html
    <!doctype html>
    <html lang="en">
      <head>
        <meta charset="UTF-8" />
        <link rel="icon" type="image/svg+xml" href="/favicon.svg" />
        <meta name="viewport" content="width=device-width, initial-scale=1.0" />
        <title>my-app</title>
      </head>
      <body>
        <!-- Сюда React будет рендерить всё приложение -->
        <div id="root"></div>
        <script type="module" src="/src/main.tsx"></script>
      </body>
    </html>
    ```

*   `package.json` — список всех зависимостей (библиотек) проекта и npm-скрипты (`dev`, `build`, `preview`).
*   `vite.config.ts` — конфигурация Vite. В минимальном виде подключает плагин React:
    ```typescript
    import { defineConfig } from 'vite'
    import react from '@vitejs/plugin-react'

    export default defineConfig({
      plugins: [react()],
    })
    ```
*   `tsconfig.json` — настройки компилятора TypeScript. Ссылается на `tsconfig.app.json` (код приложения) и `tsconfig.node.json` (конфиги).

**Папка `src/` — сердце приложения:**

*   `main.tsx` — входная точка. Здесь React «монтируется» в контейнер из `index.html`:
    ```tsx
    import { StrictMode } from 'react'
    import { createRoot } from 'react-dom/client'
    import './index.css'
    import App from './App.tsx'

    // Находим контейнер root и рендерим в него корневой компонент.
    createRoot(document.getElementById('root')!).render(
      <StrictMode>
        <App />
      </StrictMode>,
    )
    ```
    *   `createRoot` — точка входа React 18+/19: связывает виртуальное дерево React с реальным DOM-элементом.
    *   `StrictMode` — «строгий режим»: в dev-режиме помогает находить потенциальные проблемы (например, лишние побочные эффекты). На production-сборку не влияет.

*   `App.tsx` — корневой компонент приложения. После удаления демо-кода из шаблона он выглядит так:
    ```tsx
    import './App.css'

    function App() {
      return (
        <div className="app">
          <h1>Моё первое React-приложение</h1>
        </div>
      )
    }

    export default App
    ```

*   `index.css` — глобальные стили (подключаются в `main.tsx`).
*   `App.css` — стили корневого компонента (подключаются в `App.tsx`).
*   Типы окружения Vite (`import.meta.env`, импорт картинок) подключаются автоматически через `"types": ["vite/client"]` в `tsconfig.app.json` — дополнительно настраивать ничего не нужно.

**Разница между `public/` и `src/assets/`:**

*   `public/` — файлы копируются в сборку без обработки. Ссылка на них абсолютная: `/logo.svg`.
*   `src/assets/` — файлы обрабатываются сборщиком, их импортируют в код: `import logo from './assets/logo.svg'`. Так Vite может оптимизировать ресурсы.

#### **4. Практическое создание компонента**

Давайте создадим компонент для отображения списка товаров.

1.  **Создаём файл `src/components/ProductList.tsx`.** Папки `components/` в шаблоне нет — договоримся создавать её сами и складывать туда все компоненты приложения.

    ```tsx
    // src/components/ProductList.tsx

    // Описываем контракт props — какие данные принимает компонент.
    interface ProductListProps {
      title: string;
      description: string;
    }

    // Компонент — это функция, которая возвращает JSX.
    export function ProductList({ title, description }: ProductListProps) {
      return (
        <section className="product-list">
          <h2>{title}</h2>
          <p>{description}</p>
        </section>
      );
    }
    ```

    Разберём код:
    *   имя функции начинается с заглавной буквы — иначе React не распознает компонент;
    *   props принимаются через деструктуризацию параметра;
    *   `interface` описывает типы props — TypeScript подскажет, если родитель передаст не то или забудет обязательное свойство.

2.  **Подключаем компонент в `App.tsx`:**

    ```tsx
    import './App.css'
    import { ProductList } from './components/ProductList'

    function App() {
      return (
        <div className="app">
          <h1>Магазин электроники</h1>
          <ProductList
            title="Список товаров"
            description="Ноутбуки, мыши и клавиатуры"
          />
        </div>
      )
    }

    export default App
    ```

3.  **Запускаем `npm run dev`** и видим на странице заголовок из `App` и блок из `ProductList`.

Обратите внимание: в React нет ни декораторов, ни селекторов, ни регистрации компонента в модуле. Компонент — это обычная функция, а его подключение — обычный импорт.

---

### **Резюме**

*   **React** — библиотека для построения интерфейсов: компонентный подход, декларативность, JSX.
*   **Vite** — инструмент сборки: мгновенный dev-сервер с HMR, production-сборка в `dist/`.
*   **Структура проекта** логична и минимальна:
    *   `index.html` — контейнер `div#root` и подключение `src/main.tsx`;
    *   `src/main.tsx` — `createRoot` + `StrictMode`;
    *   `src/App.tsx` — корневой компонент;
    *   `src/components/` — компоненты приложения.
*   **Компонент** — функция с именем с заглавной буквы, которая возвращает JSX.
*   **Props** — входные данные компонента, типизируются через `interface`.
*   Для того чтобы использовать компонент, нужно:
    1.  Создать файл компонента в `src/components/`.
    2.  Объявить функцию и экспортировать её (`export function ...`).
    3.  Импортировать компонент и вставить его в JSX другого компонента.
