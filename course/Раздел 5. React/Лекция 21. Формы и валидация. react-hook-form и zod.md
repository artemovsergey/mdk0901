#### **1. Введение: проблема контролируемых форм**

**Контролируемый input.**
В React значение поля ввода обычно хранят в состоянии, а в `input` передают `value` и `onChange`. Такой input называют **контролируемым**.

```tsx
import { useState } from 'react';

function ControlledForm() {
  const [name, setName] = useState('');
  const [email, setEmail] = useState('');

  return (
    <form>
      <label>
        Имя
        <input value={name} onChange={(event) => setName(event.target.value)} />
      </label>

      <label>
        Email
        <input value={email} onChange={(event) => setEmail(event.target.value)} />
      </label>
    </form>
  );
}
```

Этот подход понятен, но у него есть цена:

*   **Ререндер на каждый ввод.** Каждое нажатие клавиши вызывает `setState`, и React перерисовывает компонент (а иногда и всё поддерево формы).
*   **Много «шума».** Для каждого поля нужен свой `useState`, свой обработчик и своя проверка.
*   **Валидация вручную.** Правила и сообщения об ошибках пишутся вручную и дублируются между формой и API.
*   **Сложно с вложенными структурами.** Массивы полей и вложенные объекты превращаются в громоздкий код.

На форме из 3–5 полей это незаметно. На форме из 20 полей с динамическими строками — становится серьёзной проблемой.

**Неконтролируемый подход `react-hook-form`.**
Библиотека `react-hook-form` (сокращённо RHF) предлагает другой подход: поля остаются **неконтролируемыми**, React не управляет их значением на каждый ввод. Вместо этого RHF обращается к DOM-элементам через ref, когда это действительно нужно — например, при отправке или валидации.

```tsx
import { useForm } from 'react-hook-form';

interface FormValues {
  name: string;
  email: string;
}

function FastForm() {
  const { register, handleSubmit } = useForm<FormValues>();

  const onSubmit = (data: FormValues) => {
    console.log(data); // { name: '…', email: '…' }
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input {...register('name')} />
      <input {...register('email')} />
      <button type="submit">Отправить</button>
    </form>
  );
}
```

`register('name')` возвращает набор свойств (`name`, `onChange`, `onBlur`, `ref`), которые «подключают» обычный инпут к форме. Значение реально живёт в DOM, а RHF читает его по требованию.

**Сравнение подходов:**

| Критерий | Контролируемые формы (`useState`) | `react-hook-form` |
|----------|-----------------------------------|-------------------|
| Значение поля | В состоянии React | В DOM (через ref) |
| Ререндеры | На каждый ввод | Только при ошибках/нужных данных |
| Валидация | Вручную | Через схему (`zod`) или правила |
| Ошибки | Пишем сами | `formState.errors` |
| Динамические поля | Громоздко | `useFieldArray` |
| Производительность на больших формах | Падает | Стабильная |

Для маленькой формы с одним-двумя полями контролируемый подход абсолютно нормален. Для настоящих форм входа, регистрации и редактирования данных используйте `react-hook-form`.

#### **2. Основы `react-hook-form`**

**Установка библиотеки.**

```bash
npm install react-hook-form zod@^4 @hookform/resolvers
```

*   `react-hook-form` — управление формой;
*   `zod` — описание схем валидации;
*   `@hookform/resolvers` — «мостик» между RHF и `zod` (понадобится в разделе 4).

> **Важно:** примеры курса рассчитаны на `zod` версии 4.x — именно в ней появились `z.email()` и новый формат сообщений. Команда выше фиксирует версию (`zod@^4`); проверить установленное можно командой `npm ls zod`.

**`useForm`, `register`, `handleSubmit`.**

```tsx
import { useForm } from 'react-hook-form';

// Тип значений формы.
interface LoginFormValues {
  email: string;
  password: string;
}

export function LoginForm() {
  const { register, handleSubmit } = useForm<LoginFormValues>();

  const onSubmit = (data: LoginFormValues) => {
    console.log('Данные формы:', data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <div>
        <label htmlFor="email">Email</label>
        <input id="email" type="email" {...register('email')} />
      </div>

      <div>
        <label htmlFor="password">Пароль</label>
        <input id="password" type="password" {...register('password')} />
      </div>

      <button type="submit">Войти</button>
    </form>
  );
}
```

Разберём ключевые элементы:
*   `useForm<LoginFormValues>()` — создаёт «менеджер формы»; дженерик задаёт тип значений.
*   `register('email')` — регистрирует поле с именем `email` в форме.
*   `handleSubmit(onSubmit)` — оборачивает обработчик: сначала запускает валидацию, и только если она успешна, вызывает `onSubmit` с данными.

**Важно:** не забудьте про `noValidate` на форме, если хотите, чтобы валидацию выполнял `zod`, а не встроенные подсказки браузера:

```tsx
<form onSubmit={handleSubmit(onSubmit)} noValidate>
```

**`defaultValues` и начальные значения.**
Начальные значения задаются один раз в `useForm`. Это делает форму предсказуемой и позволяет RHF корректно определять «изменённость» полей.

```tsx
const { register, handleSubmit } = useForm<FormValues>({
  defaultValues: {
    name: '',
    email: '',
    role: 'student',
    subscribed: false,
  },
});
```

Для редактирования существующей сущности `defaultValues` заполняют данными с сервера:

```tsx
useForm<UserFormValues>({
  defaultValues: {
    name: user.name,
    email: user.email,
  },
});
```

**`formState.errors` — вывод ошибок.**
Объект `formState.errors` содержит ошибки по именам полей. Выводим сообщение под соответствующим полем.

```tsx
import { useForm } from 'react-hook-form';

interface FormValues {
  name: string;
  email: string;
}

export function SimpleValidationForm() {
  const {
    register,
    handleSubmit,
    formState: { errors },
  } = useForm<FormValues>();

  const onSubmit = (data: FormValues) => console.log(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <div>
        <label htmlFor="name">Имя</label>
        {/* Правила можно задавать прямо в register — без схемы. */}
        <input
          id="name"
          {...register('name', {
            required: 'Имя обязательно',
            minLength: { value: 2, message: 'Минимум 2 символа' },
          })}
        />
        {errors.name && <p role="alert">{errors.name.message}</p>}
      </div>

      <div>
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          {...register('email', { required: 'Email обязателен' })}
        />
        {errors.email && <p role="alert">{errors.email.message}</p>}
      </div>

      <button type="submit">Сохранить</button>
    </form>
  );
}
```

Обратите внимание на `role="alert"` — скринридер объявит ошибку, когда она появится. Это простая и важная часть доступности.

**`isSubmitting` — блокировка кнопки.**
Пока идёт отправка, кнопку блокируют, чтобы пользователь не отправил форму дважды.

```tsx
const {
  register,
  handleSubmit,
  formState: { errors, isSubmitting },
} = useForm<FormValues>();

const onSubmit = async (data: FormValues) => {
  await api.save(data); // RHF сам установит isSubmitting
};

return (
  <form onSubmit={handleSubmit(onSubmit)}>
    {/* …поля… */}
    <button type="submit" disabled={isSubmitting}>
      {isSubmitting ? 'Отправка…' : 'Отправить'}
    </button>
  </form>
);
```

`isSubmitting` становится `true` на время выполнения асинхронного `onSubmit` и возвращается в `false` после завершения.

**`watch` — наблюдение за значением.**
`watch` возвращает текущее значение поля и обновляет компонент при его изменении. Используйте его, когда значение нужно отобразить или от него зависит разметка.

```tsx
const { register, watch } = useForm<FormValues>({
  defaultValues: { password: '' },
});

const password = watch('password');

return (
  <div>
    <input type="password" {...register('password')} />
    <p>Длина пароля: {password.length}</p>
  </div>
);
```

> `watch` удобен, но вызывает ререндер на каждый ввод. Если значение нужно только для проверки при отправке, `watch` не требуется.

#### **3. Валидация с `zod`**

**Зачем нужна схема.**
Правила валидации, разбросанные по `register`, быстро становятся нечитаемыми. Кроме того, те же правила нужны на сервере и при вводе, и при отправке. Схема — это **единое описание** того, какие данные считаются корректными.

`zod` — библиотека описания схем и вывода типов TypeScript из них. Одна схема даёт и валидацию, и тип.

**`z.object`, строки и числа.**

```ts
// src/features/user/userSchema.ts
import { z } from 'zod';

export const userSchema = z.object({
  name: z.string().min(2, 'Имя должно содержать минимум 2 символа'),
  age: z.number().int('Возраст должен быть целым числом').min(18, 'Возраст — от 18 лет'),
  score: z.number().min(0, 'Балл не может быть отрицательным').max(100, 'Балл не больше 100'),
});
```

`z.string()`, `z.number()`, `z.boolean()` — базовые типы. К ним можно добавлять проверки цепочкой: `.min()`, `.max()`, `.int()`, `.regex()`.

**`min`/`max`, `email`.**
В `zod` 4 для строковых форматов есть сокращённые конструкторы верхнего уровня, например `z.email()`.

```ts
import { z } from 'zod';

const contactSchema = z.object({
  // Сокращённый способ для email (zod 4).
  email: z.email('Некорректный адрес электронной почты'),

  // Так тоже можно: z.string().email('…').
  backupEmail: z.string().email('Некорректный адрес электронной почты'),

  phone: z
    .string()
    .regex(/^\+7\d{10}$/, 'Формат телефона: +71234567890'),

  nickname: z
    .string()
    .min(3, 'Минимум 3 символа')
    .max(20, 'Максимум 20 символов'),
});
```

**Сообщения об ошибках на русском.**
Вторым параметром проверки передаётся сообщение — оно попадёт в `errors.<поле>.message` и будет показано пользователю.

```ts
const schema = z.object({
  title: z
    .string()
    .min(1, 'Введите название')
    .max(100, 'Название не длиннее 100 символов'),
  count: z
    .number({ error: 'Введите число' })
    .min(1, 'Минимум 1')
    .max(1000, 'Максимум 1000'),
});
```

> В `zod` 4 сообщение можно передать строкой (`'Введите название'`) или объектом (`{ error: 'Введите название' }`). Строка короче и удобнее в большинстве случаев.

**`refine` для подтверждения пароля.**
Проверки отдельных полей не знают друг о друге. Чтобы сравнить два поля, применяют `.refine()` к **объекту**.

```ts
// src/features/registration/registrationSchema.ts
import { z } from 'zod';

export const registrationSchema = z
  .object({
    password: z.string().min(8, 'Пароль должен содержать минимум 8 символов'),
    confirmPassword: z.string().min(1, 'Подтвердите пароль'),
  })
  .refine((data) => data.password === data.confirmPassword, {
    // Сообщение появится именно под полем confirmPassword.
    message: 'Пароли не совпадают',
    path: ['confirmPassword'],
  });
```

`path: ['confirmPassword']` указывает, к какому полю «привязать» ошибку, — тогда сообщение выводится под нужным input.

**`z.infer` — тип из схемы.**
Главное преимущество `zod` в TypeScript: тип выводится из схемы автоматически, и его не нужно дублировать.

```ts
export const loginSchema = z.object({
  email: z.email('Некорректный email'),
  password: z.string().min(8, 'Минимум 8 символов'),
});

// Тип, выведенный из схемы. Эквивалент { email: string; password: string }.
export type LoginFormValues = z.infer<typeof loginSchema>;
```

Если правило меняется — меняется только схема, а тип обновляется сам. Рассинхронизация между валидацией и типами становится невозможной.

#### **4. Интеграция `zodResolver`**

Чтобы связать схему `zod` с `react-hook-form`, нужен **resolver** — адаптер из пакета `@hookform/resolvers`.

```bash
npm install @hookform/resolvers
```

```tsx
// src/features/login/LoginForm.tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

// 1. Схема валидации.
const loginSchema = z.object({
  email: z.email('Некорректный email'),
  password: z.string().min(8, 'Пароль должен содержать минимум 8 символов'),
});

// 2. Тип выводим из схемы.
type LoginFormValues = z.infer<typeof loginSchema>;

export function LoginForm() {
  // 3. Передаём resolver и тип в useForm.
  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<LoginFormValues>({
    resolver: zodResolver(loginSchema),
    defaultValues: {
      email: '',
      password: '',
    },
  });

  const onSubmit = async (data: LoginFormValues) => {
    await new Promise((resolve) => setTimeout(resolve, 1000));
    console.log('Отправлено:', data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <div>
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          autoComplete="email"
          aria-invalid={errors.email ? 'true' : 'false'}
          {...register('email')}
        />
        {errors.email && <p role="alert">{errors.email.message}</p>}
      </div>

      <div>
        <label htmlFor="password">Пароль</label>
        <input
          id="password"
          type="password"
          autoComplete="current-password"
          aria-invalid={errors.password ? 'true' : 'false'}
          {...register('password')}
        />
        {errors.password && <p role="alert">{errors.password.message}</p>}
      </div>

      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Вход…' : 'Войти'}
      </button>
    </form>
  );
}
```

`zodResolver(loginSchema)` перехватывает валидацию: RHF вызывает схему, получает ошибки и раскладывает их по `formState.errors`. Нам не нужно писать ни одной проверки вручную.

#### **5. `Controller` для нестандартных инпутов**

`register` работает с обычными HTML-элементами (`input`, `select`, `textarea`). Но есть «нестандартные» поля:

*   компоненты сторонних UI-библиотек;
*   маски и специальные виджеты;
*   поля, которым нужен полный контроль значения.

Для них в RHF есть компонент `Controller`.

```tsx
import { Controller, useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const profileSchema = z.object({
  nickname: z.string().min(3, 'Минимум 3 символа'),
  role: z.enum(['student', 'teacher', 'admin'], {
    error: 'Выберите роль',
  }),
  rating: z.number().min(1, 'Поставьте оценку от 1 до 5').max(5, 'Максимум 5'),
});

type ProfileFormValues = z.infer<typeof profileSchema>;

export function ProfileForm() {
  const {
    control,
    register,
    handleSubmit,
    watch,
    formState: { errors },
  } = useForm<ProfileFormValues>({
    resolver: zodResolver(profileSchema),
    defaultValues: {
      nickname: '',
      role: 'student',
      rating: 3,
    },
  });

  const onSubmit = (data: ProfileFormValues) => console.log(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      {/* Обычное поле — register. */}
      <div>
        <label htmlFor="nickname">Никнейм</label>
        <input id="nickname" {...register('nickname')} />
        {errors.nickname && <p role="alert">{errors.nickname.message}</p>}
      </div>

      {/* Сложное поле — Controller. */}
      <div>
        <label htmlFor="role">Роль</label>
        <Controller
          name="role"
          control={control}
          render={({ field }) => (
            <select id="role" {...field}>
              <option value="student">Студент</option>
              <option value="teacher">Преподаватель</option>
              <option value="admin">Администратор</option>
            </select>
          )}
        />
        {errors.role && <p role="alert">{errors.role.message}</p>}
      </div>

      {/* Пример нестандартного виджета: ползунок. */}
      <div>
        <label htmlFor="rating">Оценка: {watch('rating')}</label>
        <Controller
          name="rating"
          control={control}
          render={({ field }) => (
            <input
              id="rating"
              type="range"
              min={1}
              max={5}
              value={field.value}
              onBlur={field.onBlur}
              onChange={(event) => field.onChange(Number(event.target.value))}
            />
          )}
        />
        {errors.rating && <p role="alert">{errors.rating.message}</p>}
      </div>

      <button type="submit">Сохранить</button>
    </form>
  );
}
```

В `render` приходит объект `field` со свойствами `value`, `onChange`, `onBlur`, `name`, `ref`. Достаточно передать их в компонент — и он станет частью формы. Обратите внимание: для `range` значение приходит строкой, поэтому его преобразуют в число через `Number(...)`.

#### **6. Работа с состоянием формы**

**`reset` и `setValue`.**
`reset` возвращает форму к начальным (или новым) значениям, `setValue` — программно устанавливает значение одного поля.

```tsx
const {
  register,
  handleSubmit,
  reset,
  setValue,
  formState: { isSubmitting },
} = useForm<ProfileFormValues>({
  resolver: zodResolver(profileSchema),
  defaultValues: { nickname: '', role: 'student', rating: 3 },
});

// После успешной отправки очищаем форму.
const onSubmit = async (data: ProfileFormValues) => {
  await api.save(data);
  reset();
};

// Кнопка «Заполнить тестовыми данными».
const fillDemo = () => {
  reset({ nickname: 'student_demo', role: 'student', rating: 5 });
};

// Программно поправить одно поле.
const clearNickname = () => {
  setValue('nickname', '', { shouldValidate: true });
};
```

**Режимы валидации.**
По умолчанию RHF проверяет поле при отправке (`onSubmit`). Режим можно изменить:

```tsx
useForm<FormValues>({
  resolver: zodResolver(schema),
  // Первая проверка поля — при потере фокуса.
  mode: 'onBlur',
  // Повторная проверка уже «тронутого» поля — при вводе.
  reValidateMode: 'onChange',
});
```

Доступные значения `mode`: `onSubmit`, `onBlur`, `onChange`, `onTouched`, `all`. Для дружелюбных форм часто берут `onTouched` — ошибка появляется, когда пользователь закончил ввод.

**Серверные ошибки через `setError`.**
Иногда ошибку возвращает сервер (например, email уже занят). Её показывают тем же механизмом ошибок.

```tsx
const { setError } = useForm<LoginFormValues>({
  resolver: zodResolver(loginSchema),
});

const onSubmit = async (data: LoginFormValues) => {
  try {
    await api.login(data);
  } catch {
    // Привязываем сообщение сервера к конкретному полю.
    setError('email', {
      type: 'server',
      message: 'Пользователь с таким email уже зарегистрирован',
    });
  }
};
```

Пользователь увидит сообщение под полем `email` — как обычную ошибку валидации.

#### **7. Продвинутые приёмы**

**Динамические поля (`useFieldArray`).**
Если полей заранее неизвестное количество (например, список навыков), используется `useFieldArray`.

```tsx
import { useFieldArray, useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const skillsSchema = z.object({
  skills: z
    .array(z.string().min(2, 'Минимум 2 символа'))
    .min(1, 'Добавьте хотя бы один навык'),
});

type SkillsFormValues = z.infer<typeof skillsSchema>;

export function SkillsForm() {
  const { register, control, handleSubmit, formState: { errors } } = useForm<SkillsFormValues>({
    resolver: zodResolver(skillsSchema),
    defaultValues: { skills: [''] },
  });

  // fields — для рендера; append/remove — для изменения списка.
  const { fields, append, remove } = useFieldArray({
    control,
    name: 'skills',
  });

  const onSubmit = (data: SkillsFormValues) => console.log(data);

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <h3>Навыки</h3>

      {fields.map((field, index) => (
        <div key={field.id} className="skill-row">
          <input
            {...register(`skills.${index}`)}
            placeholder="Название навыка"
          />
          <button type="button" onClick={() => remove(index)} aria-label="Удалить навык">
            ×
          </button>
        </div>
      ))}

      {errors.skills?.message && <p role="alert">{errors.skills.message}</p>}

      <button type="button" onClick={() => append('')}>
        + Добавить навык
      </button>
      <button type="submit">Сохранить</button>
    </form>
  );
}
```

Ключевой момент — `key={field.id}`: RHF выдаёт стабильный `id` для каждой строки, поэтому элементы списка не «перепутываются» при удалении.

**Многошаговая форма с пошаговой валидацией.**
Форму можно разбить на шаги. Текущий шаг хранят в обычном `useState`, а валидацию конкретных полей вызывают через `trigger`.

```tsx
import { useState } from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';

const checkoutSchema = z.object({
  firstName: z.string().min(2, 'Имя обязательно'),
  lastName: z.string().min(2, 'Фамилия обязательна'),
  email: z.email('Некорректный email'),
  address: z.string().min(5, 'Укажите адрес'),
});

type CheckoutFormValues = z.infer<typeof checkoutSchema>;

export function CheckoutForm() {
  const [step, setStep] = useState(1);

  const {
    register,
    handleSubmit,
    trigger,
    formState: { errors, isSubmitting },
  } = useForm<CheckoutFormValues>({
    resolver: zodResolver(checkoutSchema),
    mode: 'onTouched',
    defaultValues: { firstName: '', lastName: '', email: '', address: '' },
  });

  // Проверяем только поля текущего шага.
  const nextStep = async () => {
    const isValid = await trigger(['firstName', 'lastName', 'email']);
    if (isValid) setStep(2);
  };

  const onSubmit = async (data: CheckoutFormValues) => {
    await new Promise((resolve) => setTimeout(resolve, 800));
    console.log('Заказ оформлен:', data);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)} noValidate>
      <p>Шаг {step} из 2</p>

      {step === 1 && (
        <>
          <div>
            <label htmlFor="firstName">Имя</label>
            <input id="firstName" {...register('firstName')} />
            {errors.firstName && <p role="alert">{errors.firstName.message}</p>}
          </div>
          <div>
            <label htmlFor="lastName">Фамилия</label>
            <input id="lastName" {...register('lastName')} />
            {errors.lastName && <p role="alert">{errors.lastName.message}</p>}
          </div>
          <div>
            <label htmlFor="email">Email</label>
            <input id="email" type="email" {...register('email')} />
            {errors.email && <p role="alert">{errors.email.message}</p>}
          </div>
          <button type="button" onClick={nextStep}>Далее</button>
        </>
      )}

      {step === 2 && (
        <>
          <div>
            <label htmlFor="address">Адрес доставки</label>
            <input id="address" {...register('address')} />
            {errors.address && <p role="alert">{errors.address.message}</p>}
          </div>
          <button type="button" onClick={() => setStep(1)}>Назад</button>
          <button type="submit" disabled={isSubmitting}>
            {isSubmitting ? 'Отправка…' : 'Оформить заказ'}
          </button>
        </>
      )}
    </form>
  );
}
```

`trigger(['firstName', 'lastName', 'email'])` запускает валидацию только перечисленных полей и возвращает `true`/`false`. Так пользователь не видит ошибок будущих шагов раньше времени.

#### **8. Практика: форма регистрации**

Соберём полноценную форму регистрации: имя, email, пароль, подтверждение пароля, согласие с условиями.

**Шаг 1. Схема валидации.**

```ts
// src/features/registration/registrationSchema.ts
import { z } from 'zod';

export const registrationSchema = z
  .object({
    // Имя: от 2 до 50 символов.
    name: z
      .string()
      .min(2, 'Имя должно содержать минимум 2 символа')
      .max(50, 'Имя не должно превышать 50 символов'),

    // Email: специальный конструктор zod 4.
    email: z.email('Введите корректный email'),

    // Пароль: длина и требования к составу.
    password: z
      .string()
      .min(8, 'Пароль должен содержать минимум 8 символов')
      .regex(/[A-Z]/, 'Пароль должен содержать заглавную букву')
      .regex(/[a-z]/, 'Пароль должен содержать строчную букву')
      .regex(/[0-9]/, 'Пароль должен содержать цифру'),

    // Подтверждение пароля проверяется ниже через refine.
    confirmPassword: z.string().min(1, 'Подтвердите пароль'),

    // Согласие с условиями: должен быть отмечен чекбокс.
    acceptTerms: z
      .boolean()
      .refine((value) => value, 'Необходимо принять условия использования'),
  })
  // Сравнение паролей на уровне всего объекта.
  .refine((data) => data.password === data.confirmPassword, {
    message: 'Пароли не совпадают',
    path: ['confirmPassword'],
  });

// Тип значений формы выводится из схемы — вручную писать не нужно.
export type RegistrationFormValues = z.infer<typeof registrationSchema>;
```

**Шаг 2. Небольшой компонент для вывода ошибки.**

```tsx
// src/components/FieldError.tsx
interface FieldErrorProps {
  id: string;
  message?: string;
}

export function FieldError({ id, message }: FieldErrorProps) {

  return (
    <p className="field-error" id={id} role="alert">

}
```

**Шаг 3. Компонент формы.**

```tsx
// src/features/registration/RegistrationForm.tsx
import { useState } from 'react';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import {
  registrationSchema,
  type RegistrationFormValues,
} from './registrationSchema';
import { FieldError } from '../../components/FieldError';

export function RegistrationForm() {
  const [successMessage, setSuccessMessage] = useState<string | null>(null);

  const {
    register,
    handleSubmit,
    watch,
    reset,
    formState: { errors, isSubmitting },
  } = useForm<RegistrationFormValues>({
    // Связываем форму со схемой zod.
    resolver: zodResolver(registrationSchema),
    defaultValues: {
      name: '',
      email: '',
      password: '',
      confirmPassword: '',
      acceptTerms: false,
    },
    // Проверяем поле после того, как пользователь его «тронул».
    mode: 'onTouched',
  });

  // Наблюдаем за паролем, чтобы показать требования в реальном времени.
  const password = watch('password');

  const onSubmit = async (data: RegistrationFormValues) => {
    setSuccessMessage(null);

    // Имитация запроса на сервер.
    await new Promise((resolve) => setTimeout(resolve, 1000));
    console.log('Регистрация:', data);

    setSuccessMessage('Регистрация прошла успешно!');
    reset();
  };

  // Требования к паролю: { текст, выполнено }.
  const passwordChecks = [
    { label: 'Минимум 8 символов', passed: password.length >= 8 },
    { label: 'Заглавная буква', passed: /[A-Z]/.test(password) },
    { label: 'Строчная буква', passed: /[a-z]/.test(password) },
    { label: 'Цифра', passed: /[0-9]/.test(password) },
  ];

  return (
    <form className="registration-form" onSubmit={handleSubmit(onSubmit)} noValidate>
      <h2>Регистрация</h2>

      {/* Имя */}
      <div className="form-group">
        <label htmlFor="name">Имя</label>
        <input
          id="name"
          type="text"
          autoComplete="name"
          aria-invalid={errors.name ? 'true' : 'false'}
          aria-describedby={errors.name ? 'name-error' : undefined}
          {...register('name')}
        />
        <FieldError id="name-error" message={errors.name?.message} />
      </div>

      {/* Email */}
      <div className="form-group">
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          autoComplete="email"
          aria-invalid={errors.email ? 'true' : 'false'}
          aria-describedby={errors.email ? 'email-error' : undefined}
          {...register('email')}
        />
        <FieldError id="email-error" message={errors.email?.message} />
      </div>

      {/* Пароль */}
      <div className="form-group">
        <label htmlFor="password">Пароль</label>
        <input
          id="password"
          type="password"
          autoComplete="new-password"
          aria-invalid={errors.password ? 'true' : 'false'}
          aria-describedby={errors.password ? 'password-error' : undefined}
          {...register('password')}
        />
        <FieldError id="password-error" message={errors.password?.message} />

        {/* Индикатор требований к паролю */}
        <ul className="password-requirements">
          {passwordChecks.map((check) => (
            <li key={check.label} className={check.passed ? 'passed' : ''}>
              {check.passed ? '✓' : '○'} {check.label}
            </li>
          ))}
        </ul>
      </div>

      {/* Подтверждение пароля */}
      <div className="form-group">
        <label htmlFor="confirmPassword">Подтвердите пароль</label>
        <input
          id="confirmPassword"
          type="password"
          autoComplete="new-password"
          aria-invalid={errors.confirmPassword ? 'true' : 'false'}
          aria-describedby={errors.confirmPassword ? 'confirm-error' : undefined}
          {...register('confirmPassword')}
        />
        <FieldError id="confirm-error" message={errors.confirmPassword?.message} />
      </div>

      {/* Согласие с условиями */}
      <div className="form-group checkbox-group">
        <label>
          <input type="checkbox" {...register('acceptTerms')} />Я принимаю условия
          использования
        </label>
        <FieldError id="terms-error" message={errors.acceptTerms?.message} />
      </div>

      {/* Кнопка блокируется на время отправки */}
      <button type="submit" disabled={isSubmitting}>
        {isSubmitting ? 'Отправка…' : 'Зарегистрироваться'}
      </button>

      {/* Сообщение об успехе */}
      {successMessage && (
        <p className="success-message" role="status">
          {successMessage}
        </p>
      )}
    </form>
  );
}
```

Что здесь важно:
*   **Ошибки показываются под полями** — через компонент `FieldError` и `formState.errors`.
*   **Связь ошибки с полем** — `aria-describedby` указывает на сообщение, `aria-invalid` сообщает о невалидности.
*   **Кнопка блокируется** на время отправки через `isSubmitting`.
*   **Схема — единственный источник правил**: и валидация, и типы взяты из `registrationSchema`.

### **Резюме**

*   **Контролируемые формы** (`useState`) перерисовываются на каждый ввод и требуют писать валидацию вручную.
*   **`react-hook-form`** оставляет поля неконтролируемыми: значение живёт в DOM, а библиотека читает его по требованию.
*   **`useForm`** создаёт менеджер формы; **`register`** подключает поле; **`handleSubmit`** валидирует и вызывает обработчик.
*   **`defaultValues`** задаёт начальные значения; **`formState.errors`** хранит ошибки; **`isSubmitting`** управляет блокировкой кнопки; **`watch`** наблюдает за значением.
*   **`zod`** описывает правила одной схемой: `z.object`, `z.string()`, `z.number()`, `z.email()`, `.min()`, `.max()`, `.regex()`.
*   Сообщения об ошибках пишутся на русском и передаются вторым аргументом проверки.
*   **`.refine()`** проверяет взаимосвязанные поля (например, пароль и подтверждение) и через `path` привязывает ошибку к нужному полю.
*   **`z.infer<typeof schema>`** выводит тип TypeScript из схемы — дублировать типы не нужно.
*   **`zodResolver`** из `@hookform/resolvers/zod` связывает схему с формой.
*   **`Controller`** подключает нестандартные инпуты, которым недостаточно `register`.
*   **`reset`, `setValue`, `setError`** управляют состоянием формы, включая серверные ошибки.
*   **`useFieldArray`** создаёт динамические списки полей.
*   **`trigger`** позволяет валидировать отдельные шаги многошаговой формы.

**Лучшие практики:**
- Держите все правила валидации в одной схеме `zod`, а тип выводите через `z.infer`.
- Показывайте ошибку под соответствующим полем и связывайте её через `aria-describedby` и `role="alert"`.
- Блокируйте кнопку отправки через `isSubmitting` — защита от двойной отправки.
- Для дружелюбного UX используйте `mode: 'onTouched'`.
- Не забывайте `noValidate` на форме, чтобы валидацию выполнял `zod`.
- Серверные ошибки показывайте через `setError`, а не отдельным блоком «где-то наверху».
