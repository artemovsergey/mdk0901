#### **1. Введение: зачем нужен роутер в SPA**

**Что такое маршрутизация в SPA.**
SPA (Single Page Application) — приложение, которое загружает одну HTML-страницу и дальше обновляет содержимое без перезагрузки. Браузер запрашивает `index.html` один раз, а React меняет то, что отрисовано в контейнере `div#root`.

Однако пользователю нужны разные экраны и адреса: главная, список товаров, профиль, форма входа. Нужно, чтобы:

*   адрес в строке браузера отражал текущий экран (`/profile/42`);
*   работали кнопки «назад/вперёд» браузера;
*   страницу можно было сохранить в закладки и переслать ссылкой;
*   при прямом заходе на вложенный адрес приложение открывалось на нужном экране.

Всем этим занимается **клиентский роутер**. Он перехватывает изменения адреса, сопоставляет URL с компонентом и рендерит нужный экран. Перезагрузки страницы не происходит.

**Возможности React Router v7:**

*   декларативное описание маршрутов объектами;
*   вложенные маршруты и общие Layout-компоненты;
*   динамические параметры (`:id`) и query-параметры (`?page=2`);
*   программная навигация из кода;
*   обработка ошибок на уровне маршрута (`errorElement`);
*   ленивая загрузка (lazy) — код страницы скачивается только при переходе на неё;
*   интеграция с загрузкой данных (loader/action) — рассматривается в разделе интеграции с бекендом.

**Установка библиотеки.**
В React Router v7 основной пакет называется `react-router` (пакет `react-router-dom` оставлен для совместимости и просто реэкспортирует API). Для браузерного SPA устанавливаем один пакет:

```bash
npm install react-router
```

#### **2. Основы React Router**

**Создание роутера.**
Роутер описывается один раз в отдельном файле (`src/router.tsx`). Маршруты — это обычный массив объектов: `path` (адрес) и `element` (что показать).

```tsx
// src/router.tsx
import { createBrowserRouter } from 'react-router'
import { RootLayout } from './layouts/RootLayout'
import { HomePage } from './pages/HomePage'
import { AboutPage } from './pages/AboutPage'
import { NotFoundPage } from './pages/NotFoundPage'

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />, // общий каркас для всех страниц
    children: [
      { index: true, element: <HomePage /> }, // адрес "/"
      { path: 'about', element: <AboutPage /> }, // адрес "/about"
      { path: '*', element: <NotFoundPage /> }, // любой несуществующий адрес
    ],
  },
])
```

Разберём ключевые поля:

*   `path: '/'` — корневой маршрут, внутри которого живут все остальные;
*   `children` — дочерние маршруты, адреса которых склеиваются с адресом родителя;
*   `index: true` — «маршрут по умолчанию» для родителя: срабатывает, когда после `/` ничего не указано. Нельзя одновременно использовать `index` и `path`;
*   `path: '*'` — catch-all («поймать всё»): сюда попадают любые адреса, не совпавшие с описанными выше.

**Подключение роутера в точке входа.**
Вместо рендера `<App />` напрямую мы передаём роутер в компонент `RouterProvider`:

```tsx
// src/main.tsx
import { StrictMode } from 'react'
import { createRoot } from 'react-dom/client'
import { RouterProvider } from 'react-router'
import { router } from './router'
import './index.css'

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <RouterProvider router={router} />
  </StrictMode>,
)
```

`RouterProvider` сам подписывается на изменения адреса и рендерит подходящий элемент. Больше ничего для базовой работы не требуется.

**Вложенные маршруты, `Outlet` и общий Layout.**
Часто у страниц есть одинаковые части: шапка, меню, подвал. Чтобы не дублировать их в каждой странице, создают Layout-компонент, а меняющуюся часть помечают компонентом `Outlet`.

```tsx
// src/layouts/RootLayout.tsx
import { Link, NavLink, Outlet } from 'react-router'

export function RootLayout() {
  return (
    <div className="app">
      <header className="app-header">
        <Link to="/" className="brand">
          MyApp
        </Link>

        <nav className="nav">
          {/* NavLink сам знает, активен ли адрес */}
          <NavLink
            to="/"
            end
            className={({ isActive }) => (isActive ? 'nav-link active' : 'nav-link')}
          >
            Главная
          </NavLink>
          <NavLink
            to="/about"
            className={({ isActive }) => (isActive ? 'nav-link active' : 'nav-link')}
          >
            О нас
          </NavLink>
        </nav>
      </header>

      <main className="app-main">
        {/* Сюда React Router подставит дочерний маршрут */}
        <Outlet />
      </main>

      <footer className="app-footer">© 2026 MyApp</footer>
    </div>
  )
}
```

`Outlet` — это «место под дочерний маршрут». Он доступен любому компоненту, который находится в дереве маршрутов (не только непосредственному родителю), поэтому Layout может быть многоуровневым.

**Декларативные ссылки `Link` и `NavLink`:**

*   `Link` — обычная ссылка SPA. Перехватывает клик и меняет адрес без перезагрузки страницы.
*   `NavLink` — та же ссылка, но её `className` (или `style`, или `children`) может быть функцией, которая получает объект с флагом `isActive`. Так удобно подсвечивать текущий раздел меню.

```tsx
// Простая ссылка
<Link to="/about">О нас</Link>

// Ссылка с активным состоянием
<NavLink to="/about" className={({ isActive }) => (isActive ? 'active' : '')}>
  О нас
</NavLink>
```

Для маршрута с `index: true` (`/`) добавьте `end`: иначе `NavLink` будет считать себя активным на всех вложенных адресах, потому что все они начинаются с `/`.

#### **3. Параметры маршрутов**

**Динамические параметры.**
Часть адреса можно объявить переменной — двоеточием перед именем. Значение подставляется во время перехода.

```tsx
// src/router.tsx (фрагмент)
{ path: 'profile/:id', element: <ProfilePage /> }
```

Прочитать значение в компоненте можно хуком `useParams`. Он возвращает объект с параметрами, ключи которого совпадают с именами в `path`:

```tsx
// src/pages/ProfilePage.tsx
import { useParams } from 'react-router'

export function ProfilePage() {
  // useParams возвращает Record<string, string | undefined>
  const { id } = useParams<{ id: string }>()

  return (
    <section>
      <h1>Профиль пользователя</h1>
      <p>Id пользователя: {id}</p>
    </section>
  )
}
```

> Обратите внимание: `id` — всегда строка. Если нужен числовой идентификатор, преобразуйте его: `Number(id)`.

Несколько параметров описываются так: `path: 'catalog/:category/:id'`. В компоненте они окажутся в одном объекте `useParams()`.

**Программная навигация: `useNavigate`.**
Иногда переход нужно выполнить не по клику по ссылке, а из кода: после успешной отправки формы, после сохранения данных, кнопкой «Назад». Для этого служит `useNavigate`:

```tsx
// src/pages/LoginPage.tsx (фрагмент)
import { useNavigate } from 'react-router'

export function SomeButton() {
  const navigate = useNavigate()

  return (
    <>
      {/* Переход на конкретный адрес */}
      <button onClick={() => navigate('/profile/42')}>Открыть профиль</button>

      {/* Переход с заменой записи в истории (нельзя вернуться назад) */}
      <button onClick={() => navigate('/home', { replace: true })}>
        На главную
      </button>

      {/* Возврат на шаг назад по истории */}
      <button onClick={() => navigate(-1)}>Назад</button>
    </>
  )
}
```

Объект `navigate` принимает либо адрес строкой, либо число (шаг по истории), либо объект вида `{ pathname, search, hash, state }`.

**Query-параметры: `useSearchParams`.**
Query-параметры — это часть адреса после знака `?`: `/search?q=react&page=2`. Они не влияют на выбор маршрута, но их удобно использовать для фильтров, сортировки и постраничной навигации.

Хук `useSearchParams` работает по принципу `useState`, но хранит значение в адресной строке:

```tsx
// src/pages/SearchPage.tsx
import { useSearchParams } from 'react-router'

export function SearchPage() {
  const [searchParams, setSearchParams] = useSearchParams()

  const query = searchParams.get('q') ?? ''
  const page = Number(searchParams.get('page') ?? '1')

  const handleChange = (value: string) => {
    // Обновляем адрес: /search?q=value&page=1
    setSearchParams({ q: value, page: '1' })
  }

  return (
    <section>
      <h1>Поиск</h1>
      <input
        type="search"
        value={query}
        onChange={(e) => handleChange(e.target.value)}
        placeholder="Что искать?"
      />
      <p>
        Страница {page}, запрос: «{query}»
      </p>
    </section>
  )
}
```

Полезно:

*   `searchParams.get('key')` — получить одно значение;
*   `searchParams.getAll('key')` — получить все значения с одинаковым именем;
*   `searchParams.toString()` — собрать строку запроса;
*   чтобы добавить параметр, не затирая остальные: `setSearchParams((prev) => { const next = new URLSearchParams(prev); next.set('page', '2'); return next })`.

#### **4. Обработка ошибок и страница 404**

**`errorElement` и `useRouteError`.**
Если во время рендера маршрута произошло исключение или не удалось загрузить данные, React Router покажет компонент из `errorElement` ближайшего маршрута (ошибки всплывают вверх по дереву). Это встроенная защита от «белого экрана».

```tsx
// src/pages/ErrorPage.tsx
import { isRouteErrorResponse, useRouteError } from 'react-router'

export function ErrorPage() {
  const error = useRouteError()

  // Ошибка уровня HTTP: 404, 401 и т. п.
  if (isRouteErrorResponse(error)) {
    return (
      <div className="error-page">
        <h1>
          {error.status} — {error.statusText}
        </h1>
        {error.data ? <p>{String(error.data)}</p> : null}
      </div>
    )
  }

  // Непредвиденная ошибка JS
  const message = error instanceof Error ? error.message : 'Неизвестная ошибка'

  return (
    <div className="error-page">
      <h1>Что-то пошло не так</h1>
      <p>{message}</p>
    </div>
  )
}
```

Подключим обработчик к корневому маршруту:

```tsx
export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    errorElement: <ErrorPage />,
    children: [ /* ... */ ],
  },
])
```

`errorElement` можно задать и для отдельного дочернего маршрута — тогда ошибка затронет только его, а общий Layout останется на месте.

**Catch-all маршрут для 404.**
`errorElement` перехватывает ошибки, но неизвестный адрес — не ошибка: роутер просто не находит совпадения. Чтобы показать страницу «Не найдено», добавьте маршрут `path: '*'` в конец списка дочерних маршрутов:

```tsx
{ path: '*', element: <NotFoundPage /> }
```

```tsx
// src/pages/NotFoundPage.tsx
import { Link } from 'react-router'

export function NotFoundPage() {
  return (
    <section className="not-found">
      <h1>404</h1>
      <p>Такой страницы не существует.</p>
      <Link to="/">Вернуться на главную</Link>
    </section>
  )
}
```

Порядок маршрутов в массиве для catch-all не критичен (React Router выбирает наиболее точное совпадение), но размещать его последним — хорошая практика для читаемости.

#### **5. Защищённые маршруты**

**Идея.** Некоторые страницы должны быть доступны только авторизованным пользователям (профиль, настройки, админ-панель). В React Router нет отдельной сущности для «охраны» маршрута — вместо этого используется **компонент-обёртка**, который проверяет условие и либо рендерит дочерние маршруты через `Outlet`, либо перенаправляет на страницу входа.

**Контекст аутентификации.** Состояние авторизации удобно хранить в контексте (подробнее о контексте — в лекции 19). Упрощённый вариант:

```tsx
// src/auth/AuthContext.tsx
import { createContext, useContext, useMemo, useState } from 'react'
import type { ReactNode } from 'react'

export interface User {
  id: number
  email: string
  name: string
  role: 'user' | 'admin'
}

interface AuthContextValue {
  user: User | null
  isAuthenticated: boolean
  isAdmin: boolean
  login: (email: string, password: string) => boolean
  logout: () => void
}

const AuthContext = createContext<AuthContextValue | null>(null)

const TOKEN_KEY = 'auth_token'

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(() => {
    const raw = localStorage.getItem(TOKEN_KEY)
    return raw ? (JSON.parse(raw) as User) : null
  })

  const login = (email: string, password: string): boolean => {
    // В реальном приложении здесь был бы запрос к API
    if (email === 'admin@example.com' && password === 'admin') {
      const nextUser: User = { id: 1, email, name: 'Администратор', role: 'admin' }
      setUser(nextUser)
      localStorage.setItem(TOKEN_KEY, JSON.stringify(nextUser))
      return true
    }
    return false
  }

  const logout = (): void => {
    setUser(null)
    localStorage.removeItem(TOKEN_KEY)
  }

  const value = useMemo<AuthContextValue>(
    () => ({
      user,
      isAuthenticated: user !== null,
      isAdmin: user?.role === 'admin',
      login,
      logout,
    }),
    [user],
  )

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>
}

// Утилита-хук: обращение к контексту с проверкой
export function useAuth(): AuthContextValue {
  const context = useContext(AuthContext)
  if (!context) {
    throw new Error('useAuth должен использоваться внутри AuthProvider')
  }
  return context
}
```

> Не забудьте обернуть приложение в `AuthProvider` в `main.tsx`: `<AuthProvider><RouterProvider router={router} /></AuthProvider>`. Провайдер должен находиться **выше** `RouterProvider`, чтобы хуки маршрутов видели контекст.

**Компонент `ProtectedRoute`:**

```tsx
// src/auth/ProtectedRoute.tsx
import { Navigate, Outlet, useLocation } from 'react-router'
import { useAuth } from './AuthContext'

export function ProtectedRoute() {
  const { isAuthenticated } = useAuth()
  const location = useLocation()

  if (!isAuthenticated) {
    // Сохраняем текущий адрес, чтобы вернуться сюда после входа
    return <Navigate to="/login" replace state={{ from: location }} />
  }

  // Пользователь авторизован — показываем дочерний маршрут
  return <Outlet />
}
```

`Navigate` — компонент-перенаправление. При рендере он немедленно меняет адрес. Атрибут `replace` заменяет текущую запись в истории, чтобы кнопка «Назад» не возвращала на закрытую страницу. Через `state` мы передаём информацию о том, откуда пришли.

**Подключение защищённых маршрутов.** Группу защищённых страниц оформляют как дочерние маршруты `ProtectedRoute`:

```tsx
// src/router.tsx (фрагмент)
import { ProtectedRoute } from './auth/ProtectedRoute'

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    errorElement: <ErrorPage />,
    children: [
      { index: true, element: <HomePage /> },
      { path: 'about', element: <AboutPage /> },
      { path: 'login', element: <LoginPage /> },

      // Всё, что вложено в ProtectedRoute, требует авторизации
      {
        element: <ProtectedRoute />,
        children: [
          { path: 'profile/:id', element: <ProfilePage /> },
          { path: 'settings', element: <SettingsPage /> },
        ],
      },

      { path: '*', element: <NotFoundPage /> },
    ],
  },
])
```

У маршрута-обёртки нет `path` — он «прозрачен» для адресов и нужен только для проверки доступа.

**Разграничение по ролям.** Так же легко добавить проверку роли. Сделаем отдельный компонент `RequireRole`:

```tsx
// src/auth/RequireRole.tsx
import { Navigate, Outlet } from 'react-router'
import { useAuth } from './AuthContext'
import type { User } from './AuthContext'

export function RequireRole({ role }: { role: User['role'] }) {
  const { isAuthenticated, user } = useAuth()

  if (!isAuthenticated) {
    return <Navigate to="/login" replace />
  }

  if (user?.role !== role) {
    return <Navigate to="/access-denied" replace />
  }

  return <Outlet />
}
```

Использование:

```tsx
{
  element: <RequireRole role="admin" />,
  children: [{ path: 'admin', element: <AdminPage /> }],
}
```

#### **6. Ленивая загрузка маршрутов**

В большом приложении не нужно скачивать код всех страниц сразу. Ленивая загрузка (lazy) разбивает сборку на части: код страницы подгружается в момент первого перехода на неё.

**Способ 1: `React.lazy` + `Suspense`.**
`React.lazy` принимает функцию, которая динамически импортирует модуль и возвращает компонент с **экспортом по умолчанию**. Пока модуль грузится, `Suspense` показывает запасной интерфейс.

```tsx
// src/router.tsx (фрагмент)
import { lazy, Suspense } from 'react'

const AboutPage = lazy(() => import('./pages/AboutPage'))

function PageLoader() {
  return <p>Загрузка страницы…</p>
}

// ...
{
  path: 'about',
  element: (
    <Suspense fallback={<PageLoader />}>
      <AboutPage />
    </Suspense>
  ),
}
```

Чтобы это работало, страница должна использовать экспорт по умолчанию:

```tsx
// src/pages/AboutPage.tsx
export default function AboutPage() {
  return <h1>О нас</h1>
}
```

**Способ 2: встроенная функция `lazy` у маршрута.**
React Router v7 умеет загружать маршрут целиком (компонент, загрузчики данных) по описанию. Это удобнее, потому что `Suspense` не нужен:

```tsx
{
  path: 'about',
  lazy: async () => {
    const { AboutPage } = await import('./pages/AboutPage')
    return { Component: AboutPage }
  },
}
```

Здесь страница может использовать именованный экспорт. React Router сам покажет индикатор загрузки, если задан `hydrateFallbackElement`.

**Когда применять.** Ленивую загрузку стоит включать для редко посещаемых тяжёлых страниц: административная панель, редакторы, разделы с большими библиотеками. Главную страницу и Layout обычно грузят сразу.

**Страница входа с возвратом на исходный адрес:**

```tsx
// src/pages/LoginPage.tsx
import { useState } from 'react'
import type { FormEvent } from 'react'
import { useLocation, useNavigate } from 'react-router'
import { useAuth } from '../auth/AuthContext'

interface LocationState {
  from?: { pathname: string }
}

export function LoginPage() {
  const { login } = useAuth()
  const navigate = useNavigate()
  const location = useLocation()

  const [email, setEmail] = useState('')
  const [password, setPassword] = useState('')
  const [error, setError] = useState<string | null>(null)

  // Адрес, с которого нас перенаправил ProtectedRoute
  const state = location.state as LocationState | null
  const from = state?.from?.pathname ?? '/'

  const handleSubmit = (event: FormEvent<HTMLFormElement>) => {
    event.preventDefault()
    setError(null)

    if (login(email, password)) {
      navigate(from, { replace: true }) // возвращаемся туда, куда шли
    } else {
      setError('Неверный email или пароль')
    }
  }

  return (
    <section className="login">
      <h1>Вход</h1>
      <form onSubmit={handleSubmit}>
        <label htmlFor="email">Email</label>
        <input
          id="email"
          type="email"
          value={email}
          onChange={(e) => setEmail(e.target.value)}
          required
        />

        <label htmlFor="password">Пароль</label>
        <input
          id="password"
          type="password"
          value={password}
          onChange={(e) => setPassword(e.target.value)}
          required
        />

        {error ? (
          <p className="form-error" role="alert">
            {error}
          </p>
        ) : null}

        <button type="submit">Войти</button>
      </form>
      <p className="hint">Демо-доступ: admin@example.com / admin</p>
    </section>
  )
}
```

**Страница профиля с параметром и query-параметром:**

```tsx
// src/pages/ProfilePage.tsx
import { useParams, useSearchParams } from 'react-router'
import { useAuth } from '../auth/AuthContext'

export function ProfilePage() {
  const { id } = useParams<{ id: string }>()
  const { user } = useAuth()
  const [searchParams, setSearchParams] = useSearchParams()

  const editMode = searchParams.get('edit') === 'true'

  const toggleEdit = () => {
    setSearchParams((prev) => {
      const next = new URLSearchParams(prev)
      next.set('edit', editMode ? 'false' : 'true')
      return next
    })
  }

  return (
    <section className="profile">
      <h1>Профиль #{id}</h1>
      <p>Вы вошли как: {user?.name}</p>
      <p>Режим редактирования: {editMode ? 'включён' : 'выключен'}</p>
      <button onClick={toggleEdit}>
        {editMode ? 'Выйти из редактирования' : 'Редактировать'}
      </button>
    </section>
  )
}
```

**Полная конфигурация маршрутов:**

```tsx
// src/router.tsx
import { lazy, Suspense } from 'react'
import { createBrowserRouter } from 'react-router'
import { RootLayout } from './layouts/RootLayout'
import { ProtectedRoute } from './auth/ProtectedRoute'
import { HomePage } from './pages/HomePage'
import { LoginPage } from './pages/LoginPage'
import { ProfilePage } from './pages/ProfilePage'
import { NotFoundPage } from './pages/NotFoundPage'
import { ErrorPage } from './pages/ErrorPage'

// «О нас» грузим лениво
const AboutPage = lazy(() => import('./pages/AboutPage'))

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    errorElement: <ErrorPage />,
    children: [
      { index: true, element: <HomePage /> },
      {
        path: 'about',
        element: (
          <Suspense fallback={<p>Загрузка страницы…</p>}>
            <AboutPage />
          </Suspense>
        ),
      },
      { path: 'login', element: <LoginPage /> },
      {
        element: <ProtectedRoute />,
        children: [{ path: 'profile/:id', element: <ProfilePage /> }],
      },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
])
```

### **Резюме**

*   **Маршрутизация** — основа SPA: роутер сопоставляет адрес с компонентом без перезагрузки страницы.
*   **`createBrowserRouter` + `RouterProvider`** — современная точка входа React Router v7.
*   **`children`** описывают вложенные маршруты, **`index`** — маршрут по умолчанию, **`path: '*'`** — страница 404.
*   **`Outlet`** — место для дочернего маршрута; позволяет вынести общий Layout.
*   **`Link`** — декларативная навигация, **`NavLink`** умеет подсвечивать активный адрес.
*   **`useParams`**, **`useNavigate`**, **`useSearchParams`** дают доступ к параметрам и навигации из кода.
*   **`errorElement`** и **`useRouteError`** защищают интерфейс от «белого экрана».
*   **Защищённые маршруты** реализуются компонентом-обёрткой с проверкой авторизации и `<Navigate to="/login" state={{ from: location }} />`.
*   **Ленивая загрузка** (`React.lazy` + `Suspense` или `lazy` у маршрута) ускоряет первую загрузку приложения.

**Лучшие практики:**

*   держите конфигурацию маршрутов в отдельном файле `router.tsx`;
*   группируйте защищённые страницы под одним `ProtectedRoute`;
*   провайдеры контекста размещайте выше `RouterProvider`;
*   используйте `replace` при служебных перенаправлениях;
*   лениво грузите редко посещаемые тяжёлые разделы;
*   всегда предусматривайте страницу 404 и обработчик ошибок.
