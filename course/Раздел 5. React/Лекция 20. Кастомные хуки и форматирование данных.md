### **Детальное рассмотрение каждого пункта плана:**

#### **1. Введение: зачем нужны кастомные хуки**

**Переиспользование логики, а не разметки.**
В React переиспользовать интерфейс помогают компоненты. Но часто переиспользовать нужно не разметку, а **логику**: подписку на данные, работу с `localStorage`, отложенное значение, таймеры, позицию окна. Раньше для этого применяли HOC и render props, а сегодня — **кастомные хуки**.

Кастомный хук — это **обычная функция**, имя которой начинается с `use` и которая внутри вызывает другие хуки (`useState`, `useEffect`, `useMemo` и т. д.). Хук не возвращает JSX — он возвращает **данные и функции**.

```tsx
// Логика использования переключателя вынесена в отдельный хук.
export function useToggle(initialValue = false) {
  const [value, setValue] = useState(initialValue);
  const toggle = () => setValue((prev) => !prev);
  return [value, toggle] as const;
}
```

```tsx
// Компонент использует готовую логику и остаётся коротким.
function Menu() {
  const [isOpen, toggleOpen] = useToggle(false);

  return (
    <>
      <button type="button" onClick={toggleOpen}>
        {isOpen ? 'Закрыть меню' : 'Открыть меню'}
      </button>
      {isOpen && <nav>«…пункты меню…»</nav>}
    </>
  );
}
```

**Правила хуков (Rules of Hooks).**
Хуки — не магия, а соглашение, которое React проверяет во время работы:
1.  Вызывайте хуки **только на верхнем уровне** компонента или другого хука. Нельзя вызывать их внутри условий, циклов и вложенных функций.
2.  Вызывайте хуки **только из компонентов React или из других хуков** — не из обычных функций.
3.  Имя собственного хука должно начинаться с `use`.

```tsx
// ❌ Плохо: хук внутри условия — порядок вызовов меняется между рендерами.
function Bad({ isEnabled }: { isEnabled: boolean }) {
  if (isEnabled) {
    const [value, setValue] = useState(0); // так нельзя
  }
}

// ✅ Хорошо: хук вызывается всегда, а логика — по условию.
function Good({ isEnabled }: { isEnabled: boolean }) {
  const [value, setValue] = useState(0);

  if (isEnabled) {
    // …работаем со значением
  }
}
```

**Почему хуки заменили HOC и render props.**
До появления хуков логику переиспользовали двумя способами.

*HOC (Higher-Order Component)* — функция, которая принимает компонент и возвращает новый компонент, «оборачивая» его и передавая дополнительные props:

```tsx
// Пример HOC: подписывает компонент на ширину окна.
function withWindowWidth<P extends object>(Component: React.ComponentType<P & { width: number }>) {
  return function Wrapped(props: P) {
    const width = useWindowWidth();
    return <Component {...props} width={width} />;
  };
}
```

*Render props* — компонент принимает функцию и вызывает её, передавая данные:

```tsx
<Mouse render={(position) => <p>Курсор: {position.x}, {position.y}</p>} />
```

Проблемы обоих подходов:
- **«Ад обёрток»**: дерево компонентов в DevTools становится вложенным и малопонятным.
- **Конфликты имён props**: обёртка может перезаписать чужое свойство.
- **Сложная типизация**: в TypeScript вывести типы HOC непросто.
- **Плохая композиция**: объединить несколько HOC или render props неудобно.

Хуки решают это: логика живёт в функции, вызывается прямо в компоненте, **без создания лишних компонентов**, и легко компонуется.

```tsx
// Та же логика хуком — без обёрток и без новых компонентов.
function Header() {
  const width = useWindowWidth();
  return <p>Ширина окна: {width}px</p>;
}
```

> Подробнее о правилах и философии хуков — в документации React: [react.dev/reference/rules](https://react.dev/reference/rules).

#### **2. Правила создания собственных хуков**

**Имя начинается с `use`.**
Без префикса `use` React не будет считать функцию хуком и не сможет проверить правила вызовов, а линтер не подскажет об ошибке.

```tsx
// ✅ Правильно: useSort
export function useSort<T>(items: T[]) { /* … */ }

// ❌ Неправильно: sortItems — это уже не хук
export function sortItems<T>(items: T[]) { /* … */ }
```

**Вызов только на верхнем уровне.**
Порядок вызовов хуков должен быть одинаковым при каждом рендере — именно так React «привязывает» состояние к нужному хуку.

```tsx
// ✅ Порядок вызовов всегда одинаков.
function Profile() {
  const [name, setName] = useState('');
  const [age, setAge] = useState(0);
  useEffect(() => { /* … */ }, []);

  return <p>{name}, {age}</p>;
}
```

```tsx
// ❌ Порядок может измениться — React потеряет соответствие состояния.
function Profile({ showAge }: { showAge: boolean }) {
  const [name, setName] = useState('');
  if (showAge) {
    const [age, setAge] = useState(0);
  }
}
```

**Из чего можно вызывать хук.**
Кастомный хук можно вызывать из компонента и из другого хука. Нельзя — из обычной функции, обработчика события или асинхронного колбэка.

```tsx
// ✅ Компонент вызывает хук.
function App() {
  const [isOpen, toggleOpen] = useToggle();
  return <button type="button" onClick={toggleOpen}>{String(isOpen)}</button>;
}
```

```tsx
// ❌ Хук внутри обработчика события — нарушение правил.
function App() {
  const handleClick = () => {
    const [isOpen, toggleOpen] = useToggle(); // так нельзя
  };
  return <button type="button" onClick={handleClick}>Нажми</button>;
}
```

#### **3. Простые кастомные хуки**

**`useToggle`** — переключатель булева значения.

```tsx
// src/hooks/useToggle.ts
import { useCallback, useState } from 'react';

// Возвращаем кортеж: [значение, функция-переключатель].
export function useToggle(initialValue = false): [boolean, () => void] {
  const [value, setValue] = useState(initialValue);

  // useCallback сохраняет одну и ту же ссылку на функцию между рендерами.
  const toggle = useCallback(() => {
    setValue((prev) => !prev);
  }, []);

  return [value, toggle];
}
```

```tsx
// Использование
function Modal() {
  const [isOpen, toggleOpen] = useToggle(false);

  return (
    <div>
      <button type="button" onClick={toggleOpen}>Показать окно</button>
      {isOpen && (
        <div role="dialog" aria-modal="true" className="modal">
          <p>Содержимое окна</p>
          <button type="button" onClick={toggleOpen}>Закрыть</button>
        </div>
      )}
    </div>
  );
}
```

**`useLocalStorage<T>`** — состояние, которое сохраняется в браузере и переживает перезагрузку страницы.

```tsx
// src/hooks/useLocalStorage.ts
import { useCallback, useState } from 'react';

export function useLocalStorage<T>(
  key: string,
  initialValue: T,
): [T, (value: T) => void] {
  // Ленивая инициализация: читаем localStorage только один раз, при первом рендере.
  const [storedValue, setStoredValue] = useState<T>(() => {
    try {
      const item = window.localStorage.getItem(key);
      return item ? (JSON.parse(item) as T) : initialValue;
    } catch (error) {
      console.warn(`Не удалось прочитать ключ "${key}" из localStorage`, error);
      return initialValue;
    }
  });

  const setValue = useCallback(
    (value: T) => {
      try {
        setStoredValue(value);
        window.localStorage.setItem(key, JSON.stringify(value));
      } catch (error) {
        console.warn(`Не удалось записать ключ "${key}" в localStorage`, error);
      }
    },
    [key],
  );

  return [storedValue, setValue];
}
```

```tsx
// Использование: тема сохраняется между визитами.
type Theme = 'light' | 'dark';

function Settings() {
  const [theme, setTheme] = useLocalStorage<Theme>('theme', 'light');

  return (
    <label>
      Тема:
      <select value={theme} onChange={(event) => setTheme(event.target.value as Theme)}>
        <option value="light">Светлая</option>
        <option value="dark">Тёмная</option>
      </select>
    </label>
  );
}
```

Почему ленивая инициализация важна: если бы мы читали `localStorage` на каждом рендере, это было бы медленнее и могло бы затирать уже введённые пользователем данные.

#### **4. Хуки с побочными эффектами**

**`useDebounce`** — откладывает обновление значения. Полезен для поиска: пока пользователь печатает, мы не шлём запрос на каждую букву.

```tsx
// src/hooks/useDebounce.ts
import { useEffect, useState } from 'react';

// Дженерик <T> — хук работает со значением любого типа.
export function useDebounce<T>(value: T, delay = 500): T {
  const [debouncedValue, setDebouncedValue] = useState(value);

  useEffect(() => {
    // Заводим таймер на delay миллисекунд.
    const timerId = window.setTimeout(() => {
      setDebouncedValue(value);
    }, delay);

    // Очистка: если value или delay изменились раньше — таймер сбрасывается.
    return () => window.clearTimeout(timerId);
  }, [value, delay]);

  return debouncedValue;
}
```

```tsx
// Использование: запрос выполняется только после паузы в вводе.
function SearchUsers() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, 400);

  useEffect(() => {
    if (!debouncedQuery) return;
    console.log('Ищем:', debouncedQuery);
    // Здесь будет запрос к API.
  }, [debouncedQuery]);

  return (
    <input
      type="search"
      value={query}
      placeholder="Поиск..."
      onChange={(event) => setQuery(event.target.value)}
    />
  );
}
```

Именно функция очистки (`return () => …`) делает эффект корректным: при каждом новом вводе старый таймер отменяется, и срабатывает только последний.

**`useFetch<T>`** — получение данных с состояниями «загрузка», «ошибка», «данные».

```tsx
// src/hooks/useFetch.ts
import { useEffect, useState } from 'react';

// Универсальный тип результата для любых данных.
interface UseFetchResult<T> {
  data: T | null;
  loading: boolean;
  error: string | null;
}

export function useFetch<T>(url: string): UseFetchResult<T> {
  const [data, setData] = useState<T | null>(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    // AbortController позволяет отменить запрос при размонтировании
    // или при изменении url — иначе получим обновление «мёртвого» компонента.
    const controller = new AbortController();

    async function load() {
      setLoading(true);
      setError(null);

      try {
        const response = await fetch(url, { signal: controller.signal });

        if (!response.ok) {
          throw new Error(`Ошибка запроса: ${response.status}`);
        }

        const result = (await response.json()) as T;
        setData(result);
      } catch (err) {
        // Отменённый запрос — не ошибка, просто выходим.
        if (err instanceof DOMException && err.name === 'AbortError') {
          return;
        }
        setError(err instanceof Error ? err.message : 'Неизвестная ошибка');
      } finally {
        if (!controller.signal.aborted) {
          setLoading(false);
        }
      }
    }

    load();

    // Функция очистки: React вызовет её при смене url или размонтировании.
    return () => controller.abort();
  }, [url]);

  return { data, loading, error };
}
```

```tsx
// Использование
interface User {
  id: number;
  name: string;
  email: string;
}

function UserList() {
  const { data: users, loading, error } = useFetch<User[]>('/api/users');

  if (loading) return <p>Загрузка…</p>;
  if (error) return <p role="alert">Ошибка: {error}</p>;
  if (!users || users.length === 0) return <p>Пользователи не найдены</p>;

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name} — {user.email}</li>
      ))}
    </ul>
  );
}
```

> В боевых проектах для серверных данных обычно используют TanStack Query (лекция 33). `useFetch` — учебный пример, который показывает, как устроена такая логика «под капотом».

#### **5. Типизация хуков дженериками**

**Зачем нужны `<T>`.**
Дженерик позволяет хуку быть универсальным, но сохранять строгую типизацию у вызывающей стороны.

```tsx
// Без дженерика пришлось бы использовать any и терять подсказки типов.
export function useFirst<T>(items: T[]): T | undefined {
  return items[0];
}

// TypeScript сам выведет T = string.
const first = useFirst(['а', 'б', 'в']); // string | undefined

// Или T = User, если указать явно.
const firstUser = useFirst<User>(users); // User | undefined
```

**Ограничения (`extends`).**
Если хуку нужны не любые значения, а, например, объекты с определённым полем, используем ограничение.

```tsx
// T обязан иметь поле id.
export function useById<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id);
}
```

```tsx
const user = useById(users, 2); // TypeScript знает, что у результата есть id
```

**Возврат кортежа или объекта.**

```tsx
// Кортеж: удобно переименовывать через деструктуризацию.
const [isOpen, toggleOpen] = useToggle(false);

// Объект: понятнее, когда значений много.
const { data, loading, error } = useFetch<User[]>('/api/users');
```

Правило простое: одно-два значения — кортеж; три и больше — объект.

#### **6. Композиция хуков**

Хуки можно собирать друг из друга — это их главное преимущество перед HOC и render props.

```tsx
// src/hooks/useUserSearch.ts
import { useDebounce } from './useDebounce';
import { useFetch } from './useFetch';
import type { User } from '../types/user';

export function useUserSearch(query: string) {
  // Откладываем запрос, пока пользователь печатает.
  const debouncedQuery = useDebounce(query, 400);

  // Формируем url и делегируем загрузку другому хуку.
  const url = debouncedQuery
    ? `/api/users?search=${encodeURIComponent(debouncedQuery)}`
    : '/api/users';

  const { data, loading, error } = useFetch<User[]>(url);

  return { users: data ?? [], loading, error };
}
```

```tsx
// Компонент вообще не знает о деталях: debounce и fetch спрятаны в хуке.
function UsersPage() {
  const [query, setQuery] = useState('');
  const { users, loading, error } = useUserSearch(query);

  return (
    <div>
      <input
        type="search"
        value={query}
        placeholder="Поиск пользователей…"
        onChange={(event) => setQuery(event.target.value)}
      />
      {loading && <p>Загрузка…</p>}
      {error && <p role="alert">{error}</p>}
      <ul>
        {users.map((user) => (
          <li key={user.id}>{user.name}</li>
        ))}
      </ul>
    </div>
  );
}
```

Компонент стал декларативным: он описывает, **что** показать, а не **как** загружать и фильтровать данные.

#### **7. Форматирование данных через `Intl`**

Встроенный объект `Intl` умеет форматировать числа, валюты и даты по правилам разных языков — без сторонних библиотек. Достаточно создать «форматтер» один раз (вне компонента) и переиспользовать его.

**`Intl.NumberFormat` — цены в рублях.**

```tsx
// src/utils/formatters.ts

// Один форматтер на всё приложение — так эффективнее.
export const priceFormatter = new Intl.NumberFormat('ru-RU', {
  style: 'currency',
  currency: 'RUB',
  minimumFractionDigits: 2,
  maximumFractionDigits: 2,
});

priceFormatter.format(12990.5);
// "12 990,50 ₽" (разделитель разрядов — неразрывный пробел)
```

Форматирование обычных чисел — проценты, разряды, знаки после запятой:

```tsx
export const percentFormatter = new Intl.NumberFormat('ru-RU', {
  style: 'percent',
  maximumFractionDigits: 1,
});

percentFormatter.format(0.873); // "87,3 %"

export const numberFormatter = new Intl.NumberFormat('ru-RU');
numberFormatter.format(1234567); // "1 234 567"
```

**`Intl.DateTimeFormat` — дата и время (`ru-RU`).**

```tsx
export const dateFormatter = new Intl.DateTimeFormat('ru-RU', {
  day: '2-digit',
  month: 'long',
  year: 'numeric',
});

dateFormatter.format(new Date('2026-09-21'));
// "21 сентября 2026 г."

export const dateTimeFormatter = new Intl.DateTimeFormat('ru-RU', {
  dateStyle: 'long',
  timeStyle: 'short',
});

dateTimeFormatter.format(new Date('2026-09-21T14:30:00'));
// "21 сентября 2026 г. в 14:30"
```

Компонент форматированной даты:

```tsx
// src/components/FormattedDate.tsx
import { dateFormatter, dateTimeFormatter } from '../utils/formatters';

interface FormattedDateProps {
  value: string | Date;
  withTime?: boolean;
}

export function FormattedDate({ value, withTime = false }: FormattedDateProps) {
  const date = typeof value === 'string' ? new Date(value) : value;

  // Некорректная дата — не роняем интерфейс.
  if (Number.isNaN(date.getTime())) {
    return <span>—</span>;
  }

  const formatter = withTime ? dateTimeFormatter : dateFormatter;

  // <time> — семантический тег для дат; dateTime хранит машинный формат.
  return <time dateTime={date.toISOString()}>{formatter.format(date)}</time>;
}
```

**`Intl.RelativeTimeFormat` — «5 минут назад».**

```tsx
export const relativeFormatter = new Intl.RelativeTimeFormat('ru-RU', {
  numeric: 'auto', // "вчера" вместо "1 день назад"
});

relativeFormatter.format(-5, 'minute'); // "5 минут назад"
relativeFormatter.format(-1, 'day');    // "вчера"
relativeFormatter.format(2, 'hour');    // "через 2 часа"
```

Чтобы получить относительное время из даты, нужно выбрать подходящую единицу измерения:

```tsx
// src/utils/relativeTime.ts
import { relativeFormatter } from './formatters';

export function formatRelativeTime(value: string | Date): string {
  const date = typeof value === 'string' ? new Date(value) : value;
  const diffSeconds = Math.round((date.getTime() - Date.now()) / 1000);

  const thresholds: Array<[Intl.RelativeTimeFormatUnit, number]> = [
    ['year', 60 * 60 * 24 * 365],
    ['month', 60 * 60 * 24 * 30],
    ['week', 60 * 60 * 24 * 7],
    ['day', 60 * 60 * 24],
    ['hour', 60 * 60],
    ['minute', 60],
  ];

  for (const [unit, secondsInUnit] of thresholds) {
    if (Math.abs(diffSeconds) >= secondsInUnit) {
      return relativeFormatter.format(Math.round(diffSeconds / secondsInUnit), unit);
    }
  }

  return relativeFormatter.format(diffSeconds, 'second');
}
```

```tsx
formatRelativeTime('2026-09-21T14:25:00'); // "5 минут назад"
```

**Кратко о `dayjs` как альтернативе.**
`Intl` встроен в браузер и не требует зависимостей. Если нужно больше удобств — парсинг в разных форматах, работа с часовыми поясами, относительное время «из коробки» — используют лёгкую библиотеку `dayjs`.

```bash
npm install dayjs
```

```tsx
// src/utils/dayjs.ts
import dayjs from 'dayjs';
import 'dayjs/locale/ru';
import relativeTime from 'dayjs/plugin/relativeTime';

dayjs.locale('ru');
dayjs.extend(relativeTime);

export { dayjs };
```

```tsx
dayjs('2026-09-21').format('D MMMM YYYY, HH:mm'); // "21 сентября 2026, 00:00"
dayjs().subtract(5, 'minute').fromNow();           // "5 минут назад"
```

Выбор простой:
- нужны стандартные форматы и нет желания добавлять зависимости — **`Intl`**;
- нужна сложная арифметика с датами и удобный синтаксис — **`dayjs`**.

// src/pages/CatalogPage.tsx (фрагмент с поиском)
import { useState } from 'react';
import { useDebounce } from '../hooks/useDebounce';

export function CatalogPage() {
  const [query, setQuery] = useState('');
  const debouncedQuery = useDebounce(query, 300);

  const visibleProducts = products.filter((product) =>
    product.title.toLowerCase().includes(debouncedQuery.toLowerCase()),
  );

  return (
    <div className="catalog">
      <h1>Каталог товаров</h1>
      <input
        type="search"
        value={query}
        placeholder="Поиск товаров…"
        onChange={(event) => setQuery(event.target.value)}
      />
      <div className="product-grid">
        {visibleProducts.map((product) => (
          <ProductCard key={product.id} product={product} />
        ))}
      </div>
    </div>
  );
}

### **Резюме**

*   **Кастомный хук** — функция с именем `use*`, которая вызывает другие хуки и переиспользует логику, а не разметку.
*   **Правила хуков**: только верхний уровень, только из компонентов и хуков, имя с `use`.
*   **Примеры хуков**: `useToggle`, `useLocalStorage<T>`, `useDebounce`, `useFetch<T>`.
*   **Дженерики** делают хуки универсальными и типобезопасными; ограничение `extends` задаёт требования к типу.
*   **Композиция** позволяет строить сложную логику из простых хуков (`useUserSearch` = `useDebounce` + `useFetch`).
*   **Хуки заменили HOC и render props**: нет «ада обёрток», конфликтов имён props и сложной типизации.
*   **`Intl.NumberFormat`** форматирует цены и числа (`ru-RU`, валюта `RUB`).
*   **`Intl.DateTimeFormat`** форматирует дату и время по локали.
*   **`Intl.RelativeTimeFormat`** выводит «5 минут назад» / «вчера».
*   **`dayjs`** — удобная альтернатива, когда нужна сложная работа с датами.
*   Форматтеры создают **один раз вне компонента** и переиспользуют.
