# Практическая работа 34. Обработка ошибок

## Тема
Централизованная обработка ошибок в ASP.NET Core Web API

## Цель
Изучить виды ошибок в веб-API, освоить централизованную обработку исключений через `IExceptionHandler` (.NET 8) и стандарт `ProblemDetails`, научиться применять собственные типы исключений, паттерн `Result<T>` и возвращать клиенту единообразные ответы с корректными HTTP-кодами.

## Теоретическая часть

### Виды ошибок

Все ошибки веб-API условно делятся на **ожидаемые** (их возникновение предусмотрено сценарием) и **неожиданные** (сбои, которые разработчик не предполагал).

| Вид ошибки | Пример | HTTP-код |
|---|---|---|
| Ошибка валидации | пустое обязательное поле, отрицательная цена | `400 Bad Request` |
| Ресурс не найден | товар с указанным `id` отсутствует | `404 Not Found` |
| Конфликт данных | дубликат уникального поля, нарушение бизнес-правила | `409 Conflict` |
| Неаутентифицирован | отсутствует или истёк JWT-токен | `401 Unauthorized` |
| Нет прав | пользователь не имеет нужной роли | `403 Forbidden` |
| Непредвиденная ошибка | деление на ноль, потеря соединения с БД | `500 Internal Server Error` |

Ожидаемые ошибки — это часть контракта API: клиент должен получать их предсказуемо и с понятным описанием. Неожиданные ошибки нельзя раскрывать клиенту в деталях (они не должны видеть стек вызовов), но их обязательно нужно логировать.

### Почему `try/catch` в каждом методе — плохо

Наивный подход — оборачивать тело каждого action в `try/catch`:

```csharp
[HttpGet("{id}")]
public async Task<IActionResult> Get(int id)
{
    try
    {
        var item = await _service.GetAsync(id);
        if (item is null) return NotFound();
        return Ok(item);
    }
    catch (Exception ex)
    {
        return StatusCode(500, ex.Message); // плохо: утечка деталей, дублирование
    }
}
```

Недостатки: код дублируется в каждом методе, логика обработки разбросана, легко «проглотить» исключение, детали внутренней реализации утекают наружу. Правильное решение — **централизованная обработка на уровне middleware**.

### Централизованная обработка: `IExceptionHandler` (.NET 8)

Начиная с .NET 8 в ASP.NET Core появился интерфейс `IExceptionHandler` — удобный способ перехватить необработанное исключение в одном месте. Встроенное middleware `ExceptionHandlerMiddleware` вызывает зарегистрированные обработчики по очереди, пока один из них не вернёт `true` (обработал).

```csharp
public interface IExceptionHandler
{
    ValueTask<bool> TryHandleAsync(
        HttpContext httpContext,
        Exception exception,
        CancellationToken cancellationToken);
}
```

Регистрация выполняется в три вызова:

```csharp
builder.Services.AddProblemDetails();                       // поддержка ProblemDetails
builder.Services.AddExceptionHandler<GlobalExceptionHandler>(); // наш обработчик
// ...
app.UseExceptionHandler();                                  // подключение middleware
```

> **Важно.** Вызов `app.UseExceptionHandler()` без аргументов использует зарегистрированные `IExceptionHandler`. Он должен стоять **в начале** конвейера, чтобы охватить все последующие middleware и endpoints.

### Стандарт ProblemDetails

`ProblemDetails` — это структурированный формат описания ошибки, закреплённый в RFC 7807/9457. ASP.NET Core умеет формировать его автоматически:

- `builder.Services.AddProblemDetails()` — регистрирует сервис, который создаёт `ProblemDetails` для ошибок и кодов состояния без тела;
- `app.UseStatusCodePages()` — превращает «пустые» ответы с кодами `401`, `403`, `404` и т. п. в ответы с телом `ProblemDetails`.

Стандартные поля:

| Поле | Назначение |
|---|---|
| `type` | URI со ссылкой на описание типа ошибки |
| `title` | Краткое человекочитаемое название |
| `status` | HTTP-код |
| `detail` | Подробное описание конкретного случая |
| `instance` | Путь запроса, к которому относится ошибка |
| `traceId` (расширение) | Идентификатор запроса для сопоставления с логами |

Для ошибок валидации используется наследник `ValidationProblemDetails` с дополнительным словарём `errors`: «имя поля → массив сообщений».

### Собственные типы исключений

Для ожидаемых ошибок удобно завести небольшой набор собственных исключений с заранее известным HTTP-кодом. Это делает код сервисов выразительным, а обработчик — простым.

```csharp
public class NotFoundException : AppException { }
public class ValidationException : AppException { }
public class ForbiddenException : AppException { }
public class ConflictException : AppException { }
```

> **Совет.** Заведите базовый абстрактный `AppException` с полем `StatusCode` — тогда обработчик сможет обрабатывать все «свои» исключения единообразно, а не перечислять каждый тип.

### Паттерн `Result<T>`

Не всякая неудача — это исключение. Когда ошибка **ожидаема и является частью нормального сценария** («товар не найден», «артикул уже занят»), удобнее возвращать результат операции без выброса исключения:

```csharp
public class Result<T>
{
    public bool IsSuccess { get; }
    public T? Value { get; }
    public string? Error { get; }
    public int StatusCode { get; }

    public static Result<T> Ok(T value) => new(true, value, null, 200);
    public static Result<T> Fail(string error, int statusCode = 400) => new(false, default, error, statusCode);
}
```

Когда что использовать:

| Ситуация | Подход |
|---|---|
| Ожидаемая ошибка (не найдено, конфликт, бизнес-правило) | `Result<T>.Fail(...)` |
| Ошибка валидации входных данных | `ValidationProblemDetails` / `ValidationException` |
| Нарушение доступа | `ForbiddenException` |
| Невозможность продолжить выполнение, сбой окружения | Исключение (перехватит `GlobalExceptionHandler`) |
| Ошибка программиста (баг) | Исключение + запись в лог уровня `Error` |

Правило простое: **исключения — для исключительных ситуаций, `Result<T>` — для предсказуемых исходов**.

### Единый формат ответа `ErrorResponse`

Главное требование к API — **все ошибки возвращаются в одном формате**. Можно использовать стандартный `ProblemDetails`, а можно собственный DTO:

```csharp
public class ErrorResponse
{
    public int Status { get; set; }
    public string Title { get; set; } = string.Empty;
    public string? Detail { get; set; }
    public IDictionary<string, string[]>? Errors { get; set; }
    public string? TraceId { get; set; }
}
```

> **Рекомендация.** В новых проектах предпочтителен стандартный `ProblemDetails`: его понимают Swagger, инструменты мониторинга и клиентские библиотеки. Собственный `ErrorResponse` оправдан, если у команды уже есть устоявшийся контракт.

### Логирование через `ILogger`

Обработчик исключений — идеальное место для логирования. Уровни выбираются по типу ошибки:

- **`LogWarning`** — ожидаемые ошибки (404, 400, 403, 409): они не должны «шуметь» в логах.
- **`LogError`** — непредвиденные сбои (500) и ошибки сохранения в БД.

Всегда логируйте сам объект исключения (`logger.LogError(ex, "...")`) и контекст (путь запроса, идентификатор). Не записывайте в лог пароли, токены и другие чувствительные данные.

### Коды ответов

| Код | Когда использовать |
|---|---|
| `400 Bad Request` | некорректные входные данные |
| `401 Unauthorized` | пользователь не аутентифицирован |
| `403 Forbidden` | аутентифицирован, но нет прав |
| `404 Not Found` | ресурс не существует |
| `409 Conflict` | конфликт (дубликат, нарушение состояния) |
| `422 Unprocessable Entity` | данные синтаксически верны, но недопустимы по бизнес-логике |
| `500 Internal Server Error` | непредвиденная ошибка сервера |

### Ошибки базы данных

При работе с EF Core сохранение изменений может выбросить `DbUpdateException`. Частые причины:

- **нарушение уникальности** (дубликат `Email`, `Sku`) — PostgreSQL отдаёт `SqlState = "23505"`, нарушенное ограничение в `ConstraintName`;
- **нарушение внешнего ключа** — `SqlState = "23503"`;
- **нарушение `NOT NULL`** — `SqlState = "23502"`.

Эти ошибки нужно преобразовывать в понятные ответы (`409 Conflict` или `400`), а не отдавать клиенту `500`. Распознать причину можно через вложенное исключение `Npgsql.PostgresException`.

```csharp
if (exception is DbUpdateException { InnerException: Npgsql.PostgresException pg })
{
    var status = pg.SqlState switch
    {
        "23505" => StatusCodes.Status409Conflict,  // уникальность
        "23503" => StatusCodes.Status400BadRequest, // внешний ключ
        _ => StatusCodes.Status500InternalServerError
    };
}
```

### Безопасность

- **Не отдавайте стектрейс в проде.** Клиенту — только `title`, `detail` для ожидаемых ошибок и `traceId`. Полное исключение пишите в лог.
- **Не раскрывайте внутренние детали** (имена таблиц, SQL, пути на диске) — это подсказка для атакующего.
- **Ограничивайте CORS** списком доверенных `allowed origins`, а не `AllowAnyOrigin`.
- **Не логируйте секреты** — токены, пароли, номера карт.

> **Примечание.** В режиме разработки детали можно расширить (например, добавить `exception.ToString()` при `app.Environment.IsDevelopment()`), но в production такой вывод должен быть отключён.

## Ход работы

1. Создать проект ASP.NET Core Web API (.NET 8) командой `dotnet new webapi -n ErrorHandlingApi`.
2. Реализовать типы исключений: базовый `AppException`, а также `NotFoundException`, `ValidationException`, `ForbiddenException`, `ConflictException`.
3. Реализовать универсальный результат `Result` / `Result<T>` с методами `Ok` и `Fail`.
4. Реализовать `GlobalExceptionHandler : IExceptionHandler`, который преобразует исключения в `ProblemDetails` и логирует их через `ILogger`.
5. Зарегистрировать сервисы в `Program.cs`: `AddControllers`, `AddProblemDetails`, `AddExceptionHandler<GlobalExceptionHandler>`, а в конвейере — `UseExceptionHandler()` и `UseStatusCodePages()`.
6. Реализовать сервис и контроллер для выбранного варианта: часть операций возвращает `Result<T>`, часть выбрасывает собственные исключения — чтобы продемонстрировать оба подхода.
7. Проверить ответы API для сценариев `400`, `404`, `409`, `500` (для проверки `500` можно временно добавить endpoint, генерирующий исключение).
8. Сделать скриншоты ответов, оформить `README.md` и загрузить решение в репозиторий Gogs.

// Common/Result.cs
using Microsoft.AspNetCore.Http;

namespace ErrorHandlingApi.Common;

/// <summary>
/// Результат операции без возвращаемого значения.
/// </summary>
public class Result
{
    public bool IsSuccess { get; }
    public string? Error { get; }
    public int StatusCode { get; }

    protected Result(bool isSuccess, string? error, int statusCode)
    {
        IsSuccess = isSuccess;
        Error = error;
        StatusCode = statusCode;
    }

    public static Result Ok() => new(true, null, StatusCodes.Status200OK);

    public static Result Fail(string error, int statusCode = StatusCodes.Status400BadRequest)
        => new(false, error, statusCode);
}

/// <summary>
/// Результат операции со значением.
/// </summary>
public class Result<T> : Result
{
    public T? Value { get; }

    private Result(bool isSuccess, T? value, string? error, int statusCode)
        : base(isSuccess, error, statusCode)
    {
        Value = value;
    }

    public static Result<T> Ok(T value) => new(true, value, null, StatusCodes.Status200OK);

    public static new Result<T> Fail(string error, int statusCode = StatusCodes.Status400BadRequest)
        => new(false, default, error, statusCode);
}
```

// Exceptions/AppException.cs
using Microsoft.AspNetCore.Http;

namespace ErrorHandlingApi.Exceptions;

/// <summary>
/// Базовое исключение приложения с известным HTTP-кодом.
/// </summary>
public abstract class AppException(string message, int statusCode) : Exception(message)
{
    public int StatusCode { get; } = statusCode;
}

/// <summary>
/// Ресурс не найден (404).
/// </summary>
public sealed class NotFoundException(string message)
    : AppException(message, StatusCodes.Status404NotFound);

/// <summary>
/// Ошибка валидации (400) с перечнем ошибок по полям.
/// </summary>
public sealed class ValidationException : AppException
{
    public IDictionary<string, string[]> Errors { get; }

    public ValidationException(IDictionary<string, string[]> errors)
        : base("Ошибка валидации", StatusCodes.Status400BadRequest)
    {
        Errors = errors;
    }
}

/// <summary>
/// Доступ запрещён (403).
/// </summary>
public sealed class ForbiddenException(string message)
    : AppException(message, StatusCodes.Status403Forbidden);

/// <summary>
/// Конфликт данных (409).
/// </summary>
public sealed class ConflictException(string message)
    : AppException(message, StatusCodes.Status409Conflict);
```

### 3. Глобальный обработчик исключений

```csharp
// Middleware/GlobalExceptionHandler.cs
using ErrorHandlingApi.Exceptions;
using Microsoft.AspNetCore.Diagnostics;
using Microsoft.AspNetCore.Mvc;
using Microsoft.EntityFrameworkCore;

namespace ErrorHandlingApi.Middleware;

/// <summary>
/// Централизованный обработчик необработанных исключений.
/// </summary>
public class GlobalExceptionHandler(ILogger<GlobalExceptionHandler> logger) : IExceptionHandler
{
    public async ValueTask<bool> TryHandleAsync(
        HttpContext httpContext,
        Exception exception,
        CancellationToken cancellationToken)
    {
        var problemDetails = new ProblemDetails
        {
            Type = "https://tools.ietf.org/html/rfc9110",
            Instance = httpContext.Request.Path,
            Extensions = { ["traceId"] = httpContext.TraceIdentifier }
        };

        switch (exception)
        {
            // Ожидаемые ошибки — уровень Warning
            case NotFoundException:
                problemDetails.Status = StatusCodes.Status404NotFound;
                problemDetails.Title = "Ресурс не найден";
                problemDetails.Detail = exception.Message;
                logger.LogWarning(exception, "Ресурс не найден: {Path}", httpContext.Request.Path);
                break;

            case ValidationException validationException:
                problemDetails.Status = StatusCodes.Status400BadRequest;
                problemDetails.Title = "Ошибка валидации";
                problemDetails.Detail = exception.Message;
                problemDetails.Extensions["errors"] = validationException.Errors;
                logger.LogWarning(exception, "Ошибка валидации: {Path}", httpContext.Request.Path);
                break;

            case ForbiddenException:
                problemDetails.Status = StatusCodes.Status403Forbidden;
                problemDetails.Title = "Доступ запрещён";
                problemDetails.Detail = exception.Message;
                logger.LogWarning(exception, "Доступ запрещён: {Path}", httpContext.Request.Path);
                break;

            case ConflictException:
                problemDetails.Status = StatusCodes.Status409Conflict;
                problemDetails.Title = "Конфликт данных";
                problemDetails.Detail = exception.Message;
                logger.LogWarning(exception, "Конфликт данных: {Path}", httpContext.Request.Path);
                break;

            // Ошибки сохранения в БД — уровень Error
            case DbUpdateException:
                problemDetails.Status = StatusCodes.Status409Conflict;
                problemDetails.Title = "Ошибка сохранения данных";
                problemDetails.Detail = "Не удалось сохранить изменения: нарушено ограничение целостности.";
                logger.LogError(exception, "Ошибка сохранения данных: {Path}", httpContext.Request.Path);
                break;

            // Непредвиденные ошибки — уровень Error, детали скрываем
            default:
                problemDetails.Status = StatusCodes.Status500InternalServerError;
                problemDetails.Title = "Внутренняя ошибка сервера";
                problemDetails.Detail = null;
                logger.LogError(exception, "Необработанное исключение: {Path}", httpContext.Request.Path);
                break;
        }

        httpContext.Response.StatusCode = problemDetails.Status.Value;
        await httpContext.Response.WriteAsJsonAsync(problemDetails, cancellationToken);

        return true; // исключение обработано
    }
}
```

### 4. Program.cs

```csharp
// Program.cs
using ErrorHandlingApi.Middleware;
using ErrorHandlingApi.Services;

var builder = WebApplication.CreateBuilder(args);

builder.Services.AddControllers();

// Стандартизированный формат ошибок + traceId в каждом ответе
builder.Services.AddProblemDetails(options =>
{
    options.CustomizeProblemDetails = context =>
    {
        context.ProblemDetails.Instance ??= context.HttpContext.Request.Path;
        context.ProblemDetails.Extensions["traceId"] = context.HttpContext.TraceIdentifier;
    };
});

// Регистрация централизованного обработчика исключений
builder.Services.AddExceptionHandler<GlobalExceptionHandler>();

builder.Services.AddSingleton<IProductService, ProductService>();

var app = builder.Build();

// Подключаем обработку исключений в начале конвейера
app.UseExceptionHandler();

// Пустые ответы (401/403/404) превращаем в ProblemDetails
app.UseStatusCodePages();

app.MapControllers();

app.Run();
```

/// <summary>Операции над товарами.</summary>
public interface IProductService
{

    Task<Result<Product>> GetByIdAsync(int id, CancellationToken ct);
    Task<Result<Product>> CreateAsync(CreateProductRequest request, CancellationToken ct);
    Task<Result> DeleteAsync(int id, CancellationToken ct);

```csharp
// Services/ProductService.cs
using ErrorHandlingApi.Common;
using ErrorHandlingApi.Dtos;
using ErrorHandlingApi.Exceptions;
using ErrorHandlingApi.Models;
using Microsoft.AspNetCore.Http;

namespace ErrorHandlingApi.Services;

/// <summary>
/// Сервис товаров. Часть операций возвращает Result<T>,
/// часть — выбрасывает собственные исключения (для демонстрации).
/// </summary>
public class ProductService : IProductService
{
    private static readonly List<Product> Products =
    [
        new Product { Id = 1, Name = "Ноутбук", Sku = "NB-001", Price = 79999m },
        new Product { Id = 2, Name = "Мышь", Sku = "MS-001", Price = 1490m }
    ];

    public Task<Result<List<Product>>> GetAllAsync(CancellationToken ct)
        => Task.FromResult(Result<List<Product>>.Ok(Products.ToList()));

    public Task<Result<Product>> GetByIdAsync(int id, CancellationToken ct)
    {
        var product = Products.FirstOrDefault(p => p.Id == id);

        return Task.FromResult(product is null
            ? Result<Product>.Fail($"Товар с идентификатором {id} не найден.", StatusCodes.Status404NotFound)
            : Result<Product>.Ok(product));
    }

    public Task<Result<Product>> CreateAsync(CreateProductRequest request, CancellationToken ct)
    {
        if (Products.Any(p => p.Sku.Equals(request.Sku, StringComparison.OrdinalIgnoreCase)))
        {
            return Task.FromResult(Result<Product>.Fail(
                $"Товар с артикулом «{request.Sku}» уже существует.",
                StatusCodes.Status409Conflict));
        }

        var product = new Product
        {
            Id = Products.Count == 0 ? 1 : Products.Max(p => p.Id) + 1,
            Name = request.Name,
            Sku = request.Sku,
            Price = request.Price
        };

        Products.Add(product);
        return Task.FromResult(Result<Product>.Ok(product));
    }

    public Task<Result> DeleteAsync(int id, CancellationToken ct)
    {
        var product = Products.FirstOrDefault(p => p.Id == id);
        if (product is null)
        {
            return Task.FromResult(Result.Fail(
                $"Товар с идентификатором {id} не найден.",
                StatusCodes.Status404NotFound));
        }

        Products.Remove(product);
        return Task.FromResult(Result.Ok());
    }

    // Вариант через исключение: обработчик сам подберёт статус 404
    public Task<Product> GetOrThrowAsync(int id, CancellationToken ct)
    {
        var product = Products.FirstOrDefault(p => p.Id == id);
        if (product is null)
        {
            throw new NotFoundException($"Товар с идентификатором {id} не найден.");
        }

        return Task.FromResult(product);
    }
}
```

### 6. Контроллер

```csharp
// Controllers/ProductsController.cs
using ErrorHandlingApi.Common;
using ErrorHandlingApi.Dtos;
using ErrorHandlingApi.Models;
using ErrorHandlingApi.Services;
using Microsoft.AspNetCore.Mvc;

namespace ErrorHandlingApi.Controllers;

/// <summary>Операции над товарами.</summary>
[ApiController]
[Route("api/[controller]")]
public class ProductsController(IProductService service) : ControllerBase
{
    /// <summary>Получить все товары.</summary>
    [HttpGet]
    [ProducesResponseType(typeof(List<Product>), StatusCodes.Status200OK)]
    public async Task<IActionResult> GetAll(CancellationToken ct)
    {
        var result = await service.GetAllAsync(ct);
        return ToActionResult(result);
    }

    /// <summary>Получить товар по идентификатору (через Result).</summary>
    [HttpGet("{id:int}")]
    [ProducesResponseType(typeof(Product), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetById(int id, CancellationToken ct)
    {
        var result = await service.GetByIdAsync(id, ct);
        return ToActionResult(result);
    }

    /// <summary>Получить товар по идентификатору (через исключение).</summary>
    [HttpGet("{id:int}/details")]
    [ProducesResponseType(typeof(Product), StatusCodes.Status200OK)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> GetDetails(int id, CancellationToken ct)
    {
        var product = await service.GetOrThrowAsync(id, ct);
        return Ok(product);
    }

    /// <summary>Создать товар.</summary>
    [HttpPost]
    [ProducesResponseType(typeof(Product), StatusCodes.Status201Created)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status409Conflict)]
    public async Task<IActionResult> Create(CreateProductRequest request, CancellationToken ct)
    {
        var result = await service.CreateAsync(request, ct);
        if (!result.IsSuccess)
        {
            return Problem(result.Error, statusCode: result.StatusCode);
        }

        return CreatedAtAction(nameof(GetById), new { id = result.Value!.Id }, result.Value);
    }

    /// <summary>Удалить товар.</summary>
    [HttpDelete("{id:int}")]
    [ProducesResponseType(StatusCodes.Status204NoContent)]
    [ProducesResponseType(typeof(ProblemDetails), StatusCodes.Status404NotFound)]
    public async Task<IActionResult> Delete(int id, CancellationToken ct)
    {
        var result = await service.DeleteAsync(id, ct);
        return result.IsSuccess ? NoContent() : ToActionResult(result);
    }

    // Единое преобразование Result<T> в ответ контроллера
    private IActionResult ToActionResult<T>(Result<T> result)
        => result.IsSuccess
            ? Ok(result.Value)
            : Problem(result.Error, statusCode: result.StatusCode);

    private IActionResult ToActionResult(Result result)
        => result.IsSuccess
            ? NoContent()
            : Problem(result.Error, statusCode: result.StatusCode);
}
```

### 7. Примеры ответов

**`404 Not Found`** — запрос `GET /api/products/42`:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110",
  "title": "Ресурс не найден",
  "status": 404,
  "detail": "Товар с идентификатором 42 не найден.",
  "instance": "/api/products/42",
  "traceId": "0HN7A2F3G4H5I6J7K8L9M0"
}
```

**`409 Conflict`** — повторное создание товара с тем же артикулом:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110",
  "title": "Конфликт данных",
  "status": 409,
  "detail": "Товар с артикулом «NB-001» уже существует.",
  "instance": "/api/products",
  "traceId": "0HN7A2F3G4H5I6J7K8L9M1"
}
```

**`400 Bad Request`** — ошибка валидации (при `ValidationException` с полем `errors`):

```json
{
  "type": "https://tools.ietf.org/html/rfc9110",
  "title": "Ошибка валидации",
  "status": 400,
  "detail": "Ошибка валидации",
  "instance": "/api/products",
  "errors": {
    "Name": ["Название товара обязательно для заполнения."],
    "Price": ["Цена должна быть больше 0."]
  },
  "traceId": "0HN7A2F3G4H5I6J7K8L9M2"
}
```

**`500 Internal Server Error`** — непредвиденная ошибка (детали скрыты):

```json
{
  "type": "https://tools.ietf.org/html/rfc9110",
  "title": "Внутренняя ошибка сервера",
  "status": 500,
  "instance": "/api/products",
  "traceId": "0HN7A2F3G4H5I6J7K8L9M3"
}
```

> **Обратите внимание.** В ответе `500` отсутствует `detail` — клиент не должен видеть внутренние детали, но в логах сервера сохранено полное исключение с тем же `traceId`, что упрощает диагностику.

## 15 вариантов заданий

Для каждого варианта требуется: собственные исключения, `GlobalExceptionHandler`, `Result<T>` и минимум три сценария ошибок с разными HTTP-кодами.

**Вариант 1: Библиотека книг**
Сущности: книга, читатель, выдача.
Ошибки: книга не найдена (`404`); книга уже выдана другому читателю (`409`); пустое название при создании (`400`); попытка выдать книгу читателю младше ограничения (`403`).

**Вариант 2: Интернет-магазин**
Сущности: товар, заказ.
Ошибки: товар не найден (`404`); недостаточно товара на складе (`409`); недопустимая цена (`400`); попытка отменить чужой заказ (`403`).

**Вариант 3: Учёт студентов**
Сущности: студент, группа.
Ошибки: студент не найден (`404`); студент с таким номером зачётки уже существует (`409`); некорректная дата рождения (`400`); попытка удалить студента чужого факультета (`403`).

**Вариант 4: Бронирование переговорных комнат**
Сущности: комната, бронь.
Ошибки: комната не найдена (`404`); время брони пересекается с существующей (`409`); время окончания раньше начала (`400`).

**Вариант 5: Продажа билетов в кино**
Сущности: фильм, сеанс, билет.
Ошибки: сеанс не найден (`404`); мест на сеанс больше нет (`409`); указано несуществующее место (`400`); возврат билета позже разрешённого срока (`409`).

**Вариант 6: Служба доставки**
Сущности: заказ доставки, курьер.
Ошибки: заказ не найден (`404`); курьер занят (`409`); адрес не в зоне обслуживания (`400`); попытка изменить назначенный заказ (`403`).

**Вариант 7: Записи в медицинскую клинику**
Сущности: врач, запись на приём.
Ошибки: врач не найден (`404`); время приёма уже занято (`409`); дата в прошлом (`400`); доступ к чужой медицинской карте (`403`).

**Вариант 8: Банковские счета**
Сущности: счёт, транзакция.
Ошибки: счёт не найден (`404`); недостаточно средств (`409`); отрицательная сумма перевода (`400`); операция по чужому счёту (`403`).

**Вариант 9: Фитнес-клуб**
Сущности: абонемент, клиент, тренер.
Ошибки: клиент не найден (`404`); абонемент просрочен (`409`); некорректный срок абонемента (`400`).

**Вариант 10: Автосервис**
Сущности: автомобиль, заказ-наряд.
Ошибки: автомобиль не найден (`404`); мастер уже назначен на другой заказ (`409`); пробег меньше предыдущего (`400`); изменение закрытого заказа (`403`).

**Вариант 11: Онлайн-школа**
Сущности: курс, запись на курс.
Ошибки: курс не найден (`404`); мест на курсе нет (`409`); повторная запись на тот же курс (`409`); запись без оплаты (`400`).

**Вариант 12: Гостиница**
Сущности: номер, бронирование.
Ошибки: номер не найден (`404`); номер занят на указанные даты (`409`); выезд раньше заезда (`400`); изменение чужой брони (`403`).

**Вариант 13: Аптека**
Сущности: лекарство, продажа.
Ошибки: лекарство не найдено (`404`); срок годности истёк (`409`); отрицательное количество (`400`); продажа рецептурного препарата без рецепта (`403`).

**Вариант 14: HR-система**
Сущности: сотрудник, заявка на отпуск.
Ошибки: сотрудник не найден (`404`); дата начала позже окончания (`400`); на сотрудника уже есть отпуск в этот период (`409`); согласование заявки чужого отдела (`403`).

**Вариант 15: Приёмная комиссия**
Сущности: абитуриент, заявление.
Ошибки: абитуриент не найден (`404`); заявление уже подано на эту специальность (`409`); балл вне диапазона 0–100 (`400`); попытка изменить поданное заявление после закрытия приёма (`403`).

## Критерии оценки

### 5 (Отлично)
- Реализован `GlobalExceptionHandler : IExceptionHandler` с регистрацией через `AddExceptionHandler`
- Все ошибки возвращаются в едином формате `ProblemDetails` с корректными HTTP-кодами
- Реализованы собственные исключения и паттерн `Result<T>`, между ними выбрана осмысленная граница
- Настроено логирование через `ILogger` с разными уровнями; в ответе `500` не раскрываются детали
- Подключены `AddProblemDetails()` и `UseStatusCodePages()`
- README.md оформлен, приложены скриншоты ответов с разными кодами

### 4 (Хорошо)
- Централизованная обработка работает, но охвачены не все типы ошибок
- Формат ответов единый, однако не для всех статусов
- Логирование присутствует частично
- README.md оформлен с небольшими недочётами

### 3 (Удовлетворительно)
- Обработка ошибок реализована частично или через дублирующиеся `try/catch`
- Формат ответов различается для разных ошибок
- Логирование отсутствует или минимально
- README.md оформлен не полностью

### 2 (Неудовлетворительно)
- Обработка ошибок не реализована
- Клиенту отдаются внутренние детали и стектрейс
- Проект не компилируется
- Отсутствует README.md
