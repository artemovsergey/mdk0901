# Практическая работа 37. Обработка ошибок от сервера

### **Тема:** Обработка ошибок от сервера API в React — Axios и TanStack Query

### **Цель:**
Освоить системную обработку ошибок, приходящих от серверного API в React-приложении. Научиться различать типы ошибок, преобразовывать технические сообщения в понятные пользователю, настраивать повторные запросы, показывать ошибки в интерфейсе и защищать приложение через Error Boundary и маршруты-заглушки.

### **Теоретическая часть:**

**Категории ошибок.** Ошибки при работе с сетью делятся на несколько групп, и для каждой группы нужна своя реакция:

| Категория | Примеры | Что делать |
|---|---|---|
| Сетевые | нет соединения, `ERR_NETWORK`, CORS | Сообщить о проблеме с подключением, предложить повторить |
| Таймаут | `ECONNABORTED`, превышено `timeout` | Предложить повторить запрос |
| Клиентские 4xx | 400, 401, 403, 404, 409, 429 | Объяснить причину, не повторять автоматически |
| Валидация | 400 / 422 с полями `errors` | Показать сообщения под конкретными полями |
| Серверные 5xx | 500, 502, 503 | Показать «ошибка на сервере», повторить запрос |

**Объект ошибки Axios.** Axios передаёт в `catch` объект `AxiosError`. Полезные свойства:

*   `error.response` — ответ сервера (если он вообще был). Если свойства нет — значит, запрос не дошёл до сервера (сеть или таймаут);
*   `error.response.status` — HTTP-код (404, 500 и т. д.);
*   `error.response.data` — тело ответа с сообщением сервера;
*   `error.code` — машинный код (`ECONNABORTED`, `ERR_NETWORK`);
*   `error.message` — техническое сообщение.

Проверить, что ошибка пришла именно от Axios, помогает функция `axios.isAxiosError(error)`. Она работает как защита типа: после проверки TypeScript знает, что у объекта есть `response` и `code`.

```ts
import axios from 'axios';

if (axios.isAxiosError(error)) {
  console.log(error.response?.status, error.code);
}
```

**Два места обработки ошибок.** В React есть два разных механизма, и их не нужно путать:

*   **`isError` в `useQuery`** — ошибка запроса на чтение. TanStack Query сам хранит ошибку в объекте результата и умеет повторять запрос. Здесь не нужен `try/catch`: достаточно ветки `if (isError)`.
*   **`try/catch` (или `onError`) в мутациях** — ошибка запроса на изменение. `useMutation` вызывает `onError`, а `mutation.error` содержит ошибку. Локальный `try/catch` нужен только если функция вызывается вручную вне мутации.

**Повторные запросы.** `useQuery` принимает:

*   `retry` — число попыток или функция `(failureCount, error) => boolean`. Логично не повторять клиентские ошибки 4xx;
*   `retryDelay` — задержка перед повтором, можно задать формулой (экспоненциальная задержка).

**Показ ошибок пользователю.** Технические сообщения вроде `Request failed with status code 500` бесполезны. Используют:

*   компонент `ErrorState` с понятным текстом и кнопкой «Попробовать снова»;
*   всплывающие уведомления (тосты) — для фоновых ошибок;
*   сообщения под полями формы — для ошибок валидации 400/422.

**Error Boundary.** Ошибку в процессе рендера компонента нельзя поймать через `try/catch`. Для этого используют **Error Boundary** — компонент, который перехватывает такие ошибки и показывает запасной интерфейс. Его можно написать классом (методы `getDerivedStateFromError` и `componentDidCatch`) или взять готовый из пакета `react-error-boundary`.

**`errorElement` в React Router.** Если ошибка произошла при загрузке данных маршрута, React Router покажет компонент, указанный в `errorElement`. Это удобно для страниц «404 — не найдено», «Доступ запрещён» и «Ошибка сервера».

**1. Единый разбор ошибок — `src/api/errors.ts`:**

```ts
import axios from 'axios';

export type ApiErrorKind =
  | 'network'
  | 'timeout'
  | 'validation'
  | 'unauthorized'
  | 'forbidden'
  | 'notFound'
  | 'rateLimit'
  | 'server'
  | 'unknown';

export interface NormalizedError {
  kind: ApiErrorKind;
  status?: number;
  message: string;
  fieldErrors: Record<string, string>;
}

interface ServerFieldError {
  field: string;
  message: string;
}

interface ServerErrorBody {
  message?: string;
  errors?: ServerFieldError[];
}

// Приводит любую ошибку к единому формату, понятному интерфейсу.
export function normalizeError(error: unknown): NormalizedError {
  if (!axios.isAxiosError(error)) {
    return {
      kind: 'unknown',
      message: error instanceof Error ? error.message : 'Неизвестная ошибка',
      fieldErrors: {},
    };
  }

  // Ответа нет: запрос не дошёл до сервера.
  if (!error.response) {
    if (error.code === 'ECONNABORTED') {
      return {
        kind: 'timeout',
        message: 'Сервер не ответил вовремя. Попробуйте ещё раз.',
        fieldErrors: {},
      };
    }
    return {
      kind: 'network',
      message: 'Нет соединения с сервером. Проверьте подключение к интернету.',
      fieldErrors: {},
    };
  }

  const status = error.response.status;
  const body = error.response.data as ServerErrorBody | undefined;

  switch (status) {
    case 400:
    case 422:
      return {
        kind: 'validation',
        status,
        message: body?.message ?? 'Проверьте правильность заполнения полей',
        fieldErrors: toFieldErrors(body?.errors),
      };
    case 401:
      return { kind: 'unauthorized', status, message: 'Требуется авторизация', fieldErrors: {} };
    case 403:
      return { kind: 'forbidden', status, message: 'Доступ запрещён', fieldErrors: {} };
    case 404:
      return {
        kind: 'notFound',
        status,
        message: 'Запрашиваемый ресурс не найден',
        fieldErrors: {},
      };
    case 429:
      return {
        kind: 'rateLimit',
        status,
        message: 'Слишком много запросов. Попробуйте позже.',
        fieldErrors: {},
      };
    default:
      if (status >= 500) {
        return {
          kind: 'server',
          status,
          message: 'Ошибка на сервере. Мы уже разбираемся, попробуйте позже.',
          fieldErrors: {},
        };
      }
      return {
        kind: 'unknown',
        status,
        message: body?.message ?? 'Произошла неизвестная ошибка',
        fieldErrors: {},
      };
  }
}

function toFieldErrors(errors?: ServerFieldError[]): Record<string, string> {
  if (!errors || errors.length === 0) {
    return {};
  }

  return errors.reduce<Record<string, string>>((result, item) => {
    result[item.field] = item.message;
    return result;
  }, {});
}

// Короткое сообщение для показа пользователю.
export function getErrorMessage(error: unknown): string {
  return normalizeError(error).message;
}
```

**5. Список с настройкой повторов — `src/components/PostsList.tsx`:**

```tsx
import { useQuery } from '@tanstack/react-query';
import type { AxiosError } from 'axios';
import { fetchPosts } from '../api/posts';
import type { Post } from '../api/posts';
import { ErrorState } from './ErrorState';

export function PostsList() {
  const { data, isPending, isError, error, refetch } = useQuery<Post[], AxiosError>({
    queryKey: ['posts'],
    queryFn: fetchPosts,
    // Повторяем только временные ошибки: сеть, таймаут и 5xx.
    retry: (failureCount, err) => {
      const status = err.response?.status;

      // Клиентские ошибки 4xx повторять бессмысленно.
      if (status !== undefined && status >= 400 && status < 500) {
        return false;
      }
      return failureCount < 2;
    },
    // Экспоненциальная задержка: 1с, 2с, 4с, но не больше 8с.
    retryDelay: (attempt) => Math.min(1_000 * 2 ** attempt, 8_000),
  });

  if (isPending) {
    return <p role="status">Загрузка записей…</p>;
  }

  if (isError) {
    return <ErrorState error={error} onRetry={() => void refetch()} />;
  }

  if (data.length === 0) {
    return <p>Записей пока нет.</p>;
  }

  return (
    <ul>
      {data.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```

**6. Хранилище уведомлений на Zustand — `src/store/toastStore.ts`:**

```ts
import { create } from 'zustand';

export type ToastType = 'success' | 'error' | 'warning' | 'info';

export interface Toast {
  id: number;
  type: ToastType;
  message: string;
}

interface ToastState {
  toasts: Toast[];
  show: (type: ToastType, message: string) => void;
  dismiss: (id: number) => void;
}

let nextId = 1;

export const useToastStore = create<ToastState>((set, get) => ({
  toasts: [],
  show: (type, message) => {
    const id = nextId++;
    set((state) => ({ toasts: [...state.toasts, { id, type, message }] }));
    // Автоматически скрываем уведомление через 4 секунды.
    window.setTimeout(() => get().dismiss(id), 4_000);
  },
  dismiss: (id) =>
    set((state) => ({ toasts: state.toasts.filter((toast) => toast.id !== id) })),
}));

// Сокращения, которыми удобно пользоваться вне компонентов.
export const toast = {
  success: (message: string) => useToastStore.getState().show('success', message),
  error: (message: string) => useToastStore.getState().show('error', message),
  warning: (message: string) => useToastStore.getState().show('warning', message),
  info: (message: string) => useToastStore.getState().show('info', message),
};
```

export function ToastHost() {

**8. Форма с разбором ошибок валидации — `src/components/ProfileForm.tsx`:**

```tsx
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { z } from 'zod';
import { useMutation } from '@tanstack/react-query';
import { updateProfile } from '../api/profile';
import type { ProfileFormValues } from '../api/profile';
import { normalizeError } from '../api/errors';
import { toast } from '../store/toastStore';

const profileSchema = z.object({
  name: z.string().min(2, 'Имя должно содержать минимум 2 символа'),
  email: z.string().email('Введите корректный email'),
});

export function ProfileForm() {
  const {
    register,
    handleSubmit,
    setError,
    reset,
    formState: { errors },
  } = useForm<ProfileFormValues>({
    resolver: zodResolver(profileSchema),
    defaultValues: { name: '', email: '' },
  });

  const mutation = useMutation({
    mutationFn: (values: ProfileFormValues) => updateProfile(values),
    onSuccess: () => {
      toast.success('Профиль сохранён');
    },
    onError: (error: unknown) => {
      const normalized = normalizeError(error);
      const fields = Object.entries(normalized.fieldErrors);

      // Ошибки валидации 400/422 раскладываем по полям формы.
      fields.forEach(([field, message]) => {
        setError(field as keyof ProfileFormValues, { type: 'server', message });
      });

      // Всё остальное показываем уведомлением.
      if (fields.length === 0) {
        toast.error(normalized.message);
      }
    },
  });

  return (
    <form onSubmit={handleSubmit((values) => mutation.mutate(values))} noValidate>
      <div>
        <label htmlFor="name">Имя</label>
        <input id="name" {...register('name')} />
        {errors.name && <p className="field-error">{errors.name.message}</p>}
      </div>

      <div>
        <label htmlFor="email">Email</label>
        <input id="email" type="email" {...register('email')} />
        {errors.email && <p className="field-error">{errors.email.message}</p>}
      </div>

      <button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? 'Сохранение…' : 'Сохранить'}
      </button>

      <button type="button" onClick={() => reset()} disabled={mutation.isPending}>
        Отмена
      </button>
    </form>
  );
}
```

**9. Error Boundary — `src/components/ErrorBoundary.tsx`:**

```tsx
import { Component } from 'react';
import type { ErrorInfo, ReactNode } from 'react';

interface ErrorBoundaryProps {
  children: ReactNode;
}

interface ErrorBoundaryState {
  hasError: boolean;
  message: string;
}

// Классовый компонент — единственный способ поймать ошибки рендера.
export class ErrorBoundary extends Component<ErrorBoundaryProps, ErrorBoundaryState> {
  state: ErrorBoundaryState = { hasError: false, message: '' };

  static getDerivedStateFromError(error: Error): ErrorBoundaryState {
    return { hasError: true, message: error.message };
  }

  componentDidCatch(error: Error, info: ErrorInfo): void {
    console.error('Ошибка интерфейса:', error, info.componentStack);
  }

  render(): ReactNode {
    if (this.state.hasError) {
      return (
        <div role="alert" className="error-boundary">
          <h2>Что-то пошло не так</h2>
          <p>{this.state.message}</p>
          <button
            type="button"
            onClick={() => this.setState({ hasError: false, message: '' })}
          >
            Попробовать снова
          </button>
        </div>
      );
    }

    return this.props.children;
  }
}
```

## **Варианты заданий:**

### **Вариант 1: Классификация ошибок и уведомления**
Реализуйте универсальный обработчик ошибок, который по статусу ответа определяет тип ошибки (сеть, таймаут, 4xx, 5xx, валидация) и автоматически показывает уведомление с понятным текстом. Используйте `axios.isAxiosError` и компонент уведомлений.

### **Вариант 2: Retry с экспоненциальной задержкой**
Создайте механизм повторных запросов с экспоненциально растущей задержкой для сетевых ошибок и ошибок сервера. Настройте в `useQuery` параметры `retry` и `retryDelay`, покажите номер текущей попытки и не повторяйте клиентские ошибки 4xx.

### **Вариант 3: Ошибки валидации по полям**
Реализуйте форму с `react-hook-form` и `zod`, которая показывает сообщения об ошибках под конкретными полями. Ошибки валидации, пришедшие с сервера (400/422), раскладывайте по полям через `setError`.

### **Вариант 4: Система уведомлений**
Создайте сервис уведомлений с четырьмя типами сообщений (`success`, `error`, `warning`, `info`), автоматическим скрытием и ручным закрытием. Храните уведомления в Zustand и выводите их в общем компоненте `ToastHost`.

### **Вариант 5: Fallback при ошибке сети**
Реализуйте стратегию запасных данных: при ошибке сети показывайте последние успешно загруженные (кэшированные) данные с пометкой, что они могли устареть. Используйте сохранение данных в `localStorage` и `placeholderData` в `useQuery`.

### **Вариант 6: Страницы ошибок 404, 500, 403**
Создайте отдельные страницы для 404, 500 и 403 с собственным дизайном и кнопкой возврата на главную. Показывайте их через `errorElement` маршрута и обработку статуса ошибки.

### **Вариант 7: Логирование ошибок с отправкой на сервер**
Реализуйте механизм логирования ошибок на клиенте: собирайте сообщение, статус, адрес и время ошибки, затем отправляйте данные в сервис мониторинга отдельным POST-запросом. Учтите, что сбой самого логирования не должен ломать приложение.

### **Вариант 8: Ошибки загрузки файлов**
Создайте систему обработки ошибок при загрузке файлов: показывайте прогресс, а при ошибке — детальную причину (слишком большой файл, неверный формат, ошибка сервера). Используйте `onUploadProgress` и разбор ответа сервера.

### **Вариант 9: Сетевые ошибки и CORS**

## **Пример README.md для варианта 1:**

```markdown
# Практическая работа 37. Обработка ошибок от сервера

## Вариант 1: Классификация ошибок и уведомления

### Задание:
Реализовать универсальный обработчик ошибок, который по статусу ответа определяет тип ошибки и автоматически показывает уведомление с понятным текстом.

### Реализация:

#### src/api/errors.ts
```ts
import axios from 'axios';

export type ApiErrorKind = 'network' | 'timeout' | 'validation' | '4xx' | 'server';

export interface AppError {
  kind: ApiErrorKind;
  message: string;
}

export function normalizeError(error: unknown): AppError {
  if (!axios.isAxiosError(error)) {
    return { kind: '4xx', message: 'Неизвестная ошибка' };
  }

  if (!error.response) {
    if (error.code === 'ECONNABORTED') {
      return { kind: 'timeout', message: 'Сервер не ответил вовремя' };
    }
    return { kind: 'network', message: 'Нет соединения с интернетом' };
  }

  const status = error.response.status;

  if (status === 400 || status === 422) {
    return { kind: 'validation', message: 'Проверьте заполнение полей' };
  }
  if (status >= 500) {
    return { kind: 'server', message: 'Ошибка на сервере. Попробуйте позже' };
  }
  return { kind: '4xx', message: `Ошибка запроса (${status})` };
}
```

#### src/components/PostsWithErrors.tsx
```tsx
import { useQuery } from '@tanstack/react-query';
import type { AxiosError } from 'axios';
import { fetchPosts } from '../api/posts';
import type { Post } from '../api/posts';
import { normalizeError } from '../api/errors';
import { toast } from '../store/toastStore';

export function PostsWithErrors() {
  const { data, isPending, isError, error } = useQuery<Post[], AxiosError>({
    queryKey: ['posts'],
    queryFn: fetchPosts,
  });

  if (isError) {
    // Показываем пользователю разобранное сообщение.
    const appError = normalizeError(error);
    toast.error(appError.message);
  }

  if (isPending) {
    return <p role="status">Загрузка…</p>;
  }

  if (isError) {
    return <p role="alert">{normalizeError(error).message}</p>;
  }

  return (
    <ul>
      {data.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```
