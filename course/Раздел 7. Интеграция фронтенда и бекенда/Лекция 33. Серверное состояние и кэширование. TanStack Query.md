### **Детальное рассмотрение каждого пункта плана:**

#### **1. Клиентское и серверное состояние**

В любом приложении есть два принципиально разных вида состояния.

**Клиентское состояние** — данные, которые живут только в браузере и принадлежат интерфейсу: открыто ли модальное окно, выбранная тема оформления, текст, который пользователь печатает в форме, активный пункт меню. Такое состояние удобно хранить в `useState` (внутри компонента) или в Zustand (если оно нужно многим компонентам).

**Серверное состояние** — данные, которые хранятся на сервере (в базе данных) и лишь «отражаются» в интерфейсе: список товаров, профиль пользователя, каталог записей. Такие данные:
*   принадлежат серверу, а не приложению;
*   могут измениться без ведома браузера;
*   требуют загрузки по сети и могут устареть.

Сравним два вида состояния:

| Признак | Клиентское состояние | Серверное состояние |
|---|---|---|
| Где «живёт» | В браузере | На сервере (БД) |
| Примеры | открыто ли окно, тема, черновик формы | каталог товаров, профиль пользователя |
| Кто владелец данных | приложение | сервер |
| Инструменты | `useState`, Zustand | TanStack Query |
| Что приходится решать | — | кэш, устаревание, повторные запросы, синхронизация |

**Как обычно делают новички.** Загружают данные вручную: заводят три состояния и `useEffect`.

```tsx
import { useEffect, useState } from 'react';
import axios from 'axios';

interface Post {
  id: number;
  title: string;
}

export function PostsList() {
  const [posts, setPosts] = useState<Post[]>([]);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    let cancelled = false;
    setIsLoading(true);

    axios
      .get<Post[]>('https://jsonplaceholder.typicode.com/posts')
      .then((response) => {
        if (!cancelled) setPosts(response.data);
      })
      .catch((err: Error) => {
        if (!cancelled) setError(err.message);
      })
      .finally(() => {
        if (!cancelled) setIsLoading(false);
      });

    return () => {
      // Защита от гонки запросов и обновления размонтированного компонента.
      cancelled = true;
    };
  }, []);

  if (isLoading) return <p>Загрузка…</p>;
  if (error) return <p role="alert">Ошибка: {error}</p>;

  return (
    <ul>
      {posts.map((post) => (
        <li key={post.id}>{post.title}</li>
      ))}
    </ul>
  );
}
```

Такой код работает, но повторяет одну и ту же логику в каждом компоненте и не отвечает на важные вопросы:
*   что показать, если те же данные нужны на другой странице (загружать заново?);
*   как понять, что данные устарели и их пора обновить;
*   как обновить список после добавления или удаления записи;
*   как отменить устаревший запрос, если пользователь быстро меняет фильтр.

**Кэш** — это временное хранилище уже загруженных данных. Если данные лежат в кэше и ещё «свежие», повторный запрос не нужен. **Синхронизация** — это механизм, который решает, когда кэш нужно обновить: по истечении времени, при возврате во вкладку, после изменения данных.

Именно этим и занимается **TanStack Query** (ранее React Query) — библиотека для работы с серверным состоянием в React. Она берёт на себя загрузку, кэширование, обновление и синхронизацию данных, а разработчик описывает только то, *что* загружать.

#### **2. Установка и настройка TanStack Query**

Устанавливаем два пакета: саму библиотеку и панель разработчика.

```bash
npm install @tanstack/react-query
npm install -D @tanstack/react-query-devtools
```

**`QueryClient`** — это объект, который хранит кэш всех запросов и управляет им. Создаётся один раз на всё приложение. **`QueryClientProvider`** делает клиент доступным любому компоненту ниже по дереву.

Обновим точку входа `src/main.tsx`:

```tsx
import { StrictMode } from 'react';
import { createRoot } from 'react-dom/client';
import { QueryClient, QueryClientProvider } from '@tanstack/react-query';
import { ReactQueryDevtools } from '@tanstack/react-query-devtools';
import './index.css';
import App from './App.tsx';

// Один клиент на всё приложение: он хранит кэш запросов.
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      // Данные считаются свежими 60 секунд: повторный запрос не выполняется.
      staleTime: 60_000,
      // Данные без «наблюдателей» удаляются из кэша через 5 минут.
      gcTime: 5 * 60_000,
      // Не перезапрашивать данные при возврате фокуса в окно.
      refetchOnWindowFocus: false,
    },
  },
});

createRoot(document.getElementById('root')!).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <App />
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  </StrictMode>,
);
```

Два ключевых параметра, которые чаще всего настраивают:

*   **`staleTime`** — сколько времени данные считаются «свежими». Пока данные свежие, библиотека отдаёт их из кэша и не делает новый запрос.
*   **`gcTime`** — сколько времени «несвежие» данные хранятся в памяти после того, как на них больше никто не подписан (параметр переименован из `cacheTime` в версии 5).

#### **3. `useQuery`: чтение данных и кэширование**

Сначала вынесем работу с сетью в отдельный модуль. Это хорошая практика: компонент не знает, откуда берутся данные.

```ts
// src/api/posts.ts
import axios from 'axios';

export interface Post {
  id: number;
  userId: number;
  title: string;
  body: string;
}

export async function fetchPosts(): Promise<Post[]> {
  const { data } = await axios.get<Post[]>(
    'https://jsonplaceholder.typicode.com/posts',
    { params: { _limit: 10 } },
  );
  return data;
}
```

Теперь загрузим данные с помощью `useQuery`:

```tsx
// src/components/PostsList.tsx
import { useQuery } from '@tanstack/react-query';
import { fetchPosts } from '../api/posts';
import type { Post } from '../api/posts';

export function PostsList() {
  const {
    data: posts,
    isPending,
    isError,
    error,
    isSuccess,
    isFetching,
    refetch,
  } = useQuery<Post[], Error>({
    queryKey: ['posts'],
    queryFn: fetchPosts,
    staleTime: 60_000,
  });

  if (isPending) {
    return <p>Загрузка записей…</p>;
  }

  if (isError) {
    return (
      <div role="alert">
        <p>Не удалось загрузить записи: {error.message}</p>
        <button type="button" onClick={() => void refetch()}>
          Повторить
        </button>
      </div>
    );
  }

  return (
    <section>
      <h2>Записи</h2>
      {isFetching && <p>Обновление…</p>}
      {isSuccess && (
        <ul>
          {posts.map((post) => (
            <li key={post.id}>{post.title}</li>
          ))}
        </ul>
      )}
    </section>
  );
}
```

Разберём параметры `useQuery`:

**`queryKey` — ключ кэша.** Это массив, по которому библиотека различает запросы. `['posts']` и `['posts', 2]` — разные записи кэша. Если ключ включает переменную (номер страницы, поисковую строку), при её изменении выполняется новый запрос:

```tsx
useQuery({
  queryKey: ['posts', page],
  queryFn: () => fetchPostsPage(page),
});
```

**`queryFn` — функция загрузки.** Должна возвращать промис. Именно её результат попадает в `data`.

**Типизация.** Если `queryFn` возвращает `Promise<Post[]>`, TypeScript сам выведет тип `data`. Обобщение `useQuery<Post[], Error>` задаёт типы ответа и ошибки явно — полезно, когда функция объявлена отдельно и хочется зафиксировать контракт.

**Статусы запроса:**

| Свойство | Что означает |
|---|---|
| `isPending` | Данных ещё нет, запрос только начался |
| `isLoading` | `isPending && isFetching` — идёт самая первая загрузка |
| `isError` | Запрос завершился ошибкой |
| `isSuccess` | Данные успешно получены |
| `isFetching` | Идёт любой запрос, включая фоновое обновление |

Важно различать `isPending` и `isFetching`: при повторном запросе данные уже есть, поэтому `isPending` равен `false`, а `isFetching` — `true`. Это позволяет показывать старые данные, не «мигая» индикатором загрузки на весь экран.

**Дополнительные параметры:**

*   **`enabled`** — включает или выключает запрос. Удобно для поиска: пока строка пустая, запрос не нужен.

    ```tsx
    useQuery({
      queryKey: ['search', term],
      queryFn: () => searchPosts(term),
      enabled: term.length > 0,
    });
    ```

*   **`placeholderData`** — временные данные, пока настоящие ещё не пришли. Например, `placeholderData: []` отдаст пустой массив, и компоненту не придётся проверять `undefined`.

*   **`refetchOnWindowFocus`** — перезапрашивать ли данные при возврате во вкладку. По умолчанию `true`; для «спокойных» данных часто отключают.

*   **`select`** — преобразование данных прямо в кэше запроса. Полезно, если компоненту нужна лишь часть ответа:

    ```tsx
    const { data: titles } = useQuery({
      queryKey: ['posts'],
      queryFn: fetchPosts,
      select: (posts) => posts.map((post) => post.title),
    });
    ```

    `select` не изменяет данные в кэше — он возвращает преобразованное значение в компонент.

#### **4. `useMutation`: изменение данных**

Для создания, обновления и удаления используется отдельный хук — `useMutation`. В отличие от `useQuery`, он не запускается автоматически: мутацию нужно вызвать вручную через `mutate`.

Добавим функции изменения данных в API-модуль:

```ts
// src/api/posts.ts (продолжение)
export type NewPost = Omit<Post, 'id'>;

export async function createPost(payload: NewPost): Promise<Post> {
  const { data } = await axios.post<Post>(
    'https://jsonplaceholder.typicode.com/posts',
    payload,
  );
  return data;
}

export async function deletePost(id: number): Promise<void> {
  await axios.delete(`https://jsonplaceholder.typicode.com/posts/${id}`);
}
```

Теперь компонент формы добавления:

```tsx
// src/components/CreatePostForm.tsx
import { useState } from 'react';
import type { FormEvent } from 'react';
import { useMutation, useQueryClient } from '@tanstack/react-query';
import { createPost } from '../api/posts';
import type { NewPost } from '../api/posts';

export function CreatePostForm() {
  const [title, setTitle] = useState('');
  const [body, setBody] = useState('');
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (payload: NewPost) => createPost(payload),
    onSuccess: () => {
      setTitle('');
      setBody('');
      // Сообщаем кэшу, что данные по ключу ['posts'] устарели.
      void queryClient.invalidateQueries({ queryKey: ['posts'] });
    },
    onError: (error: Error) => {
      console.error('Не удалось создать запись:', error.message);
    },
  });

  function handleSubmit(event: FormEvent<HTMLFormElement>) {
    event.preventDefault();
    mutation.mutate({ userId: 1, title, body });
  }

  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="title">Заголовок</label>
      <input
        id="title"
        value={title}
        onChange={(event) => setTitle(event.target.value)}
        required
      />

      <label htmlFor="body">Текст</label>
      <textarea
        id="body"
        value={body}
        onChange={(event) => setBody(event.target.value)}
        required
      />

      <button type="submit" disabled={mutation.isPending}>
        {mutation.isPending ? 'Сохранение…' : 'Добавить запись'}
      </button>

      {mutation.isError && (
        <p role="alert">Ошибка: {mutation.error.message}</p>
      )}
    </form>
  );
}
```

Ключевые моменты:

*   **`mutationFn`** — функция, которая выполняет запрос и принимает аргумент из `mutate(...)`.
*   **`onSuccess`** — вызывается после успеха. Здесь удобно очищать форму и обновлять список.
*   **`onError`** — обработка ошибки.
*   **`useQueryClient()`** — доступ к клиенту кэша из компонента.
*   **`queryClient.invalidateQueries({ queryKey: ['posts'] })`** — самый важный приём синхронизации: данные по этому ключу помечаются устаревшими, и все активные запросы с ключом `['posts']` перезагружаются автоматически. После добавления записи список на экране обновится сам.

**Оптимистичное обновление (кратко).** Иногда не хочется ждать ответа сервера, и интерфейс обновляют заранее, «на веру». Для этого в `useMutation` используют `onMutate` (запомнить предыдущее состояние и обновить кэш вручную), `onError` (откатить изменения, если запрос упал) и `onSettled` (в любом случае перепроверить данные). Полный разбор таких сценариев выходит за рамки лекции — важно знать, что механизм есть и строится он вокруг `queryClient.setQueryData` и `getQueryData`.

#### **5. Практические приёмы и инструменты**

**Пагинация.** При переключении страницы не хочется, чтобы список «прыгал» на индикатор загрузки. Для этого в версии 5 есть хелпер `keepPreviousData`:

```tsx
import { useState } from 'react';
import { keepPreviousData, useQuery } from '@tanstack/react-query';

interface PagedPostsProps {
  fetchPage: (page: number) => Promise<Post[]>;
}

export function PagedPosts({ fetchPage }: PagedPostsProps) {
  const [page, setPage] = useState(1);

  const { data: posts, isPlaceholderData } = useQuery({
    queryKey: ['posts', page],
    queryFn: () => fetchPage(page),
    // Пока грузится новая страница, показываем данные предыдущей.
    placeholderData: keepPreviousData,
  });

  return (
    <div>
      <ul>
        {(posts ?? []).map((post) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>

      <button
        type="button"
        onClick={() => setPage((current) => Math.max(current - 1, 1))}
        disabled={page === 1}
      >
        Назад
      </button>

      <button
        type="button"
        onClick={() => setPage((current) => current + 1)}
        disabled={isPlaceholderData}
      >
        Вперёд
      </button>
    </div>
  );
}
```

Пока для новой страницы грузятся данные, `isPlaceholderData` равен `true`, а на экране остаются данные предыдущей страницы.

**`useQueryClient`.** Хук даёт доступ к кэшу из любого компонента. Кроме `invalidateQueries`, часто используют:
*   `queryClient.setQueryData(['posts'], newData)` — руками положить данные в кэш;
*   `queryClient.getQueryData(['posts'])` — прочитать данные из кэша;
*   `queryClient.removeQueries({ queryKey: ['posts'] })` — удалить запись кэша.

**Devtools.** Компонент `ReactQueryDevtools` показывает плавающую панель со всеми запросами: их ключи, статусы, время последнего обновления, содержимое кэша. Это удобно во время разработки: сразу видно, почему данные взялись из кэша или почему пошёл повторный запрос. В production-сборке панель не отображается.

**Сравнение подходов.**

| Задача | `useEffect` + `useState` | TanStack Query |
|---|---|---|
| Загрузка данных | Пишем в каждом компоненте | Один вызов `useQuery` |
| Состояния загрузки/ошибки | Заводим вручную | Готовые `isPending`, `isError` |
| Кэширование | Нет или пишем сами | Встроено |
| Повторные запросы | Нужно контролировать | Управляются `staleTime`/`gcTime` |
| Обновление после мутации | Вручную | `invalidateQueries` |
| Защита от гонок запросов | Вручную (`cancelled`) | Автоматически |
| Отмена устаревших запросов | Вручную | Автоматически |
| Devtools | Нет | Есть |

### **Резюме**

*   **Клиентское состояние** (тема, модальные окна, формы) хранится в приложении, **серверное** (списки, профили, каталоги) — на сервере и требует кэша.
*   **TanStack Query** — библиотека для серверного состояния: загрузка, кэширование, синхронизация и обновление «из коробки».
*   **`QueryClient`** создаётся один раз, **`QueryClientProvider`** передаёт его вниз по дереву компонентов.
*   **`useQuery`** принимает `queryKey` и `queryFn`, возвращает `data` и набор статусов; настройками `staleTime`, `gcTime`, `enabled`, `placeholderData`, `select` управляют поведением запроса.
*   **`isPending`** — данных ещё нет, **`isFetching`** — идёт любой запрос; их полезно различать, чтобы не «мигать» индикатором.
*   **`useMutation`** выполняет изменения; после успеха вызывают **`queryClient.invalidateQueries`**, чтобы кэш и интерфейс синхронизировались.
*   **`placeholderData: keepPreviousData`** сохраняет данные предыдущей страницы при пагинации, **Devtools** помогает видеть состояние кэша в разработке.
