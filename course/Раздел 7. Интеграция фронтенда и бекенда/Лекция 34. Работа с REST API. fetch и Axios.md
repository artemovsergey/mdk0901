#### **1. REST и HTTP: базовые понятия**

**REST (Representational State Transfer)** — архитектурный стиль, в котором данные представляются в виде **ресурсов**, а действия над ними выполняются стандартными методами HTTP. В REST-API каждый ресурс имеет адрес (URL), а метод HTTP говорит, что именно нужно сделать.

| Метод | Назначение | Пример |
|---|---|---|
| `GET` | Получить данные | `GET /posts` — список записей |
| `POST` | Создать ресурс | `POST /posts` — новая запись |
| `PUT` | Полностью заменить ресурс | `PUT /posts/1` |
| `PATCH` | Частично обновить ресурс | `PATCH /posts/1` |
| `DELETE` | Удалить ресурс | `DELETE /posts/1` |

**Статус ответа** сообщает, чем закончился запрос. Основные группы:

| Код | Значение |
|---|---|
| `200 OK` | Успех |
| `201 Created` | Ресурс создан (часто ответ на `POST`) |
| `204 No Content` | Успех без тела ответа (частый ответ на `DELETE`) |
| `400 Bad Request` | Некорректные данные запроса |
| `401 Unauthorized` | Требуется авторизация |
| `403 Forbidden` | Доступ запрещён |
| `404 Not Found` | Ресурс не найден |
| `500 Internal Server Error` | Ошибка на сервере |

**Заголовки** передают служебную информацию. Для работы с JSON важны два:
*   `Content-Type: application/json` — в запросе говорит серверу, что тело в формате JSON;
*   `Accept: application/json` — в запросе сообщает, какой формат ответа ожидает клиент.

**JSON** — текстовый формат обмена данными. Тело запроса и ответа — это, как правило, JSON-строка, которую нужно превратить в объект JavaScript (при чтении) или наоборот (при отправке).

#### **2. Запросы через `fetch`**

`fetch` — встроенная в браузер функция для HTTP-запросов. Она возвращает промис с объектом `Response`.

**GET-запрос.** Простейший случай: получить список данных.

```ts
interface Post {
  id: number;
  userId: number;
  title: string;
  body: string;
}

const API_URL = 'https://jsonplaceholder.typicode.com';

async function fetchPosts(): Promise<Post[]> {
  const response = await fetch(`${API_URL}/posts?_limit=10`);

  // ВАЖНО: fetch не бросает ошибку на статусы 4xx и 5xx!
  if (!response.ok) {
    throw new Error(`Ошибка запроса: ${response.status}`);
  }

  // .json() тоже возвращает промис, поэтому нужен await.
  const posts: Post[] = await response.json();
  return posts;
}
```

Обратите внимание на проверку `response.ok`: она равна `true` для статусов 200–299. Если сервер вернул `404` или `500`, промис всё равно **успешно** завершится, и без проверки `response.ok` ошибка не будет замечена.

**POST-запрос.** Отправляем данные на сервер. Тело нужно сериализовать в строку через `JSON.stringify`, а заголовок `Content-Type` указать явно.

```ts
type NewPost = Omit<Post, 'id'>;

async function createPost(payload: NewPost): Promise<Post> {
  const response = await fetch(`${API_URL}/posts`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      Accept: 'application/json',
    },
    body: JSON.stringify(payload),
  });

  if (!response.ok) {
    throw new Error(`Не удалось создать запись: ${response.status}`);
  }

  const created: Post = await response.json();
  return created;
}
```

**PUT и PATCH.** Разница в объёме передаваемых данных: `PUT` заменяет ресурс целиком, `PATCH` — только указанные поля.

```ts
async function updatePost(id: number, payload: NewPost): Promise<Post> {
  const response = await fetch(`${API_URL}/posts/${id}`, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ ...payload, id }),
  });

  if (!response.ok) {
    throw new Error(`Не удалось обновить запись: ${response.status}`);
  }

  return response.json() as Promise<Post>;
}

async function patchPost(id: number, patch: Partial<NewPost>): Promise<Post> {
  const response = await fetch(`${API_URL}/posts/${id}`, {
    method: 'PATCH',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(patch),
  });

  if (!response.ok) {
    throw new Error(`Не удалось обновить запись: ${response.status}`);
  }

  return response.json() as Promise<Post>;
}
```

**DELETE.** Часто сервер отвечает статусом `204` без тела, поэтому `response.json()` вызывать не нужно.

```ts
async function deletePost(id: number): Promise<void> {
  const response = await fetch(`${API_URL}/posts/${id}`, {
    method: 'DELETE',
  });

  if (!response.ok) {
    throw new Error(`Не удалось удалить запись: ${response.status}`);
  }
}
```

#### **3. Ошибки, отмена и таймаут**

У `fetch` есть неприятная особенность: у него **нет таймаута** и он «висит», пока сервер не ответит или соединение не оборвётся. Если компонент размонтирован или фильтр поиска изменился, старый запрос нужно отменить — для этого служит `AbortController`.

```ts
async function fetchWithTimeout(
  url: string,
  timeoutMs = 8000,
  externalSignal?: AbortSignal,
): Promise<Response> {
  const controller = new AbortController();

  // Связываем внешний сигнал (например, из UI) с нашим таймаутом.
  const onAbort = () => controller.abort();
  externalSignal?.addEventListener('abort', onAbort);

  const timer = setTimeout(() => controller.abort(), timeoutMs);

  try {
    return await fetch(url, { signal: controller.signal });
  } finally {
    clearTimeout(timer);
    externalSignal?.removeEventListener('abort', onAbort);
  }
}
```

Использование в React-компоненте с `useEffect`: при размонтировании вызов очистки отменяет запрос.

```tsx
import { useEffect, useState } from 'react';
import type { Post } from '../api/posts';

export function PostDetails({ id }: { id: number }) {
  const [post, setPost] = useState<Post | null>(null);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    const controller = new AbortController();

    fetchWithTimeout(`https://jsonplaceholder.typicode.com/posts/${id}`, 8000, controller.signal)
      .then(async (response) => {
        if (!response.ok) {
          throw new Error(`Ошибка запроса: ${response.status}`);
        }
        return (await response.json()) as Post;
      })
      .then(setPost)
      .catch((err: unknown) => {
        // Отменённый запрос — не ошибка: просто игнорируем.
        if (err instanceof DOMException && err.name === 'AbortError') return;
        setError(err instanceof Error ? err.message : 'Неизвестная ошибка');
      });

    return () => controller.abort();
  }, [id]);

  if (error) return <p role="alert">{error}</p>;
  if (!post) return <p>Загрузка…</p>;

  return (
    <article>
      <h2>{post.title}</h2>
      <p>{post.body}</p>
    </article>
  );
}
```

Классификация ошибок при работе с сетью:
*   **Сетевые** — сервер недоступен, нет интернета, запрос отменён (`AbortError`).
*   **Клиентские** — статусы `4xx`: неправильный адрес, нет прав, неверные данные.
*   **Серверные** — статусы `5xx`: ошибка на стороне сервера.

#### **4. Инкапсуляция запросов**

Держать вызовы `fetch` прямо в компонентах плохо: логика дублируется, а компонент знает слишком много о сети. Лучше вынести всё в отдельный модуль.

```ts
// src/api/http.ts
const API_BASE_URL =
  import.meta.env.VITE_API_URL ?? 'https://jsonplaceholder.typicode.com';

/** Собственная ошибка с кодом статуса — удобно различать случаи в UI. */
export class HttpError extends Error {
  constructor(
    public readonly status: number,
    message: string,
  ) {
    super(message);
    this.name = 'HttpError';
  }
}

async function request<T>(
  path: string,
  init: RequestInit = {},
): Promise<T> {
  const response = await fetch(`${API_BASE_URL}${path}`, {
    ...init,
    headers: {
      'Content-Type': 'application/json',
      Accept: 'application/json',
      ...init.headers,
    },
  });

  if (!response.ok) {
    throw new HttpError(response.status, `Ошибка запроса: ${response.status}`);
  }

  // 204 No Content — тела нет.
  if (response.status === 204) {
    return undefined as T;
  }

  return (await response.json()) as T;
}

export function httpGet<T>(path: string, init?: RequestInit): Promise<T> {
  return request<T>(path, { ...init, method: 'GET' });
}

export function httpPost<T>(
  path: string,
  body: unknown,
  init?: RequestInit,
): Promise<T> {
  return request<T>(path, { ...init, method: 'POST', body: JSON.stringify(body) });
}

export function httpDelete<T = void>(path: string, init?: RequestInit): Promise<T> {
  return request<T>(path, { ...init, method: 'DELETE' });
}
```

Теперь работа с данными в модуле `src/api/posts.ts` выглядит коротко и типизированно:

```ts
// src/api/posts.ts
import { httpDelete, httpGet, httpPost } from './http';

export interface Post {
  id: number;
  userId: number;
  title: string;
  body: string;
}

export type NewPost = Omit<Post, 'id'>;

export function fetchPosts(): Promise<Post[]> {
  return httpGet<Post[]>('/posts?_limit=10');
}

export function createPost(payload: NewPost): Promise<Post> {
  return httpPost<Post>('/posts', payload);
}

export function deletePost(id: number): Promise<void> {
  return httpDelete(`/posts/${id}`);
}
```

#### **5. Axios: удобная альтернатива**

**Axios** — популярная библиотека для HTTP-запросов. Она автоматически преобразует JSON в обе стороны, умеет таймауты, перехватчики (интерцепторы Axios) и работает не только в браузере, но и в Node.js.

Установка:

```bash
npm install axios
```

Создание настроенного экземпляра. Вместо того чтобы каждый раз писать полный адрес и заголовки, задаём их один раз в `axios.create`:

```ts
// src/api/client.ts
import axios from 'axios';

export const api = axios.create({
  baseURL: import.meta.env.VITE_API_URL ?? 'https://jsonplaceholder.typicode.com',
  headers: {
    'Content-Type': 'application/json',
    Accept: 'application/json',
  },
  timeout: 8000,
});
```

Типизированные запросы. Axios указывается тип ожидаемых данных через обобщение, а `data` возвращается уже разобранным объектом:

```ts
// src/api/posts.ts
import { api } from './client';

export interface Post {
  id: number;
  userId: number;
  title: string;
  body: string;
}

export type NewPost = Omit<Post, 'id'>;

export async function fetchPosts(): Promise<Post[]> {
  const { data } = await api.get<Post[]>('/posts', {
    // params собирает строку запроса автоматически: /posts?_limit=10
    params: { _limit: 10 },
  });
  return data;
}

export async function fetchPostById(id: number): Promise<Post> {
  const { data } = await api.get<Post>(`/posts/${id}`);
  return data;
}

export async function createPost(payload: NewPost): Promise<Post> {
  // Объект передаётся в data и сериализуется автоматически.
  const { data } = await api.post<Post>('/posts', payload);
  return data;
}

export async function updatePost(id: number, payload: NewPost): Promise<Post> {
  const { data } = await api.put<Post>(`/posts/${id}`, payload);
  return data;
}

export async function deletePost(id: number): Promise<void> {
  await api.delete(`/posts/${id}`);
}
```

**Обработка ошибок.** Axios **сам** бросает ошибку на статусы `4xx` и `5xx` (в отличие от `fetch`). Для разбора ошибки служит тип `AxiosError` и функция-проверка `axios.isAxiosError`.

```ts
// src/api/errors.ts
import axios from 'axios';

/** Превращает любую ошибку в понятное пользователю сообщение. */
export function getErrorMessage(error: unknown): string {
  if (axios.isAxiosError<{ message?: string }>(error)) {
    // Сервер не ответил: нет сети, таймаут, запрос отменён.
    if (!error.response) {
      return 'Нет соединения с сервером. Проверьте подключение к сети.';
    }

    const status = error.response.status;
    switch (status) {
      case 400:
        return 'Некорректные данные запроса.';
      case 401:
        return 'Требуется авторизация.';
      case 403:
        return 'Доступ запрещён.';
      case 404:
        return 'Ресурс не найден.';
      case 500:
        return 'Ошибка на сервере. Попробуйте позже.';
      default:
        return error.response.data?.message ?? `Ошибка запроса: ${status}`;
    }
  }

  if (error instanceof Error) {
    return error.message;
  }

  return 'Неизвестная ошибка.';
}
```

Использование в компоненте: ошибка ловится в обработчике и показывается пользователю, а не «проглатывается».

```tsx
import { useState } from 'react';
import { deletePost } from '../api/posts';
import { getErrorMessage } from '../api/errors';

export function DeletePostButton({ id }: { id: number }) {
  const [error, setError] = useState<string | null>(null);

  async function handleDelete() {
    setError(null);
    try {
      await deletePost(id);
    } catch (err: unknown) {
      setError(getErrorMessage(err));
    }
  }

  return (
    <div>
      <button type="button" onClick={() => void handleDelete()}>
        Удалить
      </button>
      {error && <p role="alert">{error}</p>}
    </div>
  );
}
```

**Сравнение `fetch` и Axios.**

| Критерий | `fetch` | Axios |
|---|---|---|
| Что это | Встроено в браузер | Внешняя библиотека |
| Установка | Не нужна | `npm install axios` |
| Разбор JSON | Вручную через `response.json()` | Автоматически |
| Сериализация тела | `JSON.stringify` вручную | Автоматически |
| Ошибка на 4xx/5xx | Не бросает, нужна проверка `response.ok` | Бросает `AxiosError` |
| Таймаут | Нет, нужен `AbortController` | Параметр `timeout` |
| Query-параметры | Собирать строку вручную | Объект `params` |
| Интерцепторы Axios | Нет | Есть |
| Размер бандла | 0 КБ | Дополнительный вес |
| Работа в Node.js | Только с ограничениями | Полноценно |

**Рекомендация.** Для небольших проектов и пары запросов достаточно встроенного `fetch` — он не добавляет зависимостей. Если запросов много, нужны общие заголовки, таймауты, централизованная обработка ошибок и интерцепторы Axios — удобнее Axios. Главное — в обоих случаях прячьте сетевую логику в отдельный модуль, а компоненты оставляйте «чистыми».

Дальше в курсе: **интерцепторы Axios** (добавление токена авторизации, общий обработчик ошибок) разбираются в практической работе 38, а управление загрузкой, кэшем и синхронизацией данных — в лекции 33 и практической работе 35 с TanStack Query.

### **Резюме**

*   **REST** описывает данные как ресурсы, а действие задаётся методом HTTP: `GET`, `POST`, `PUT`, `PATCH`, `DELETE`.
*   **Статусы ответа** делятся на успешные (`2xx`), клиентские ошибки (`4xx`) и серверные (`5xx`); их нужно проверять.
*   **`fetch`** не выбрасывает ошибку на статусы `4xx`/`5xx` — обязательна проверка `response.ok`.
*   Тело запроса в `fetch` сериализуется через `JSON.stringify`, заголовок `Content-Type: application/json` задаётся вручную.
*   **`AbortController`** отменяет запрос и реализует таймаут; отменённый запрос — не ошибка.
*   Сетевую логику выносят в модуль (`src/api/http.ts`), а компоненты используют типизированные функции.
*   **Axios** автоматически работает с JSON, поддерживает `timeout`, `params`, `baseURL` и бросает `AxiosError` на ошибочные статусы.
*   Ошибки должны быть **классифицированы** и показаны пользователю понятным сообщением.
