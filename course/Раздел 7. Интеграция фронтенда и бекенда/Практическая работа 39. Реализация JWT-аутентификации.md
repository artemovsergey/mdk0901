# Практическая работа 39. Реализация JWT-аутентификации

### **Тема:** Аутентификация и авторизация в React-приложении на основе JWT-токенов

### **Цель:**
Освоить полный цикл аутентификации в SPA на React: разобрать структуру JWT, реализовать вход и регистрацию, сохранить access-токен, подставлять его в запросы через интерцептор Axios, обрабатывать ответ 401, защищать маршруты с помощью `ProtectedRoute` и отображать данные текущего пользователя.

### **Теоретическая часть:**

**Зачем нужна аутентификация.** Сервер должен понимать, кто выполняет запрос. Пароль нельзя передавать при каждом обращении, поэтому после успешного входа сервер выдаёт клиенту **токен** — короткую строку, которая подтверждает личность пользователя. Дальше клиент отправляет этот токен вместе с запросами к защищённым ресурсам.

**Что такое JWT.** JWT (JSON Web Token) — это компактный текстовый токен из трёх частей, разделённых точками:

```
header.payload.signature
```

- **Header** — заголовок: алгоритм подписи и тип токена (`HS256`, `RS256`), закодирован в Base64URL.
- **Payload** — полезная нагрузка: данные о пользователе и служебные поля (`sub` — идентификатор пользователя, `email`, `name`, `exp` — время истечения, `iat` — время выдачи).
- **Signature** — подпись: результат подписи первых двух частей секретным ключом сервера. Именно она не даёт подделать токен.

**Важно:** payload не зашифрован, а только закодирован. Любой может прочитать его содержимое через `atob`, поэтому в токене не хранят пароли и другие секреты.

**Проверка на клиенте.** Расшифровать подпись клиент не может (секретного ключа у него нет), но может прочитать payload и проверить срок жизни токена:

```ts
interface JwtPayload {
  sub: string;
  exp: number;
}

const [, payload] = token.split('.');
const data = JSON.parse(atob(payload)) as JwtPayload;
const isExpired = data.exp * 1000 <= Date.now();
```

**Flow аутентификации:**

1. Пользователь вводит email и пароль в форму.
2. Клиент отправляет их на сервер (`POST /auth/login`).
3. Сервер проверяет данные и возвращает `accessToken` и объект пользователя.
4. Клиент сохраняет токен и данные пользователя.
5. Каждый защищённый запрос уходит с заголовком `Authorization: Bearer <accessToken>`.
6. Сервер проверяет подпись и срок действия токена и отвечает данными.
7. При истечении токена сервер отвечает `401 Unauthorized`, и клиент отправляет пользователя на страницу входа.

**Где хранить access-токен.** Есть несколько вариантов:

- **localStorage** — просто и удобно: токен сохраняется между перезагрузками и вкладками. Главный недостаток — доступность из JavaScript: при XSS-атаке вредоносный скрипт сможет прочитать токен. В учебном проекте этот способ допустим, но в реальном приложении его нужно осознанно взвешивать.
- **sessionStorage** — то же самое, но данные живут до закрытия вкладки.
- **HttpOnly cookie** — токен недоступен из JavaScript, что защищает от XSS, но требует настройки CORS, `credentials` и защиты от CSRF.
- **В памяти (переменная в модуле/состоянии)** — максимально безопасно, но токен теряется при перезагрузке страницы.

> ⚠️ **Предупреждение о безопасности.** Хранение токена в `localStorage` делает его уязвимым к XSS: любой внедрённый скрипт может забрать токен. Снижайте риск: экранируйте пользовательские данные, подключайте только доверенные библиотеки, задавайте короткий срок жизни access-токена и используйте refresh-токены/HttpOnly cookies там, где это возможно. Никогда не храните в токене пароли и персональные секреты.

**React Context для состояния авторизации.** Данные о пользователе нужны сразу в нескольких местах: в шапке, на странице профиля, в защищённых маршрутах. Передавать их через props на каждом уровне неудобно, поэтому используют Context:

1. `createContext<T | null>(null)` — создаёт контекст со значением по умолчанию `null`;
2. компонент-провайдер `<AuthContext.Provider value={...}>` — предоставляет значение потомкам;
3. хук доступа `useAuth()` на базе `useContext` — читает значение и выбрасывает ошибку, если провайдер забыли подключить.

```tsx
const AuthContext = createContext<AuthContextValue | null>(null);

export function useAuth(): AuthContextValue {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth должен использоваться внутри AuthProvider');
  }
  return context;
}
```

**Инстанс Axios и интерцепторы.** Чтобы не добавлять заголовок `Authorization` в каждый запрос вручную, создают один экземпляр Axios и навешивают на него интерцепторы:

- **интерцептор запроса** — берёт токен из хранилища и добавляет `Authorization: Bearer <token>`;
- **интерцептор ответа** — ловит ошибки; при `401` очищает токен и перенаправляет на страницу входа.

```ts
http.interceptors.request.use((config) => {
  const token = getAccessToken();
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});
```

**Формы входа и регистрации.** Значения полей удобно держать в `react-hook-form`, а правила — описывать схемой `zod`. Схема регистрации проверяет имя, email, сложность пароля и совпадение пароля с подтверждением (через `.refine`). Ошибки выводятся под полем и связываются с ним через `aria-invalid` и `aria-describedby`.

**Защищённые маршруты.** Компонент-обёртка `ProtectedRoute` проверяет авторизацию. Если пользователь не вошёл, он возвращает `<Navigate to="/login" replace state={{ from: location.pathname }} />` — так запоминается исходный адрес, и после входа пользователь вернётся туда, откуда его перенаправили.

**2. src/api/http.ts — экземпляр Axios и интерцепторы:**

```ts
import axios from 'axios';
import type { AxiosError, InternalAxiosRequestConfig } from 'axios';

const ACCESS_TOKEN_KEY = 'access_token';

/** Расширяем конфигурацию запроса: признак публичного запроса. */
declare module 'axios' {
  export interface AxiosRequestConfig {
    // Публичные запросы (вход, регистрация) уходят без заголовка Authorization.
    skipAuth?: boolean;
  }
}

export function getAccessToken(): string | null {
  return localStorage.getItem(ACCESS_TOKEN_KEY);
}

export function setAccessToken(token: string): void {
  localStorage.setItem(ACCESS_TOKEN_KEY, token);
}

export function clearAccessToken(): void {
  localStorage.removeItem(ACCESS_TOKEN_KEY);
}

// Единый экземпляр Axios: базовый URL берём из переменной окружения.
export const http = axios.create({
  baseURL: import.meta.env.VITE_API_URL ?? 'http://localhost:3000/api',
  headers: { 'Content-Type': 'application/json' },
  timeout: 10_000,
});

// --- Интерцептор запроса: подставляем access-токен ---
http.interceptors.request.use((config: InternalAxiosRequestConfig) => {
  if (!config.skipAuth) {
    const token = getAccessToken();
    if (token) {
      config.headers.Authorization = `Bearer ${token}`;
    }
  }
  return config;
});

/** Переход на страницу входа: интерцептор работает вне React. */
function redirectToLogin(): void {
  if (window.location.pathname !== '/login') {
    window.location.replace('/login');
  }
}

// --- Интерцептор ответа: обрабатываем 401 и приводим ошибки к тексту ---
http.interceptors.response.use(
  (response) => response,
  (error: AxiosError<{ message?: string }>) => {
    // 401 на защищённом запросе: токен недействителен — выходим и уходим на вход.
    if (error.response?.status === 401 && !error.config?.skipAuth) {
      clearAccessToken();
      redirectToLogin();
      return Promise.reject(new Error('Сессия истекла. Войдите заново.'));
    }

    // Публичные запросы (неверный пароль) показывают сообщение сервера.
    const message =
      error.response?.data?.message ??
      (error.response ? `Ошибка ${error.response.status}` : 'Нет соединения с сервером');

    return Promise.reject(new Error(message));
  },
);
```

**3. src/utils/jwt.ts — чтение payload и проверка срока действия:**

```ts
/** Полезная нагрузка JWT-токена. */
export interface JwtPayload {
  sub: string;
  email: string;
  name: string;
  exp: number;
}

/**
 * Декодирует payload токена без проверки подписи.
 * Подпись проверяет только сервер, у клиента секретного ключа нет.
 */
export function decodeToken(token: string): JwtPayload | null {
  try {
    const [, payload] = token.split('.');
    return JSON.parse(atob(payload)) as JwtPayload;
  } catch {
    return null;
  }
}

/** Проверяет, не истёк ли токен (exp указывается в секундах). */
export function isTokenExpired(token: string): boolean {
  const payload = decodeToken(token);
  if (!payload) {
    return true;
  }
  return payload.exp * 1000 <= Date.now();
}
```

**4. src/api/auth.ts — сервисные функции:**

```ts
import { clearAccessToken, http, setAccessToken } from './http';

export interface User {
  id: number;
  name: string;
  email: string;
}

export interface AuthResponse {
  accessToken: string;
  user: User;
}

export interface LoginData {
  email: string;
  password: string;
}

export interface RegisterData {
  name: string;
  email: string;
  password: string;
  passwordConfirmation: string;
}

/** Вход: получаем токен и данные пользователя. */
export async function login(data: LoginData): Promise<AuthResponse> {
  const { data: response } = await http.post<AuthResponse>('/auth/login', data, {
    skipAuth: true,
  });
  setAccessToken(response.accessToken);
  return response;
}

/** Регистрация: сервер сразу выдаёт токен. */
export async function register(data: RegisterData): Promise<AuthResponse> {
  const { data: response } = await http.post<AuthResponse>('/auth/register', data, {
    skipAuth: true,
  });
  setAccessToken(response.accessToken);
  return response;
}

/** Выход: сообщаем серверу и в любом случае очищаем токен локально. */
export async function logout(): Promise<void> {
  try {
    await http.post('/auth/logout');
  } catch {
    // Даже если сервер недоступен, пользователь должен выйти локально.
  } finally {
    clearAccessToken();
  }
}

/** Текущий пользователь по сохранённому токену. */
export async function fetchMe(): Promise<User> {
  const { data } = await http.get<User>('/auth/me');
  return data;
}
```

```ts
import { z } from 'zod';

export const loginSchema = z.object({
  email: z.email('Введите корректный email'),
  password: z.string().min(6, 'Пароль должен содержать минимум 6 символов'),
});

export type LoginValues = z.infer<typeof loginSchema>;

export const registerSchema = z
  .object({
    name: z
      .string()
      .min(2, 'Имя должно содержать минимум 2 символа')
      .max(50, 'Имя не должно превышать 50 символов'),
    email: z.email('Введите корректный email'),
    password: z
      .string()
      .min(8, 'Пароль должен содержать минимум 8 символов')
      .regex(/[A-ZА-ЯЁ]/, 'Добавьте хотя бы одну заглавную букву')
      .regex(/[0-9]/, 'Добавьте хотя бы одну цифру'),
    passwordConfirmation: z.string().min(1, 'Подтвердите пароль'),
  })
  .refine((data) => data.password === data.passwordConfirmation, {
    error: 'Пароли не совпадают',
    path: ['passwordConfirmation'],
  });

export type RegisterValues = z.infer<typeof registerSchema>;
```

**6. src/context/AuthContext.tsx — провайдер и хук `useAuth`:**

```tsx
import { createContext, useCallback, useContext, useEffect, useMemo, useState } from 'react';
import type { ReactNode } from 'react';
import {
  fetchMe,
  login as loginRequest,
  logout as logoutRequest,
  register as registerRequest,
} from '../api/auth';
import type { LoginData, RegisterData, User } from '../api/auth';
import { clearAccessToken, getAccessToken } from '../api/http';
import { isTokenExpired } from '../utils/jwt';

interface AuthContextValue {
  user: User | null;
  isAuthenticated: boolean;
  isLoading: boolean;
  login: (data: LoginData) => Promise<void>;
  register: (data: RegisterData) => Promise<void>;
  logout: () => Promise<void>;
}

const AuthContext = createContext<AuthContextValue | null>(null);

export function AuthProvider({ children }: { children: ReactNode }) {
  const [user, setUser] = useState<User | null>(null);
  // Пока идёт проверка сохранённого токена — показываем состояние загрузки.
  const [isLoading, setIsLoading] = useState<boolean>(() => getAccessToken() !== null);

  // При запуске приложения восстанавливаем сессию по сохранённому токену.
  useEffect(() => {
    const token = getAccessToken();

    if (!token || isTokenExpired(token)) {
      clearAccessToken();
      setIsLoading(false);
      return;
    }

    let cancelled = false;

    fetchMe()
      .then((data) => {
        if (!cancelled) {
          setUser(data);
        }
      })
      .catch(() => {
        if (!cancelled) {
          setUser(null);
        }
      })
      .finally(() => {
        if (!cancelled) {
          setIsLoading(false);
        }
      });

    return () => {
      cancelled = true;
    };
  }, []);

  const login = useCallback(async (data: LoginData) => {
    const response = await loginRequest(data);
    setUser(response.user);
  }, []);

  const register = useCallback(async (data: RegisterData) => {
    const response = await registerRequest(data);
    setUser(response.user);
  }, []);

  const logout = useCallback(async () => {
    await logoutRequest();
    setUser(null);
  }, []);

  const value = useMemo<AuthContextValue>(
    () => ({
      user,
      isAuthenticated: user !== null,
      isLoading,
      login,
      register,
      logout,
    }),
    [user, isLoading, login, register, logout],
  );

  return <AuthContext.Provider value={value}>{children}</AuthContext.Provider>;
}

/** Хук доступа к контексту авторизации. */
export function useAuth(): AuthContextValue {
  const context = useContext(AuthContext);
  if (!context) {
    throw new Error('useAuth должен использоваться внутри AuthProvider');
  }
  return context;
}
```

**7. src/components/ProtectedRoute.tsx — защищённый маршрут:**

```tsx
import { Navigate, Outlet, useLocation } from 'react-router';
import { useAuth } from '../context/AuthContext';

/** Пропускает дальше только авторизованных, иначе — на страницу входа. */
export function ProtectedRoute() {
  const { isAuthenticated, isLoading } = useAuth();
  const location = useLocation();

  if (isLoading) {
    return (
      <p className="state" role="status">
        Проверка сессии…
      </p>
    );
  }

  if (!isAuthenticated) {
    // Запоминаем исходный адрес, чтобы вернуться на него после входа.
    return <Navigate to="/login" replace state={{ from: location.pathname }} />;
  }

  return <Outlet />;
}
```

**9. src/pages/LoginPage.tsx — форма входа:**

```tsx
import { useState } from 'react';
import { Link, useLocation, useNavigate } from 'react-router';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { loginSchema } from '../schemas/authSchemas';
import type { LoginValues } from '../schemas/authSchemas';
import { useAuth } from '../context/AuthContext';

interface LocationState {
  from?: string;
}

export function LoginPage() {
  const { login } = useAuth();
  const navigate = useNavigate();
  const location = useLocation();
  const from = (location.state as LocationState | null)?.from ?? '/profile';

  const [serverError, setServerError] = useState<string | null>(null);

  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<LoginValues>({
    resolver: zodResolver(loginSchema),
    defaultValues: { email: '', password: '' },
  });

  async function onSubmit(values: LoginValues) {
    setServerError(null);
    try {
      await login(values);
      // Возвращаемся на страницу, с которой пользователя перенаправили.
      navigate(from, { replace: true });
    } catch (error) {
      setServerError(error instanceof Error ? error.message : 'Не удалось войти');
    }
  }

  return (
    <section className="page">
      <form className="auth-form" onSubmit={handleSubmit(onSubmit)} noValidate>
        <h1>Вход в систему</h1>

        <div className="field">
          <label htmlFor="email">Email</label>
          <input
            id="email"
            type="email"
            autoComplete="email"
            aria-invalid={Boolean(errors.email)}
            aria-describedby={errors.email ? 'email-error' : undefined}
            {...register('email')}
          />
          {errors.email && (
            <span id="email-error" className="field-error" role="alert">
              {errors.email.message}
            </span>
          )}
        </div>

        <div className="field">
          <label htmlFor="password">Пароль</label>
          <input
            id="password"
            type="password"
            autoComplete="current-password"
            aria-invalid={Boolean(errors.password)}
            aria-describedby={errors.password ? 'password-error' : undefined}
            {...register('password')}
          />
          {errors.password && (
            <span id="password-error" className="field-error" role="alert">
              {errors.password.message}
            </span>
          )}
        </div>

        {serverError && (
          <p className="form-error" role="alert">
            {serverError}
          </p>
        )}

        <button type="submit" disabled={isSubmitting}>
          {isSubmitting ? 'Вход…' : 'Войти'}
        </button>

        <p className="auth-link">
          Нет аккаунта? <Link to="/register">Зарегистрируйтесь</Link>
        </p>
      </form>
    </section>
  );
}
```

```tsx
import { useState } from 'react';
import { Link, useNavigate } from 'react-router';
import { useForm } from 'react-hook-form';
import { zodResolver } from '@hookform/resolvers/zod';
import { registerSchema } from '../schemas/authSchemas';
import type { RegisterValues } from '../schemas/authSchemas';
import { useAuth } from '../context/AuthContext';

export function RegisterPage() {
  const { register: registerUser } = useAuth();
  const navigate = useNavigate();
  const [serverError, setServerError] = useState<string | null>(null);

  const {
    register,
    handleSubmit,
    formState: { errors, isSubmitting },
  } = useForm<RegisterValues>({
    resolver: zodResolver(registerSchema),
    defaultValues: {
      name: '',
      email: '',
      password: '',
      passwordConfirmation: '',
    },
  });

  async function onSubmit(values: RegisterValues) {
    setServerError(null);
    try {
      await registerUser(values);
      navigate('/profile', { replace: true });
    } catch (error) {
      setServerError(error instanceof Error ? error.message : 'Не удалось зарегистрироваться');
    }
  }

  return (
    <section className="page">
      <form className="auth-form" onSubmit={handleSubmit(onSubmit)} noValidate>
        <h1>Регистрация</h1>

        <div className="field">
          <label htmlFor="name">Имя</label>
          <input
            id="name"
            type="text"
            autoComplete="name"
            placeholder="Иван Петров"
            aria-invalid={Boolean(errors.name)}
            aria-describedby={errors.name ? 'name-error' : undefined}
            {...register('name')}
          />
          {errors.name && (
            <span id="name-error" className="field-error" role="alert">
              {errors.name.message}
            </span>
          )}
        </div>

        <div className="field">
          <label htmlFor="reg-email">Email</label>
          <input
            id="reg-email"
            type="email"
            autoComplete="email"
            placeholder="user@example.com"
            aria-invalid={Boolean(errors.email)}
            aria-describedby={errors.email ? 'reg-email-error' : undefined}
            {...register('email')}
          />
          {errors.email && (
            <span id="reg-email-error" className="field-error" role="alert">
              {errors.email.message}
            </span>
          )}
        </div>

        <div className="field">
          <label htmlFor="reg-password">Пароль</label>
          <input
            id="reg-password"
            type="password"
            autoComplete="new-password"
            aria-invalid={Boolean(errors.password)}
            aria-describedby={errors.password ? 'reg-password-error' : undefined}
            {...register('password')}
          />
          {errors.password && (
            <span id="reg-password-error" className="field-error" role="alert">
              {errors.password.message}
            </span>
          )}
        </div>

        <div className="field">
          <label htmlFor="confirm-password">Подтверждение пароля</label>
          <input
            id="confirm-password"
            type="password"
            autoComplete="new-password"
            aria-invalid={Boolean(errors.passwordConfirmation)}
            aria-describedby={
              errors.passwordConfirmation ? 'confirm-password-error' : undefined
            }
            {...register('passwordConfirmation')}
          />
          {errors.passwordConfirmation && (
            <span id="confirm-password-error" className="field-error" role="alert">
              {errors.passwordConfirmation.message}
            </span>
          )}
        </div>

        {serverError && (
          <p className="form-error" role="alert">
            {serverError}
          </p>
        )}

        <button type="submit" disabled={isSubmitting}>
          {isSubmitting ? 'Отправка…' : 'Зарегистрироваться'}
        </button>

        <p className="auth-link">
          Уже есть аккаунт? <Link to="/login">Войти</Link>
        </p>
      </form>
    </section>
  );
}
```

```tsx
import { useNavigate } from 'react-router';
import { useAuth } from '../context/AuthContext';

export function ProfilePage() {
  const { user, logout } = useAuth();
  const navigate = useNavigate();

  async function handleLogout() {
    await logout();
    navigate('/login', { replace: true });
  }

  if (!user) {
    return (
      <p className="state" role="status">
        Загрузка профиля…
      </p>
    );
  }

  return (
    <section className="page">
      <h1>Профиль пользователя</h1>

      <dl className="profile-info">
        <div className="profile-row">
          <dt>ID</dt>
          <dd>{user.id}</dd>
        </div>
        <div className="profile-row">
          <dt>Имя</dt>
          <dd>{user.name}</dd>
        </div>
        <div className="profile-row">
          <dt>Email</dt>
          <dd>{user.email}</dd>
        </div>
      </dl>

      <button type="button" className="logout-button" onClick={() => void handleLogout()}>
        Выйти
      </button>
    </section>
  );
}
```

```tsx
import { createBrowserRouter, Navigate } from 'react-router';
import { RootLayout } from './components/RootLayout';

import { RegisterPage } from './pages/RegisterPage';

import { NotFoundPage } from './pages/NotFoundPage';

export const router = createBrowserRouter([
  {
    path: '/',
    element: <RootLayout />,
    children: [
      { index: true, element: <Navigate to="/profile" replace /> },
      { path: 'login', element: <LoginPage /> },
      { path: 'register', element: <RegisterPage /> },
      {
        // Защищённая группа маршрутов: доступна только после входа.
        element: <ProtectedRoute />,
        children: [{ path: 'profile', element: <ProfilePage /> }],
      },
      { path: '*', element: <NotFoundPage /> },
    ],
  },
]);
```

## **Варианты заданий:**

### **Вариант 1: Полный цикл JWT-аутентификации**
Реализуйте на React полный цикл аутентификации: вход, регистрация, выход, хранение access-токена, подстановку токена в запросы и защиту маршрутов.

### **Вариант 2: Обновление access-токена (refresh)**
Создайте систему refresh-токенов: при ответе 401 приложение автоматически запрашивает новый access-токен и повторяет исходный запрос.

### **Вариант 3: Ролевая модель (User, Admin)**
Реализуйте роли с разными уровнями доступа: обычный пользователь и администратор видят разные маршруты и разделы интерфейса.

### **Вариант 4: Обработка 401 с редиректом**
Создайте интерцептор ответа, который при 401 очищает токен и автоматически перенаправляет пользователя на страницу входа, запоминая исходный адрес.

### **Вариант 5: «Запомнить меня»**
Реализуйте функцию «Remember me»: при включённой галочке выдаётся и хранится долгоживущий токен, иначе сессия завершается при закрытии вкладки.

### **Вариант 6: Управление активными сессиями**
Создайте сервис и интерфейс для просмотра активных сессий пользователя (устройство, время входа) и завершения выбранных сессий.

### **Вариант 7: Вход через OAuth2 (Google/GitHub)**
Реализуйте вход через внешнего провайдера (Google или GitHub) с получением JWT от бекенда и отображением профиля пользователя.

### **Вариант 8: Двухфакторная аутентификация (2FA)**
Создайте систему 2FA: после ввода пароля запрашивается код подтверждения, полученный по email или SMS, и только затем выдаётся токен.

### **Вариант 9: Принудительный выход**
Реализуйте принудительный выход при смене пароля или блокировке аккаунта: приложение отслеживает ответ сервера и завершает сессию пользователя.

### **Вариант 10: Проверка прав по JWT claims**
Создайте проверку прав доступа к разделам и запросам на основе claims токена (роль, права), с единым хуком проверки прав в компонентах.

### **Вариант 11: Безопасное хранение токена**
Реализуйте безопасное хранение токена с использованием HttpOnly cookies вместо `localStorage` и сравните поведение с токеном в памяти приложения.

### **Вариант 12: Ограничение попыток входа**
Создайте систему ограничения попыток входа и блокировки при подозрительной активности с отображением оставшихся попыток и времени блокировки.

### **Вариант 13: Восстановление пароля**
Реализуйте функцию «Забыли пароль?»: форма запроса, отправка ссылки сброса на email и форма установки нового пароля по токену из письма.

### **Вариант 14: Админ-панель управления пользователями**
Создайте административную панель для просмотра пользователей, изменения их ролей и прав, а также блокировки и разблокировки аккаунтов.

### **Вариант 15: Аудит действий и событий аутентификации**
Реализуйте аудит: журнал важных событий (вход, выход, смена пароля, неудачные попытки) с отображением списка событий и фильтрацией.
