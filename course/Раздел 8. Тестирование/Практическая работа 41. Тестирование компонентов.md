# Практическая работа 41. Тестирование компонентов

### **Тема:** Unit-тестирование React-компонентов с помощью Vitest и React Testing Library

### **Цель:**
Научиться настраивать тестовое окружение в Vite-проекте, писать unit-тесты для React-компонентов (рендер, пользовательские события, условный вывод, списки), изолировать компонент от сети с помощью моков и проверять асинхронную загрузку данных.

### **Теоретическая часть:**

**Зачем тестировать компоненты?**
Unit-тест проверяет поведение отдельного компонента в изоляции. Он быстрый, не требует браузера и сервера, а после рефакторинга сразу показывает, не сломалось ли поведение интерфейса.

**Инструменты:**

*   **Vitest** — тест-раннер для Vite-проектов: `describe`, `it`, `expect`, `vi`.
*   **React Testing Library (RTL)** — `render`, `screen`, `renderHook`, `waitFor`; тестируем так, как видит пользователь.
*   **@testing-library/user-event** — реалистичная имитация кликов и ввода.
*   **@testing-library/jest-dom** — дополнительные матчеры: `toBeInTheDocument`, `toHaveValue` и др.
*   **jsdom** — эмуляция DOM в Node.js.

**Установка:**

```bash
npm i -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event @vitest/coverage-v8
```

**Основные запросы RTL:**

| Запрос | Назначение | Варианты |
|--------|-----------|----------|
| `getByRole('button', { name: 'Добавить' })` | Поиск по роли (лучший способ) | `queryByRole`, `findByRole` |
| `getByLabelText('Новая задача')` | Поле формы по подписи `<label>` | `queryByLabelText`, `findByLabelText` |
| `getByPlaceholderText('…')` | По плейсхолдеру | `queryBy…`, `findBy…` |
| `getByText('Задач нет')` | По тексту | `queryByText`, `findByText` |
| `getByTestId('…')` | По `data-testid` (крайний случай) | `queryByTestId`, `findByTestId` |

*   `getBy*` — элемент должен быть сейчас, иначе ошибка.
*   `queryBy*` — вернёт `null`, если элемента нет (для проверки отсутствия).
*   `findBy*` — `Promise`, ждёт появления элемента (для асинхронности).

**События пользователя:**

```tsx
const user = userEvent.setup();

await user.type(screen.getByLabelText('Новая задача'), 'Купить хлеб');
await user.click(screen.getByRole('button', { name: 'Добавить' }));
await user.clear(screen.getByLabelText('Новая задача'));
await user.selectOptions(screen.getByRole('combobox'), 'completed');
```

**Моки:**

```ts
const handler = vi.fn();          // функция-шпион
vi.mock('../api/users');          // подмена всего модуля (только на верхнем уровне файла)
vi.spyOn(console, 'error');       // слежка за методом объекта
```

**Асинхронность:**

```tsx
expect(await screen.findByText('Анна')).toBeInTheDocument();
await waitFor(() => expect(handler).toHaveBeenCalled());
```

### **Ход работы:**

1. Создать новый проект React + TypeScript с помощью Vite и установить зависимости.
2. Установить тестовые пакеты (`vitest`, `jsdom`, библиотеки Testing Library, `@vitest/coverage-v8`).
3. Добавить npm-скрипты `test`, `test:run`, `coverage`; настроить `vite.config.ts` и создать `src/test/setup.ts`; подключить типы `vitest/globals` в `tsconfig.app.json`.
4. Реализовать компонент списка по варианту (например, `TodoList`) с добавлением, отметкой выполнения, удалением и фильтрацией.
5. Написать тесты компонента: рендер, пустое состояние, добавление через `userEvent.type` и `click`, удаление, переключение чекбокса, фильтрация.
6. Реализовать компонент, загружающий данные (`UserList`), и написать для него тест с моком API-модуля через `vi.mock` и ожиданием через `findByText`.
7. Запустить однократный прогон тестов командой `npm run test:run` и убедиться, что все тесты зелёные.
8. Сформировать отчёт о покрытии (`npm run coverage`), сделать скриншоты работающего приложения и оформить README.md; загрузить проект в Gogs.

#### **2. `src/components/TodoList.tsx`:**

```tsx
import { useState } from 'react';
import './TodoList.css';

export interface Todo {
  id: number;
  title: string;
  completed: boolean;
}

type Filter = 'all' | 'active' | 'completed';

export function TodoList() {
  const [todos, setTodos] = useState<Todo[]>([]);
  const [title, setTitle] = useState('');
  const [filter, setFilter] = useState<Filter>('all');

  const addTodo = () => {
    const trimmed = title.trim();
    if (!trimmed) {
      return;
    }

    setTodos((prev) => [
      ...prev,
      { id: Date.now(), title: trimmed, completed: false },
    ]);
    setTitle('');
  };

  const toggleTodo = (id: number) => {
    setTodos((prev) =>
      prev.map((todo) =>
        todo.id === id ? { ...todo, completed: !todo.completed } : todo,
      ),
    );
  };

  const deleteTodo = (id: number) => {
    setTodos((prev) => prev.filter((todo) => todo.id !== id));
  };

  const visibleTodos = todos.filter((todo) => {
    if (filter === 'active') {
      return !todo.completed;
    }
    if (filter === 'completed') {
      return todo.completed;
    }
    return true;
  });

  const completedCount = todos.filter((todo) => todo.completed).length;

  return (
    <section className="todo">
      <h2>Список задач</h2>

      <div className="todo-add">
        <label htmlFor="todo-title">Новая задача</label>
        <input
          id="todo-title"
          value={title}
          onChange={(event) => setTitle(event.target.value)}
          placeholder="Что нужно сделать?"
        />
        <button onClick={addTodo}>Добавить</button>
      </div>

      <p className="todo-stats">
        Выполнено: {completedCount} из {todos.length}
      </p>

      <div className="todo-filters">
        <button onClick={() => setFilter('all')}>Все</button>
        <button onClick={() => setFilter('active')}>Активные</button>
        <button onClick={() => setFilter('completed')}>Выполненные</button>
      </div>

      {visibleTodos.length === 0 ? (
        <p>Задач нет</p>
      ) : (
        <ul>
          {visibleTodos.map((todo) => (
            <li key={todo.id}>
              <label>
                <input
                  type="checkbox"
                  checked={todo.completed}
                  onChange={() => toggleTodo(todo.id)}
                />
                <span>{todo.title}</span>
              </label>
              <button
                aria-label={`Удалить задачу ${todo.title}`}
                onClick={() => deleteTodo(todo.id)}
              >
                Удалить
              </button>
            </li>
          ))}
        </ul>
      )}
    </section>
  );
}
```

#### **3. `src/components/TodoList.test.tsx`:**

```tsx
import { render, screen } from '@testing-library/react';
import userEvent from '@testing-library/user-event';
import { TodoList } from './TodoList';

describe('TodoList', () => {
  it('при пустом списке показывает сообщение и нулевую статистику', () => {
    // Arrange & Act
    render(<TodoList />);

    // Assert
    expect(screen.getByText('Задач нет')).toBeInTheDocument();
    expect(screen.getByText('Выполнено: 0 из 0')).toBeInTheDocument();
  });

  it('добавляет задачу через ввод и клик по кнопке', async () => {
    // Arrange
    const user = userEvent.setup();
    render(<TodoList />);

    // Act
    await user.type(screen.getByLabelText('Новая задача'), 'Купить хлеб');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));

    // Assert
    expect(screen.getByText('Купить хлеб')).toBeInTheDocument();
    expect(screen.getByLabelText('Новая задача')).toHaveValue('');
    expect(screen.queryByText('Задач нет')).not.toBeInTheDocument();
  });

  it('не добавляет задачу из одних пробелов', async () => {
    const user = userEvent.setup();
    render(<TodoList />);

    await user.type(screen.getByLabelText('Новая задача'), '   ');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));

    expect(screen.getByText('Задач нет')).toBeInTheDocument();
    expect(screen.getByText('Выполнено: 0 из 0')).toBeInTheDocument();
  });

  it('отмечает задачу выполненной и обновляет статистику', async () => {
    const user = userEvent.setup();
    render(<TodoList />);

    await user.type(screen.getByLabelText('Новая задача'), 'Учёба');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));
    await user.click(screen.getByRole('checkbox', { name: 'Учёба' }));

    expect(screen.getByRole('checkbox', { name: 'Учёба' })).toBeChecked();
    expect(screen.getByText('Выполнено: 1 из 1')).toBeInTheDocument();
  });

  it('удаляет задачу', async () => {
    const user = userEvent.setup();
    render(<TodoList />);

    await user.type(screen.getByLabelText('Новая задача'), 'Позвонить');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));
    await user.click(
      screen.getByRole('button', { name: 'Удалить задачу Позвонить' }),
    );

    expect(screen.queryByText('Позвонить')).not.toBeInTheDocument();
    expect(screen.getByText('Задач нет')).toBeInTheDocument();
  });

  it('фильтрует выполненные и активные задачи', async () => {
    const user = userEvent.setup();
    render(<TodoList />);

    await user.type(screen.getByLabelText('Новая задача'), 'Активная');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));
    await user.type(screen.getByLabelText('Новая задача'), 'Готовая');
    await user.click(screen.getByRole('button', { name: 'Добавить' }));
    await user.click(screen.getByRole('checkbox', { name: 'Готовая' }));

    // Только выполненные
    await user.click(screen.getByRole('button', { name: 'Выполненные' }));
    expect(screen.getByText('Готовая')).toBeInTheDocument();
    expect(screen.queryByText('Активная')).not.toBeInTheDocument();

    // Только активные
    await user.click(screen.getByRole('button', { name: 'Активные' }));
    expect(screen.getByText('Активная')).toBeInTheDocument();
    expect(screen.queryByText('Готовая')).not.toBeInTheDocument();
  });
});
```

#### **4. `src/api/users.ts` — модуль работы с API:**

```ts
export interface User {
  id: number;
  name: string;
}

export async function fetchUsers(): Promise<User[]> {
  const response = await fetch('/api/users');
  if (!response.ok) {
    throw new Error('Не удалось загрузить пользователей');
  }
  return (await response.json()) as User[];
}
```

#### **5. `src/components/UserList.tsx` — загрузка данных:**

```tsx
import { useEffect, useState } from 'react';
import { fetchUsers } from '../api/users';
import type { User } from '../api/users';

export function UserList() {
  const [users, setUsers] = useState<User[]>([]);
  const [isLoading, setIsLoading] = useState(true);
  const [error, setError] = useState<string | null>(null);

  useEffect(() => {
    fetchUsers()
      .then(setUsers)
      .catch((reason: unknown) => {
        setError(reason instanceof Error ? reason.message : 'Неизвестная ошибка');
      })
      .finally(() => setIsLoading(false));
  }, []);

  if (isLoading) {
    return <p>Загрузка…</p>;
  }

  if (error) {
    return <p role="alert">{error}</p>;
  }

  return (
    <ul>
      {users.map((user) => (
        <li key={user.id}>{user.name}</li>
      ))}
    </ul>
  );
}
```

#### **6. `src/components/UserList.test.tsx` — мок API и `findByText`:**

```tsx
import { render, screen } from '@testing-library/react';
import { UserList } from './UserList';
import { fetchUsers } from '../api/users';

// vi.mock должен быть на верхнем уровне файла
vi.mock('../api/users');

const mockedFetchUsers = vi.mocked(fetchUsers);

describe('UserList', () => {
  beforeEach(() => {
    mockedFetchUsers.mockReset();
  });

  it('сначала показывает загрузку, затем список пользователей', async () => {
    // Arrange
    mockedFetchUsers.mockResolvedValue([
      { id: 1, name: 'Анна' },
      { id: 2, name: 'Иван' },
    ]);

    // Act
    render(<UserList />);

    // Assert
    expect(screen.getByText('Загрузка…')).toBeInTheDocument();
    expect(await screen.findByText('Анна')).toBeInTheDocument();
    expect(screen.getByText('Иван')).toBeInTheDocument();
    expect(screen.queryByText('Загрузка…')).not.toBeInTheDocument();
  });

  it('показывает сообщение об ошибке, если запрос завершился неудачно', async () => {
    mockedFetchUsers.mockRejectedValue(new Error('Сервер недоступен'));

    render(<UserList />);

    expect(await screen.findByRole('alert')).toHaveTextContent(
      'Сервер недоступен',
    );
  });
});
```

## **Варианты заданий:**

Для **каждого** варианта: создать React-проект, реализовать один или несколько компонентов и написать unit-тесты с помощью Vitest + React Testing Library. Обязательно покрыть: начальный рендер, пользовательские события, граничные случаи (пустые данные, неверный ввод), а для вариантов с загрузкой данных — мок API и асинхронное ожидание.

### **Вариант 1: Компонент «Список задач» (TodoList)**
Компонент с добавлением задачи, отметкой выполнения, удалением и фильтрацией (все / активные / выполненные) и счётчиком выполненных.
Тесты: пустое состояние, добавление через `userEvent.type` + `click`, отказ добавлять пустую строку, переключение чекбокса, удаление, фильтрация.

### **Вариант 2: Компонент «Таймер»**
Таймер с кнопками «Старт», «Пауза», «Сброс» и отображением прошедших секунд.
Тесты: начальное значение `00:00`, запуск увеличивает счётчик (fake timers), пауза останавливает отсчёт, сброс возвращает нуль.

### **Вариант 3: Компонент «Калькулятор»**
Калькулятор с двумя полями и кнопками арифметических операций (сложение, вычитание, умножение, деление).
Тесты: корректный результат для каждой операции, деление на ноль показывает ошибку, пустые поля не приводят к сбою, кнопка «Сброс» очищает поля.

### **Вариант 4: Компонент «Форма входа»**
Форма с полями email и пароль, кнопкой «Войти» и отображением ошибок валидации.
Тесты: пустая форма показывает обе ошибки, неверный email подсвечивается, после корректного заполнения вызывается обработчик отправки, кнопка недоступна во время отправки.

### **Вариант 5: Компонент «Погода»**
Компонент погоды с переключением между городами и выводом температуры и состояния.
Тесты: отображается город по умолчанию, переключение города меняет данные, для состояния показывается соответствующая иконка/текст, мок API возвращает данные асинхронно (`findByText`).

### **Вариант 6: Компонент «Карусель изображений»**
Карусель с кнопками «Назад»/«Вперёд», точками-индикаторами и счётчиком слайдов.
Тесты: первый слайд активен при рендере, «Вперёд» смещает слайд, «Назад» с первого слайда не уходит за границу, клик по индикатору открывает нужный слайд.

### **Вариант 7: Компонент «Прогресс-бар»**
Прогресс-бар со значением `value`, текстом процентов и кнопками увеличения/уменьшения.
Тесты: отображает переданное значение, проценты совпадают со значением, значение не выходит за 0 и 100, установка значения через prop обновляет полосу.

### **Вариант 8: Компонент «Рейтинг»**
Звёздный рейтинг с выбором оценки от 1 до 5 и режимом «только чтение».
Тесты: отображает текущий рейтинг, клик по звезде устанавливает оценку, `onChange` вызывается с нужным числом, в режиме `readOnly` клики не меняют значение.

### **Вариант 9: Компонент «Поиск»**
Строка поиска с фильтрацией списка и сообщением «ничего не найдено».
Тесты: при вводе список фильтруется, регистронезависимый поиск, пустой результат показывает сообщение, очистка поля возвращает весь список.

### **Вариант 10: Компонент «Уведомления»**
Система уведомлений с типами (`success`, `error`, `warning`, `info`) и ручным закрытием.
Тесты: уведомление отображается с нужным текстом, применение типа даёт соответствующий класс, клик по кнопке закрытия удаляет уведомление, несколько уведомлений рендерятся списком.

### **Вариант 11: Компонент «Аккордеон»**
Аккордеон с несколькими секциями и возможностью открывать по одной секции.
Тесты: при рендере все секции закрыты, клик по заголовку раскрывает секцию, повторный клик закрывает, при открытии одной секции другая закрывается.

### **Вариант 12: Компонент «Вкладки»**
Компонент вкладок с переключением контента по клику.
Тесты: активна первая вкладка, клик по другой вкладке показывает её контент, активная вкладка имеет признак `aria-selected`, скрытые панели отсутствуют в разметке.

### **Вариант 13: Компонент «Модальное окно»**
Переиспользуемое модальное окно с заголовком, контентом и кнопками «ОК»/«Отмена».
Тесты: при `isOpen = false` окно не отображается, при `isOpen = true` — видно заголовок и контент, «Отмена» вызывает `onClose`, «ОК» вызывает `onConfirm`, клик по заголовку не закрывает окно.

### **Вариант 14: Компонент «Хлебные крошки»**
Навигационные хлебные крошки по массиву пунктов, последний пункт — без ссылки.

## **Инструкция по сдаче работы:**

2. Клонировать репозиторий локально.
3. Создать React-проект в папке репозитория:
   ```bash
   npm create vite@latest . -- --template react-ts
   npm install
   ```

   ```bash
   npm i -D vitest jsdom @testing-library/react @testing-library/jest-dom @testing-library/user-event @vitest/coverage-v8
   ```
5. Настроить `vite.config.ts`, создать `src/test/setup.ts`, добавить npm-скрипты.
6. Реализовать компоненты согласно варианту и написать тесты.
