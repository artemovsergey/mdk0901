## 1. Презентации лекций (PPTX)

### 1.1 Источник
Каждая лекция — Markdown-файл:
`course/Раздел 5. React/Лекция N. <Название>.md`

Структура источника (два формата):

**Формат лекции (15–23):**
```
# Лекция 17. Условный рендеринг и списки
**Цель лекции:** ...
**Аудитория:** ...
---
### **План лекции:**
1. **Заголовок пункта**
    *   подпункт
...
### **Детальное рассмотрение каждого пункта плана:**
#### **1. Заголовок**
абзац с **термином**
*   маркер
```tsx
код
```
### **Резюме**
*   ...
### **Контрольные вопросы:**
1. ...
### **Материалы презентации**
*   ...
```

**Формат практического занятия, оформленного как лекция (24–25):**
```
# Лекция 24. UI-компоненты. shadcn-ui и Tailwind
### **Тема:** ...
### **Цель:** ... (многострочное описание далее)
### **Теоретическая часть:**
**Термин** — определение
*   маркер
```bash
команда
```
### **Установка и настройку:**
### **Ход работы:**
### **Практический пример:**
```

### 1.2 Генератор
Основной инструмент: `tools/generate_all_pptx.py` (python-pptx 1.0.2, Pillow, Python 3.12). Рендеринг слайдов выполняет `tools/generate_lecture_pptx.py`.

Запуск (из корня репозитория):
```bash
python tools/generate_all_pptx.py --lecture 1          # одна лекция
python tools/generate_all_pptx.py --section "Раздел 6" # все лекции раздела
python tools/generate_all_pptx.py --all                # все лекции, существующие PPTX пропускаются
python tools/generate_all_pptx.py --all --force        # перезаписать все PPTX
python tools/generate_all_pptx.py --all --dry-run      # только план без записи
```

Генератор парсит Markdown и собирает PPTX со следующей последовательностью слайдов:
1. Титульный слайд (номер лекции, название, курс, 2 академических часа / 90 мин).
2. Цель лекции.
3. Аудитория.
4. План лекции.
5. На каждый раздел (`####` / `### **Заголовок:**`): слайд «Что разберём» + слайды контента (абзацы, маркеры, таблицы, блоки кода).
6. На каждый слайд контента добавляется выделенный блок **«ЧТО ЗАКОНСПЕКТИРОВАТЬ»** — определения и ключевые термины для записи в конспект (светло-жёлтая рамка, акцентная полоса слева).
7. Резюме (конспект-термины; при переполнении — несколько слайдов).
8. Контрольные вопросы (по 6 вопросов на слайд).
9. Материалы презентации.

Абзацы и пункты пагинируются по высоте, чтобы не заходить на блок конспекта. Блок кода разбивается по 18 строк; при длинных строках автоматически уменьшается шрифт.

Практические работы, ошибочно названные `Лекция N ...md`, пропускаются по H1 `# Практическая работа`. Флаг `--include-practical` включает их принудительно.

### 1.3 Куда сохранять
```
course/Раздел N. <Название>/Презентация N. <Название>/Лекция N. <Название>.pptx
course/Раздел N. <Название>/Презентация N. <Название>/schemes/
course/Раздел N. <Название>/Презентация N. <Название>/screenshots/
```
Папки `Презентация N...` создаются генератором автоматически.

### 1.4 Требования к оформлению
- Соотношение 16:9 (13.333 × 7.5 дюйма).
- Тёмно-синий верхний баннер (`#142D4E`) с кикером и названием, акцентная подчёркивающая полоса (`#2E7DB5`).
- Тело текста: Segoe UI, тёмный инк `#212529`.
- Блок конспекта: заливка `#FFF7E1`, рамка `#E8A31D`, заголовок «ЧТО ЗАКОНСПЕКТИРОВАТЬ — запомни и запиши в конспект:».
- Код: Consolas, фон `#F2F4F8`, без переноса строк.

### 1.5 Длительность
Каждая лекция = 2 академических часа (~90 мин = 1 пара), подтверждено КТП. Количество слайдов не регламентировано жёстко, но по умолчанию получается 45–147 слайдов — темп =~ 30–40 сек на слайд с перерывами на код.

## 2. Практические работы (обновление)

### 2.1 Источник
`course/Раздел 5. React/Практическая работа N. <Название>.md`

Каждая практическая работа содержит секции: Тема, Цель, Теоретическая часть, Ход работы, Пошаговая реализация, Варианты заданий (15 вариантов), Критерии оценки (2–5), Контрольные вопросы, Файловая структура, Пример README, Инструкция по сдаче.

### 2.2 Что обновлять
Для каждой практической работы 15–23:

1. **Пошаговая реализация** — привести к maximally simple (максимально простой) варианту:
   - одна страница / один компонент,
   - не более 3–4 файлов,
   - только материал, пройденный на предыдущих лекциях раздела (не опережать теорию),
   - время выполнения укладывается в 90 мин (1 пара).

2. **Скриншоты / GIF** — добавить метки под каждый этап:
   - `[СКРИНШОТ N]` — где сделать снимок экрана (результат этапа),
   - `[GIF N]` — где записать короткую анимацию процесса (например, клик по фильтру, переключение вкладки, открытие модалки).

3. **Варианты заданий** — оставить 15 вариантов, но каждый вариант должен быть выполним за 90 мин и использовать только пройденный материал. Сложные варианты упростить или убрать.

4. **Критерии оценки (2–5)** — оставить, привязать к выполнению пошаговой реализации.

### 2.3 Правило "только пройденный материал"
Практическая работа N может использовать только темы лекций 15–N (и ранее). Примеры:
- Практ. 17 (состояние и хуки) — только useState, без useEffect/Zustand (это лекции 18/23).
- Практ. 21 (сервисный слой и Context) — только Context +useState, без react-hook-form (лекция 21).
- Практ. 23 (навигация) — только React Router, без Zustand (лекция 22).

## 3. Руководство по скриншотам и GIF

См. отдельный файл: `course/Раздел 5. React/SCREENSHOT_GIF_GUIDE.md` (создан в рамках этого skill-а).

Кратко:
- Скриншоты: PNG, 1920×1080, чистый интерфейс без лишних окон, кладите в `Презентация N.../screenshots/` и в папку практической работы `screenshots/`.
- GIF: записи до 15 сек, FPS 10–12, размер ≤ 2 МБ, показывают одно действие (клик, фильтр, переход).
- Называйте файлы по шагам: `step01_initial.png`, `step02_filter_clicked.gif`, и т.д.
- В тексте практической работы ссылайтесь через `[СКРИНШОТ N]` / `[GIF N]` с пометкой, что файл приложен отдельно.

python tools/generate_all_pptx.py --all --force
```
После этого проверить, что все PPTX открываются:
```
python -c "from pptx import Presentation; import glob;
for f in sorted(glob.glob('course/**/*.pptx', recursive=True)):
    print(len(Presentation(f).slides), f)"
```
